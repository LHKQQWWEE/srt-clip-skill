# C2 Universal｜运行契约

本文件定义唯一运行入口、素材读取边界、单次语义分析的资料复用方式和固定交付格式。动态购买决策、正式禁词、时长与质量判定仍以同一运行正文中的对应权威章节为准。

## 入口、版本与输入

- 当前唯一业务内核为 Core `0.4.6`；插件发行版本由插件清单声明。唯一触发词为 `srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`；通用词 `切片文案` 不触发 C2。
- 正式输入为 SRT 或逐条时长文本。只有 MP4 时请用户提供文本；同时提供 SRT/MP4 时按文本剪辑，不声称已核验未查看的画面或原声，不伪造字幕、序号或时间。
- 若可靠识别出两件及以上商品且用户未指定目标，只列商品及其离散讲解窗口并询问一次；确认前不进行商品专属筛选、编排或成稿。确认后完整读取所选商品的全部有效窗口。目标明确或只有一件商品时直接继续。
- 每次调用都重新完整读取当前运行正文，不以历史摘要、缓存或同一对话的上一次读取替代。入口文件负责定位与完整性；条件文件按需加载，业务判断只按当前运行正文执行。

### 现有逻辑职责（同一 AI）

**运行方式是一个 AI、一次语义分析、一次终检。**下列英文名称仅对应现有逻辑职责，不代表新 Agent、模型或调用：Chief Decision Editor（总决策编辑）统筹目标与候选六维比较，并按用户授权维护唯一词库；Product Purchase-Decision Architect（商品购买决策架构师）完整识别信息并控制粒度、设计正式命中与风险提示边界，再为各核心角度重评、编排全部有效信息；Product Facts & Boundaries Officer（商品事实与边界官）核对商品归属、证据、条件和合规边界，对硬边界有否决权；Purchase-Decision Editor（购买决策剪辑师）按原话编排完整候选并保留全部有效信息；Final Quality Auditor（成片质量审计官）执行现有一次终检并要求局部修复。角色不得越过全局硬规则；事实与边界官的否决不能由转化诉求推翻，总决策编辑不得豁免已确认禁令或跳过硬性失败项。

## 一次语义分析中的共享资料与候选处理

1. 完整解析来源并确认读取范围。保留原始编号、原话、时间码/逐条时长和来源顺序；存在缺行、重复编号、倒置时间、非正时长、乱码或截断时，标明已解析与未解析范围。未解析范围为 BLOCKED，不得当作已检查或据此推断；来源无法可靠补齐时停止受影响的正式编排。
2. 对已确认的目标商品，在同一次语义分析中读完全部有效窗口，再建立紧凑共享信息池：有效独立购买信息、商品/款式归属、原话来源、必要证据与条件、重复/递进关系、事实待核实和风险标记。建池时不赋固定价值等级；有效性决定覆盖义务，价值按每个候选的核心角度动态重评。
3. 每个候选从同一完整信息池独立排序并编排全部有效信息及必要证据/条件。先完成完整路径、跳点核对和全量覆盖资格，再按六个既定维度比较完整候选。每条多视频方案各自覆盖完整信息池；方案并集不能补足单条遗漏。未指定多条时，发现可行的实质差异化方案则先建议主题与数量并等待用户选择。
4. 选择性保留候选的紧凑映射即可；只有获选方案展开原话全文。共享来源索引、禁词直接命中和其他机械证据，不共享不同候选的价值排序、合规语义结论或剪辑选择。

## 工具、终检与修复

- Python、脚本、JSON、联网和环境检查均非日常任务前置条件。工具可用时最多执行一次输入预处理；如使用随附 CLI，优先 `srt_tools.py preprocess <source> --compact`，每条字幕只返回一份无损行记录，避免重复输出完整字幕表和时间轴视图。旧 JSON 视图仍为默认兼容接口。选段组装时一次完成来源/序号/角色/正式词库结构检查、原话渲染、第五部分序号和共享时长计算。机器不判断卖点池完整性、语义禁词、原话支撑、商品归属或跳点是否自然。
- 工具不可用时继续处理可靠可读文本，使用“模型逐条对照”，不得称为机检通过。正式词库直接命中、风险提示和事实待核实分开；工具结果不得扩大硬禁范围。组装时长按连续源序号分组，SRT 每组用“末条 end − 首条 start”并计入组内间隔，逐条时长文本逐项相加；先求源时长，再除以 1.2 一次，并按 0.5ms 进位规则舍入到毫秒一次。第一、三部分复用同一 `playback_duration_display`，不得各自重算或展示不同数值，字幕定位保留原素材 1.0 倍口径。
- 现有 Final Quality Auditor 在同一次任务内完成一次终检：反向核对目标商品完整来源范围，逐条核验每条候选覆盖全量有效信息及必要支持，再检查原话、归属、条件、语义合规、重复和上下文连续性。该检查是现有终检的审计视角，不增加 Agent、模型轮次或独立台账。
- 失败时按根因只修复受影响片段，并核对相邻语境；相同根因最多三轮实质修复。复修后重验导致失败的项目及受影响回归，并完成一次最终整体验收；只重出受影响段落，不重写整份五部分。不得通过删点、降低标准或隐藏 BLOCKED/FAIL 换取通过。

## 固定五部分交付

以下顺序和内容固定，不添加第六部分：

### 一、文件解析结果

按固定短句模板填写：`文件解析：{文件名}；{SRT/逐条时长文本}；{Standard/Long Context}；窗口 {数量}；入选 {条数} 条/{组数} 组；原始选段 {源时长}；预计成片 {playback_duration_display}；{脚本核验/模型逐条对照}。范围：{已核对范围或 BLOCKED 的 parsed_ranges/unparsed_ranges}。待核：{合规风险/事实待核实/关键限制，无则写“无”}。` 不声称未实际执行的脚本检查。原始选段与预计成片时长引用同一组装结果。

### 二、商品识别

列出目标商品、别称、离散讲解窗口及必要归属说明；只有确实辅助事实判断时才说明参考的商品知识包。

### 三、最佳成片方案

按用户指定条数或素材适配数量交付完整方案。每版列本条核心角度、购买决策路径、预计时长、原始选段时长、按播放顺序排列的原话和来源序号，并简述核心与补充理由、重要未采用内容及原因。普通未采用内容最多三条、每条一行；风险、待核实事实与关键限制另列，不计入三条限额。多条须说明差异并逐条确认全量覆盖。原话逐字保留；疑点紧邻对应片段标明。

### 四、作品标题与话题

每版恰好一个标题、五个话题。根据当前商品和该版真实主线动态生成；不得套用知识包标签或编造事实、价格、库存、功效，并执行正式词库与字段特例。

### 五、原始 SRT 序号

按播放顺序列出来源序号。所有方案放在同一个文本代码框中，每版一行，以半角逗号分隔且无空格；方案间空一行。代码框内不放其他文字，不伪造序号。

时长统一按当前覆盖与时长规则计算；时间不是任务完成门槛。CTA 可选。日常输出仅此五部分。
