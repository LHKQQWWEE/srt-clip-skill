# 商品类目识别与专项模块注册表

## 自动识别

- 优先采用用户明确指定的商品类别或商品名称。
- 用户未指定时，根据商品名称、字幕中主播的商品自称、材质/功能/用途及上下文识别类别。
- 一个商品可以有多个兼容标签，例如“围巾/围脖”可能属于时尚配饰，也可能属于服装搭配；按实际商品属性加载相关模块。
- 不要仅凭主播顺带提到的搭配单品改变当前目标商品类别。
- 类别无法确定且会影响规则加载时，只询问一次；不影响通用剪辑时可先按通用核心执行。

## 未建立专项模块的类别

首版尚未建立独立专项规则的类别包括首饰、美妆、童装、家居、食品、数码及其他商品。它们仍可使用通用核心：
- 识别商品、别称、窗口和商品归属。
- 盘点有原话支持的购买理由。
- 比较开头候选、编排中段、自然收尾。
- 保留原话、来源和适用条件。
- 执行统一时长与离线合规基线。

不得把女装的面料、版型、穿搭规则冒充为首饰、美妆或其他类别的专业规则。若某个专业判断确实影响成片，明确指出专项规则尚未建立；不编造行业标准或商品事实。

## 新增模块原则

未来新增类别时，只新增对应 `categories/<category>.md`，并更新本注册表。通用核心保持不变。新增模块必须写明适用范围、可判断内容、不能推断的事实、该类目的常见亮点和风险，不得覆盖全局原话、时长、触发词、输出或禁用规则。

## 话题策略

- Universal Core 输出总计五个与商品/类目相关的话题。
- 类目模块可声明最多两个固定类目话题，Core 生成其余话题补足五个。
- 当前女装与时尚配饰模块声明 `#穿搭`、`#时尚营销`。
- 没有专项模块的类目由 Core 直接生成五个相关话题，不借用女装话题。
