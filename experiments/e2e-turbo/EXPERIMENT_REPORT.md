# SRT E2E-TURBO 候选实验记录（2026-11-02）

状态：CANDIDATE；不替换 Google Drive V3.0 FAST-LITE-1 ACTIVE，不修改 V3.0 五部分格式。

## 验证
- 真实输入：用户当前上传的 523 条 SRT；与现有的 62 条/10组编排 PLAN 对比。
- 首轮封装实验 13/13 单元测试通过；本地五部分输出与旧版预期文本完全一致。
- 40 次本地双进程完整 scan+render 计时：旧版中位数 56.766ms；多包裹一层的实验版 59.086ms，慢 4.1%。
- **结论**：废弃无效 wrapper；代码保留与旧版 srt_fast.py 字节一致。真正待优化项目是跨会话启动、云盘读取、AI单轮决策和直接输出文本。
- 不引入任何原始用户直播转写数据到公开 Skill 或 GitHub 仓库。

## 实施策略
- SKILL.md 固定业务路径和输出合同（仅安装/加载成功时可以跳过每次获取云盘 Runtime）。
- 每个SRT两次确定性子进程调用：`scan`，AI一次编排，`render`；失败才局部修正。
- 生成五部分时使用程序原样输出，避免聊天UI重复包装第3/5部分。

## 尚未验证，严禁夸大
- 未测量从用户提交到第五部分最后一字输出的真实端到端时间；当前工具环境不提供可信客户端终端显示时间戳。
- 多商品合并与边界判定依赖AI人工语义判断，合成案例只验证索引保持完整，不是自动识别质量验证。
- GitHub仓库放置Skill不等于已在用户ChatGPT中安装，不能自称免云盘启动已生效。

## 正式发布门槛
- 至少3类真实素材：单商品短、单商品长、多商品，交替对照各若干轮完整交付耗时中位数。
- 字幕与时间码映射零错误、五部分格式零漂移、钩子/逻辑/CTA质量不降。
- 没有端到端收益证据时，保持ACTIVE不变。
