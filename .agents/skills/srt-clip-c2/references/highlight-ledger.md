# 字幕亮点对照表与结构检查

仅字幕/SRT工具路径使用。人工通读、区分不同购买理由并完成逐窗记录后，建立 UTF-8 JSON，保存为 `highlights.json`。一项购买理由一条，`point` 为原话要点，`source_ids` 为快照中支持该点的原始字幕编号；按原素材记录，不凭品类补造。每项用 `importance` 标注为 `核心` 或 `次要`：核心内容直接影响商品是否适合或为何购买；次要内容用于补充搭配、颜色、场景或使用信息。多个相关但不同的利益分别记录，不以同类归并。来源或商品指代不明时仍可记录可靠编号并标待核实，不采用无编号的虚构来源。

单方案沿用根级 `status` 记录。多方案时，根级保留亮点清单，每一项新增 `by_plan`，按 `plans.json` 中方案顺序用字符串序号（`"1"`、`"2"`、`"3"`）记录该亮点在每版的处理；所有亮点都必须为每个方案提供一条状态。每项核心亮点优先进入适合的方案；在时长允许且有帮助时可跨方案重复。次要亮点可以按方案侧重点分配，避免每版重复罗列。每条方案预计1.2倍速成片时长不得超过120秒；时间不够时标记明确的取舍原因，不冒称该版覆盖全部亮点。

```json
{
  "highlights": [
    {
      "id": "h1",
      "point": "穿着轻",
      "importance": "核心",
      "source_ids": ["12"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["12"]},
        "2": {"status": "入选", "retained_ids": ["12"]}
      }
    },
    {
      "id": "h2",
      "point": "柔软",
      "importance": "核心",
      "source_ids": ["34"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["34"]},
        "2": {"status": "入选", "retained_ids": ["34"]}
      }
    },
    {
      "id": "h3",
      "point": "轻薄手感",
      "importance": "次要",
      "source_ids": ["56"],
      "by_plan": {
        "1": {"status": "合并", "merged_into": "h1", "retained_ids": ["12"], "reason": "与h1同义，均表达穿着轻"},
        "2": {"status": "合并", "merged_into": "h1", "retained_ids": ["12"], "reason": "与h1同义，均表达穿着轻"}
      }
    },
    {
      "id": "h4",
      "point": "功能待核实",
      "importance": "核心",
      "source_ids": ["78"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["78"], "note": "商品归属可靠；功能及适用条件待核实"},
        "2": {"status": "待核实", "exception_kind": "商品归属不明", "reason": "交叉讲解指代不清，无法确认目标商品"}
      }
    }
  ]
}
```

状态及字段：
- `入选`：`retained_ids` 非空，必须属于该条 `source_ids`，且实际存在对应冻结方案中。商品归属可靠但内容存疑的亮点仍为入选，在该状态的 `note` 写明具体待核实事项；渲染器按保留序号自动显示在对应片段。
- `合并`：`merged_into` 指向同一方案中的一条 `入选`记录，`retained_ids` 是该目标实际入选来源，`reason` 说明同义关系。同类但信息不同不可误标同义。
- `importance`：每项必须标 `核心` 或 `次要`。模型人工判断并说明依据；程序只核对字段取值，不替代重要性判断。
- `未入选`：仅用于真实素材例外，`exception_kind` 为 `商品归属不明`、`已知不实`、`当前素材已拒审` 或 `用户指定禁用词句`。时长、价值和方案侧重点不是素材例外。
- `待核实`：用于上述真实素材例外，必须提供 `exception_kind` 和具体 `reason`。归属可靠但内容存疑仍应为入选，并在对应组的 `note` 标具体疑点。用户禁用句例外须引用确实包含禁用表述的完整原句。
- `侧重点省略`：只允许 `importance` 为 `次要` 的亮点；须写明为什么更适合其他方案。多方案时，同一亮点至少应在一个方案入选/合并；如所有方案都因时长无法容纳，使用 `时长取舍` 并逐版说明。
- `时长取舍`：明确因120秒上限无法纳入某条方案；须说明该亮点在该版未入选的具体原因。若仍有方案适合承载，应安排到该版。

同一来源字幕内有完整句需要保留、另一个完整句因平台反馈或用户指定禁用而删除时，方案组使用 `sentence_edits` 明确句子边界；每个分段都写原文及 `保留`/`剪除`，按原顺序拼接后必须与来源字幕全文完全一致。例外亮点的 assignment 增加 `excluded_sentences`，逐项提供 `source_id` 和需从成片排除的精确原句。该序号可同时出现在方案和例外记录中，但校验器会确认实际保留/剪除的句子完全对应；删句仍计入来源字幕整行时长。渲染器检查选入字幕、拼接口播及标题话题，不允许用户指定禁用表述残留；例外说明可为审计引用原句。

```json
{
  "plans": [{
    "groups": [{
      "ids": ["1"],
      "function": "面料",
      "note": "序号1保留独立完整句；句间剪点待回听",
      "sentence_edits": [{
        "id": "1",
        "sentences": [
          {"text": "平台指出的整句。", "action": "剪除"},
          {"text": "同一字幕里的其他完整句。", "action": "保留"}
        ]
      }]
    }]
  }]
}
```

对应的 `highlights.json` 例外记录：

```json
{
  "highlights": [{
    "id": "h-risk",
    "point": "平台指出的材质句",
    "source_ids": ["1"],
    "status": "待核实",
    "exception_kind": "当前素材已拒审",
    "reason": "平台明确指出该整句",
    "excluded_sentences": [{"source_id": "1", "text": "平台指出的整句。"}]
  }]
}
```

完成主观补漏比较和人工冻结后执行：
```text
python -S scripts/check_highlights.py --snapshot session.json --plans plans.json --ledger highlights.json
```

退出码为0表示记录结构、来源ID、状态及保留序号与快照及每条方案的机械对应通过。失败时修正具体错误并复核。程序不识别遗漏的亮点，不判断重要性、含义是否相同、理由是否真实成立、窗口是否读完、商品事实、平台合规或音画；`HIGHLIGHT RECORD CHECK PASS` 不代表亮点齐全或成片质量通过。渲染器另行执行120秒和指定禁用表述检查。通过后仍要人工逐项审阅和按源内容补漏，逐窗反查核心与次要亮点的安排。

短文本可以直接在工作记录列出等价表并人工核对；没有原始字幕编号的 MP4-only 不虚造编号或运行此工具，应使用实际可核验时间与工作记录手动核对。没有可靠方案时不运行空方案来伪造通过。

- 被平台明确指出的材质违规句及用户指定禁用句不得作为成片原话。若整条字幕就是该句，该序号不得入选；若同一字幕还有独立清楚的其他句，可用 `sentence_edits` 保留。成片片段只显示保留句，例外记录列出被删原句和原始序号；在对应组旁标明句内剪点待回听。用户指定禁用的固定表述和变体见 `references/editorial-policy.md`。其他句/字幕逐条判断，不因此删除整段或全部材质内容。商品归属不明的行不入片。
