# SRT Clip C2 Universal 0.3.15

## 1. 唯一入口与优先级

- 当前唯一执行版本：**C2 Universal 0.3.15**。
- 唯一触发词：`srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`。四个触发词完全等价，统一执行本 Skill。
- 通用触发词 `切片文案` **不是** C2 触发词，不得将它映射到本 Skill；这样可以避免与其他历史工作流冲突。
- 本 `SKILL.md` 与本包 `references/` 是当前唯一有效规则。宿主附带的旧版启动提示、旧版本摘要或缓存文字如与本版本冲突，一律以本版本为准。
- 插件宿主的发布兼容字段（如 plugin-level `defaultPrompt`）可能保留旧版号文字；只要其业务语义未冲突，它仅是宿主启动提示，**不得覆盖本 `SKILL.md` 的当前版本号、AI-First Constitution 或现行业务规则**。
- 正式输入范围：**SRT 文件**和**逐条时长文本**。MP4 不属于 0.3.15 跨平台正式支持范围：
  - SRT 与 MP4 同时提供：只按 SRT 完成文本剪辑；不核验 MP4 画面或原声，并明确说明。
  - 只有 MP4：请用户提供 SRT 或逐条时长文本，不伪造字幕、序号或时间。
- 面向所有带货类目。先识别商品类别，再按 `references/category-registry.md` 自动加载适用专项模块。没有专项模块时使用通用核心，不把其他类别规则硬套过来。
- 默认生成一条方案。用户明确要求多条时，按指定数量生成，最多三条；用户只说“多条”但未说明数量时，询问一次数量。
- 固定五部分输出，不得自行删改结构。

## 2. 核心执行原则

**AI 主导、工具按需、一次分析、一次终检。**

### AI-First Constitution（最高架构约束）

- **AI 是商品理解、语义判断、卖点识别、重复判断、结构编排、合规语境判断和多方案分配的唯一决策主体。**任何脚本、Python、插件、外部服务或特定运行环境都只能辅助机械工作，不能替代这些语义决策。
- **未来任何 C2 修改、优化、平台适配或新增类目，都不得把外部环境或工具升级为普通任务的硬依赖。**新增能力必须先设计 AI 可独立执行的主路径，再把工具作为可选增强。
- 工具只允许做机械性工作：文件分段读取、序号/时间码定位、范围提取、时长累计、格式检查、重复编号检查等。工具输出必须交回 AI 判断，不能直接决定“这是核心卖点”“这句应当入片”或“这两个表达语义重复”；**工具不能替代这些语义决策**。
- 工具不可用、Python 不可用或平台没有特定能力时，只要原始文本仍能被 AI 可靠读取，任务必须继续执行。只有**输入本身无法取得、存在无法补齐的截断，或关键来源范围无法确认**时，才允许暂停受影响部分并如实说明。
- 不为了追求可测量、可脚本化而把自然语言任务强行转换成逐条 JSON、复杂状态机或多轮工作流。准确性需要核实时，在同次语义筛选与编排中结合来源和条件判断；最终检查只核对已选成片，不另做遗漏扫描。
- 完整细则见 `references/ai-first-constitution.md`。
- **未来每次更新与发布须按 `references/update-protocol.md` 的固定六项审查、三条一票否决及版本记录格式执行。该协议仅约束开发与发布，不增加普通 SRT 文案任务的前置步骤。**

- 普通任务默认不调用 Python、不运行环境测试、不扫描工具依赖、不创建中间 JSON 或工作流文件。
- 不把 Python、脚本、联网、外部服务或特定平台功能设为普通文本任务的前置条件。
- 只有在工具能明显提高准确性时才调用，例如：文件读取确实截断、复杂累计计算、超大文本精确定位或用户明确要求程序核验。
- 工具不可用时，普通任务继续用可用能力完成；只有在输入不完整、商品归属无法确认或关键计算无法可靠完成时，才暂停受影响部分并说明原因。
- 不得把模型人工对照说成程序核验；没有实际执行程序就不得报告“程序通过”。
- 不创建逐条 `source_text`、`semantic_summary`、`attribution` 证明字段；只对确实存在歧义的字幕记录具体疑点。
- 不建立逐条 JSON 台账，不执行旧版多阶段强制工作流工具。
- 不重复全文解析、重复建立台账或为了形式而进行多轮核验。发现局部错误时局部修复。

## 3. 一次完整执行流程

### 第一步：读取与输入检查

1. 读取本轮提供的完整 SRT 或逐条时长文本，并先判断采用 **Standard Mode** 还是 **Long Context Mode**。
2. 保留原始字幕编号、原话、时间码或逐条时长；不改写、不补造、不覆盖原件。
3. 检查明显格式问题：缺行、重复编号、编号异常、时间码倒置、时长非正数、输入截断或乱码。
4. **Standard Mode**：AI 能在一次可靠读取中覆盖全文，且不会明显增加截断、遗漏或上下文污染风险时，直接一次通读并进入商品识别。
5. **Long Context Mode**：当全文一次读取存在截断、遗漏、上下文污染或反复切换商品的明显风险时自动启用，**不设必须依赖脚本的固定条数门槛**。约1000条以上、长达数十分钟、多商品频繁切换、宿主单次读取无法覆盖全文等都属于强触发信号；2000条、接近2小时的素材必须按长文本模式处理。
6. Long Context Mode 按 `references/long-context-mode.md` 确认全局读取覆盖和商品窗口；目标窗口的购买价值筛选、去重及编排在同次 AI 语义处理中完成，再进入现有时长处理与一次终检。
7. 长文本分段时必须覆盖首尾和段间连续性，并记录已读范围；只补读缺失部分，不为了形式重复读取已经确认完整的内容。工具可帮助分段和定位，但**商品切换、指代、卖点和优先级均由 AI 判断**。
8. 读取不完整时明确标出未读范围，不得声称已完整分析。

### 第二步：商品识别与类目加载

1. 识别全部商品、别称、款式差异、商品切换边界及离散讲解窗口。Long Context Mode 下，先完成全局商品窗口地图，再锁定目标商品；**关键词只能辅助定位，不能替代 AI 对“这个/它/那款”等指代和商品切换的判断。**
2. 区分目标商品介绍、顺带搭配、其他商品独立规格、价格/库存互动和主播过渡话术。
3. 用户已指定商品时直接锁定。未指定且存在多个明确商品时，只列商品名称及必要区分信息，询问一次；在得到选择前不生成正式成片方案。
4. 自动识别商品类别并加载适用模块。以鞋类为目标优先加载 `categories/shoes.md`，以围巾/围脖/丝巾/披肩/围领配饰为目标优先加载 `categories/scarves.md`；两者均不与 `categories/womens-fashion.md` 的专项判断叠加。其他多个类别确实兼容时才组合加载；存在实质冲突或无法判断时才询问。
5. 未建立专项模块的类别仍可使用通用核心；不虚构专业规则，并在确实影响判断时说明专项规则尚未建立。

### 第三步：购买价值判断与成片编排（同次 AI 语义处理）

1. 以目标商品全部讲解窗口为判断范围；Long Context Mode 先用窗口地图确保读取完整，再在读取目标窗口时直接判断购买价值并考虑编排。
2. 遵循 **卖点决定“留不留”，结构决定“怎么排”**。凡是原话提供新的、有效的商品购买决策信息，都作为候选，包括效果、版型、材质与触感、舒适度、功能、设计、颜色、搭配、人群与身材适配、尺码、场景、季节、护理和限制。成交话术作为转化机会另行按语义价值判断，不作为商品卖点；具体价格、优惠、赠品、库存等动态交易信息按 `references/editorial-policy.md` 全局默认排除。不同类别可以同时进入同一成片；不得因主题不同、开头方向不同或衔接暂时不顺而淘汰独立有效信息。
3. 去重只看是否提供了新的购买信息。真正同义、只重复情绪而无信息增量的表达可择优保留；同类别的不同事实仍分别保留，例如不同版型效果、不同搭配理由或不同适用条件。同一具体卖点最多保留两处原话：主表达之外的第二处须有补充证据、感受、条件或更好承接价值。
4. 在筛选和排序中同时保留核心与次要购买信息。开头强度、类别、主题一致性只用于选入口或安排顺序，不构成卖点去留门槛。无需建立卖点台账或其他中间结构；判断、筛选与成片组织属于一次语义编排。
5. 仅在商品归属无法确认、必要条件无法保留、已确认合规禁用、明确已知不实等现行规则要求时排除相关原话；保留必要的适用人群、安全、护理与限制条件。语义符合但画面依赖的内容按类目规则标注待核实。

### 第四步：开头、中段与结尾编排

1. **默认以第一次刷到视频的陌生顾客为开头判断对象，老粉兼顾但不主导。**开头不是“主播最想先介绍什么”，而是“陌生顾客为什么愿意停下来”。外观/使用结果、商品核心信息、真实顾客困扰、可信体验、版型/设计、材质体验等候选统一竞争，**不设固定类型排序**；比较顾客相关性、即时收益、差异性、**具体与可信度**和**后续承接**/兑现能力。差异性是重要加分项，不是硬门槛；普遍但强烈的结果型表达只要原文真实且后续能支撑，仍可胜出。纯颜色介绍、普通搭配、普通尺码、泛泛材质名或孤立“好看/洋气”等默认降级，但**颜色若直接带来明确顾客结果**（如显气色、不沉闷），且完整原话在相关性、可信度和承接上实际竞争力更强，仍可作为开头候选。链接、价格/库存/活动、直播过渡、强依赖前情或只对老粉成立的表达原则上不作通用首钩。选定后，在同一次编排中优先寻找能解释、证明或展示开头核心价值的原话；按最小充分承接原则选择最有说服力的部分，不穷尽同主题内容。若素材无法充分支撑开头，应重新权衡开头选择；不要求整条成片只围绕一个主题。这个“陌生顾客测试”只是同次 AI 语义判断，不新增流程节点、模型轮次或台账。
2. 顾客困扰必须来自顾客原话或主播清楚转述的顾客烦恼。主播回答不能单独冒充顾客问题；尺码建议、搭配建议、主播个人偏好不自动算顾客困扰。
3. 若主播明确确认商品存在顾客担心的负面表现，该困扰及确认性回答默认不作开头、不入片；用户明确要求制作该主题答疑时例外，仍须忠实原话且不得编造解决效果。
4. 中段先兑现开头价值，再容纳其他独立有效卖点。开头获得充分支撑且至少一个购买决策理由已经成立后，若原文存在自然、完整、**对陌生顾客也成立**的成交机会，应安排最早合理的成交机会；不能仅凭“拍/买/入/拿”等关键词逼单，也不必等待所有卖点讲完。成交话术按实际作用判断，可承担价值确认、人群/尺码适配、决策简化（颜色/款式选择）、行动引导或总结等不同作用，不要求固定类型。只对“老粉/老顾客/复购用户”等限定人群成立的购买建议默认降级，除非当前素材明确面向该人群，或同一句对陌生用户也有独立、完整的决策价值。成交之后继续覆盖其他独立购买价值；后续成交节点只有提供新增转化价值时才考虑。成交次数、位置、软硬类型比例不固定，结尾不强制逼单；没有优秀成交话术时可以不放。**弱成交话术不得挤占独立有效卖点**，重复行动引导、强依赖实时直播背景或限定老粉的话术在时长竞争中低于独立购买信息。可利用效果→原因、问题→解决、顾虑→回应、特点→使用价值、属性→场景、版型→身材效果、材质→穿着体验、设计→功能价值、单品特点→搭配、人群特点→适用理由等关系自然排序；这些关系是编排提示，不是硬模板，也不要求每条都覆盖。
5. 原文天然存在的痛点与回应、预期与结果、普通状态与实际效果、错误认知与事实、前后变化等真实反差可适度提高其开头或中段优先级。只加权原文确实存在的关系，不制造冲突、故事、竞品比较、问题或承诺；没有真实反差时照常按购买信息价值编排。
6. 多方案执行 **Single Analysis, Multi Output**：商品识别、语义筛选、合规判断与来源归属只做一次；方案共享同一判断结果，按不同钩子和承接分配内容，不为制造差异牺牲独立有效卖点。
7. 结尾选择最自然、语义完整且有价值的原话；可以是商品价值、购买建议或成交引导，不强制安排逼单。动态交易信息在开头、中段、成交节点和结尾一律默认排除；仅用户明确要求制作有效期明确的活动素材并确认发布时仍有效时，才对该任务例外处理。
8. 可以重排同一商品的原话，但必须保持对象、条件和原意。不能拼接不同商品或把不同款的事实混在一起。缺少有力开头或结尾时如实说明。
### 第五步：时长计算

- 播放速度统一按 **1.2 倍速**估算。
- 每条方案预计成片时长不得超过 **120 秒**。
- 预计时长按：`选段原始时长 ÷ 1.2 + 已知未加速片头/转场/停顿` 计算。
- 毫秒四舍五入到最近 1 毫秒，正好半毫秒向上。
- SRT 来源时间码与定位保持原素材 1.0 倍口径，不缩放。SRT 选段按连续组的起止跨度估算，组内空隙计入；逐条时长文本按入选条目时长累计，未知字幕间隔不计入并需说明。
- 超过 120 秒时先排除本就不合格的无关闲聊和默认排除的动态交易信息等，再按以下顺序压缩：**真正语义重复 → 没有信息增量的重复夸赞/情绪强化 → 购买决策价值较低的内容 → 已被更强片段充分覆盖的次级信息 → 最后才是在确实时长不足时舍弃独立有效卖点。**不得因主题不同、开头方向不同、结构不统一或衔接不便优先删除独立购买理由；不突破硬上限，因时长不得不舍弃时说明具体取舍。
- 充分筛选后预计 30 秒以下，标记为“短候选，非正式成片”；大于 30 秒但不足 45 秒可以交付，并说明素材本身限制，不硬凑。
- SRT 或逐条时长文本无法核实实际导出时长、实际剪辑间隔和 1.2 倍速后的语音清晰度，必须如实说明。

### 第六步：一次最终检查与局部修复

按 `references/final-check.md` 完成现有的一次终检，核实成片来源、原意、条件、顺序、时长和合规；不新增全文回扫或独立遗漏检查阶段。
发现错误时只修复受影响的商品归属、字幕、亮点、顺序或计算，不重跑无关步骤。只有输入变化、来源映射错误或质量条件失败时才重新打开整份方案。

## 4. 合规规则

### 全商品统一禁令｜两种更新入口
- **唯一权威执行库**：`references/global-rules.md`。所有现有及新增商品类目统一继承；专项模块不得覆盖、放宽或另外维护重复禁令。
- **更新入口仅有两种**：①用户提供抖音/千川违规审核截图；②用户明确说某词句违规或要求禁用。AI 识别截图实际指出的违规宣传，或按用户明确指定内容更新全局库。无法从截图可靠定位具体词句时才询问，不根据笼统“虚假宣传”“资质不符”推造禁词。
- **严格语义边界**：AI 识别字形、数字、口语和语义等价变体；相近但含量、成分、保证程度、对象或条件不同的表述不得自动扩禁。否定/引用语境需判断实际是否构成禁用宣传；用户明确要求“该词不论语境禁止出现”的按字面禁用。重复内容合并，记录截图或用户要求的来源；用户内部禁令不冒称平台通用禁令。
- **命中即排除完整原始字幕序号**：不能在同一序号中抠除违规词后保留剩余正常卖点。同一序号涉及其他商品也整条排除；跨连续序号共同构成禁用宣传时，仅排除确实参与构成该表达的序号，不连带排除其他正常序号；不扫描无关商品的全部窗口。
- **疑似识别错误**：能依据原始连续语境可靠确认命中时排除；无法确认时把相关序号标记待回听，暂不纳入正式成片，不得伪称已核实音频。
- **执行位置**：识别目标商品及其全部离散讲解窗口时同步筛查，在编排前排除确定命中的序号；从其他合规原话补足不同卖点并检查剩余语句完整性。原有一次最终检查对入选字幕、标题与话题核对；违规标题/话题仅重写受影响字段。命中时在例外中记录排除序号、对应禁用表述和原因；无命中不另出报告。
- **材质证明审核案例**：截图明确将某材质/成分宣传指认为需要证明且被拒审时，将能够定位的对应表述及其等价变体纳入全局禁令，命中即整条排除，即使后来拿到证明也不自动解除。不要仅凭一个材质名扩大到整类材质。纯商品资质/链接问题不自动转为禁词。
- **效率**：日常只用离线规则，不联网、不定期搜索、不建立新强制流程/程序/JSON。若用户另行明确要求调查官方政策，可单独处理，但不自动扩大全局禁用库。一般风险、动态价格/库存和未经证实的信息继续按 `references/qianchuan-offline.md` 及现有业务规则处理。
- **诚实与来源**：保留原始序号和原话；不改写、不跨商品混编、不声称平台保证过审；历史审核案例未直接证实的官方普遍禁词不得伪称官方规定。

## 5. 固定五部分交付

### 一、文件解析结果
写明文件名、输入类型、原始字幕条数/覆盖跨度（如可得）、执行模式（Standard/Long Context）、目标商品窗口数量、入选条数、组数、原始选段时长、预计 1.2 倍速成片时长，以及实际核验方式。若未运行程序，明确写“模型逐条对照，未运行程序”；不得写程序通过。末尾简要说明实际检查范围及合规风险。

### 二、商品识别
列出目标商品、别称、离散讲解窗口、必要的商品归属说明，以及加载的类目模块。多个商品未指定时，先询问，不进入正式方案。

### 三、最佳成片方案
默认一条；用户明确要求多条时最多三条。每版说明主卖点或开头切入点（仅描述本版入口，不构成单主题限制）、预计时长、原始选段时长、逐组原话与来源序号。
- 原话逐字保留，按成片播放顺序展示；不得润色或拼接造句。
- 每组使用简短作用标签，例如“开头钩子”“版型承接”“材质细节”“搭配补充”“自然收尾”。
- 逐版列出亮点覆盖清单，说明核心/次要、入选序号、同义关系和未入选原因；同一卖点保留两处时，标明第二处的强化价值，不把它误报为新的独立卖点。
- 仅将商品归属不明、明确已知不实、当前素材明确拒审、用户指定禁用句等真实例外单列；时长取舍与方案侧重点不是素材违规例外。
- 疑点紧邻对应片段说明，不得只在文末笼统提醒。
- 不显示逐句毫秒时间轴或冗长过程证明；SRT 仅给大致组级来源定位，逐条时长文本给未缩放累计位置估算。
- 30 秒及以下标记“短候选，非正式成片”。

### 四、作品标题与话题
每条方案恰好一个标题、**五个话题**。话题必须与当前商品、类目和该版主线相关；不得彼此重复。已加载的类目模块可以指定最多两个类目固定话题，即**类目模块可固定最多两个类目话题**；通用核心生成其余话题补足五个；没有专项模块时，由通用核心生成五个相关话题。**通用核心不得强制加入其他类目的话题。**标题和话题不得编造事实、价格、库存或未证实功效；标题与主线一致。

### 五、原始 SRT 序号
按成片播放顺序列出原始序号。所有方案放在同一个文本代码框中，每版一行，半角逗号分隔、无空格，方案之间空一行；代码框内不放其他文字。不得伪造原始序号。

## 6. 能力与诚实边界

- 0.3.15 正式跨平台支持 SRT 和逐条时长文本。
- MP4、ASR、音画核验不在首版正式范围；没有实际视频能力时不得声称已看画面或听原声。
- 文件读取能力不足时，请用户粘贴文本或分段提供；不得声称完整读取未获得的内容。
- Python、计算器、脚本或其他工具都是可选增强，不是普通任务的必需条件；Long Context Mode 也不得把它们变成硬依赖。
- 不报告未执行的扫描、核验、测试或环境检查。
