# SRT文案与SRT切片文案｜C2 0.1.11 唯一规则版

## 优先级与范围
- **唯一规则版本：C2 0.1.11。** “srt文案”“srt切片文案”“str文案”和“C2完整精简版”均按本Skill执行；旧 V3.0、FAST-LITE、R8、旧固定交付契约和 RC5 候选规则不再作为这些触发词的现行规则。
- 适用于用户提供的 SRT 或逐条时长文本；不处理 MP4。视频或原声判断仍走独立的「切片文案 V5.1」流程。
- 本Skill用于用户已确认的**C2文本对照剪辑模式**：完整原话+原SRT编号+片段大致时间即可，不显示每句精确时间码。
- 使用本Skill定义的五部分结构、原文与编号对照、商品识别、有效CTA与时长规则。45–90秒及默认约70秒均指视频按1.2倍速播放后的预计成片时长；原始选段时长按原素材1.0倍计算，统一加速后预计成片时长 = 原始选段时长 ÷ 1.2。对应原始选段有效范围为54–108秒，约84秒原始素材对应70秒成片。只在语义完整、至少两类独立购买理由和真实CTA等质量条件满足时靠近目标，不得硬凑或重复卖点。
- 脚本按毫秒将预计成片时长四舍五入到最近1毫秒，正好半毫秒时向上；时长门槛以此预计值判断。原始字幕时间码、时长文本累计位置及剪辑定位保持原素材1.0倍口径，不按1.2倍速缩放。此规则假设全部入选素材统一以1.2倍速播放；若另有未加速的片头、转场或停顿，应将其已知时长加到预计成片时长后再判断。纯SRT工具无法核实实际导出时长或加速后的语音清晰度。
- 短文本或本轮已完整可读且结构简单的内容，直接通读一次并完成商品识别、选段、编排和输出检查。
- 长附件、行数多、输出可能被截断或累计计算较复杂时，优先走下方的长文本工具路径：工具一次处理格式、编号和累计位置，助手只做一次语义筛选；定稿后再一次核验并渲染。
- 直接读取路径可逐条对照原文并计算时长，但若未运行程序，只能说明“模型逐条对照，未执行程序”，不得声称程序核验通过或写“来源核对PASS”。`来源核对PASS`仅用于实际执行了对应脚本并通过其覆盖的来源、结构和时长检查；不代表音视频或语义已自动核验。
- 日常执行不自动读取云盘；用户明确要求规则同步、审计或云盘编辑时，定位当前ACTIVE权威版本，按用户确认范围更新并回读确认。Drive中的旧版规则与候选文档已删除；上一工作区仍有一份旧插件更新ZIP因自动审核阻止删除，禁止打开或作为规则来源。遇到其他外部或缓存旧副本，按当前ACTIVE规则裁决，不反向覆盖。安装后本Skill可以作为受支持环境的默认触发路径。

## 输入格式
- SRT文件：优先直接读取本轮可见的完整文本。若附件内容未直接呈现但本机路径可用，可用 `python -S scripts/srt_fast.py scan INPUT.srt --snapshot session.json` 读取一次。
- 逐条时长文本：每条字幕一行，格式为 `正整数编号 秒数s 原话`，例如 `1 3.4s 有请361度当家小花旦卫衣闪亮登场`。其中 `1` 是原字幕编号，`3.4s` 表示这段原话在原素材1.0倍下持续了3.4秒；编号用于定位，不能当作时长。可以上传文本文件，也可以直接粘贴；只解析每行开头的编号和时长，行内其余文字完整保留为原话。
- 文本完整可读时直接按原编号、时长和原话处理；若需脚本读取，文件方式运行 `python -S scripts/srt_fast.py scan-text INPUT.txt --snapshot session.json`，标准输入方式运行 `python -S scripts/srt_fast.py scan-text --stdin --snapshot session.json`。
- 空行忽略；编号必须为正整数且不重复；时长必须大于0且最多精确到毫秒（小数最多3位）；每条记录必须有原话。格式错误时按报错行修正，不自行猜测或丢弃内容。
- 此格式只含原素材1.0倍下每条字幕的时长、编号和原话，不含原始起止时间及字幕间隔。程序按输入顺序累加时长以提供**未缩放的累计位置估算**，不把它说成原视频绝对时间；精确核验以原编号、原话、逐条时长和选中片段总时长为限。

## 快速执行与核验分级

### 短文本快路径
1. 当字幕内容完整可读、行数与计算量适中时，直接处理文本。一次通读，在同一轮完成商品识别、离散窗口、别称、候选判断、语义筛选、合规风险提示、编排和五部分输出；不运行扫描或渲染脚本，不重复全文解析或展开多轮候选竞赛。
2. 从原文保留序号、原话、时间码或逐条时长。交叉检查入选数量、播放顺序、分组、总时长和末尾序号串。若无法可靠完成精确核对，转长文本工具路径，不猜测。
3. 在“一、文件解析结果”中注明“模型逐条对照，未执行程序”。不使用“来源核对PASS”“程序核验通过”等表述。

### 工具辅助路径（长文本、异常输入或程序核验）
1. 对很长的附件、可能被聊天显示截断的内容、需要大量累计时长计算的逐条时长文本、结构异常的输入，或用户明确要求程序级核验时，使用一次 `scan` 或 `scan-text`，生成只读 `session.json`。读取工具输出前确保返回预算足以容纳完整扫描清单；不要同时重读本Skill，也不要为避开截断而重新读取源文件。
2. 逐条时长文本可以在开头包含一行 `srt文案`、`str文案` 或 `C2完整精简版` 触发标题；解析器会忽略这一行和空行，并继续严格检查记录格式、正整数编号、重复编号、正时长和毫秒精度。
3. 助手只对完整扫描清单做一次语义分析，并在同一轮识别候选合规风险；冻结商品、候选和最终播放顺序，生成六键 `plan.json`。定稿前不计算多版方案的累计位置，不反复改方案。
4. 选段定稿后只运行一次 `python -S scripts/render_compact.py --snapshot session.json --plan plan.json --stdout`。使用其核验和渲染结果作为交付，不再手工重算时间、序号或重写字幕。
5. 若输出仍被截断，从已生成的快照分页读取剩余记录，不重读原附件：`python -S scripts/srt_fast.py page --snapshot session.json --offset <首条未读记录的零基偏移> --limit <页大小>`。若脚本不可用但完整文本可读，可直接处理并注明未运行程序；若完整文本也无法读取或无法可靠核对，则如实说明限制。多源文件各自隔离。

- 对短文本，只有附件无法直接读取、格式异常或用户明确要求程序核验时才启用脚本。长文本路径实际通过 `render_compact.py` 后，才报告其覆盖范围内的程序核验结果。
- 若存在多个可确认商品且目标未指定，只列按首次出现排序的商品名和**各自离散讲解窗口**，集中询问一次后暂停商品专属编排；时长文本窗口标为累计位置估算。多源文件相互隔离。

## 业务质量（不能为了速度牺牲）
- 开头钩子判定：以抖音数据中心的“5秒完播率”作为开头优化的首要复盘指标；“2秒跳出率”等可作辅助，不能替代它。“前5秒”统一按最终成片实际播放时间计算，不按原素材1.0倍计时；当口播统一按1.2倍速播放时，成片前5秒约对应原素材前6秒。未加速的片头、转场和停顿也按实际播放时长计入这5秒；剪辑判断以最终播放速度和顺序为准，SRT时间码及逐条时长仍按原素材1.0倍口径。剪辑时尽量让观众在最终成片前5秒内听清相关人群/场景/问题、商品类别和原文支持的具体利益，并在前1–3个信息点内组成自足、完整的语义单元（信息点不等于剪辑组或字幕行）。5秒是优化目标，不是机械截断点；完整语义优先，若自然口播超过5秒则保留完整表达，并尽量前置最能留住目标观众的痛点或利益。三项都有原文依据且开场自然时，才标为完整钩子。
- 候选筛选与编排：在一次全稿语义筛选中比较开头候选，优先按“人群/场景或痛点→商品类别→具体利益”的顺序安排，尽量让原文支持的具体利益前置到最终成片的前5秒，并保留自足、自然衔接的原文。不得以“而且/但是/然后/所以”等依赖上文的连接词开场，也不得用缺少先行词的“这个/它”等悬空指代开场。只在语义和语气连贯时重排同一商品的原句；不补写口播，序号按最终播放顺序列出，逐条时长文本位置标为累计估算。纯文本无法验证音画拼接是否自然。
- 开头数据复盘：用户提供作品数据时，以5秒完播率作为首要开头观察项，参照同账号相近题材和时长，不设通用及格线。5秒完播率偏低时检查开头相关性、商品是否说清、具体利益是否太晚；成片前5秒留存尚可而之后流失时检查中段。不要把单项指标描述为流量保证。
- 素材不够时：不得补编原文没有提供的人群、场景或利益。优先用最强的自足商品/利益句开场，并将首组标注为“卖点开场（部分符合钩子标准：缺少……）”；三项未齐时不声称完整通过。
- 成片时长：所有入选片段按1.2倍速统一播放时，预计成片45–90秒为有效范围，默认在质量允许时尽量靠近70秒。按原素材1.0倍统计时，对应选段总长54–108秒，目标约84秒。时长文本按入选逐条时长求和；SRT按每个入选连续字幕组的起止跨度求和（组内字幕空隙计入，组间未入选部分不计入）。计算预计成片时长时用原始总时长除以1.2，并四舍五入到毫秒，半毫秒向上；有效范围检查只看该1.2倍速预计值。只有语义完整、至少两类独立购买理由和真实CTA等质量条件满足时，才优先选择最接近70秒的方案；如需硬凑或重复卖点，不扩充内容，改选范围内更自然、完整的方案。若片头、转场或停顿未按1.2倍速处理，需把其已知时长额外计入总时长。脚本只给出统一1.2倍速的数学估算，无法核实实际导出时长或语音清晰度。
- 中间必须有至少两类**独立**购买理由；避免为凑时长重复卖点、不拿读弹幕/工作人员指令充当主播陈述。
- 片段必须语义完整、自然过渡；历史价格、库存、材质、售后、购买链接只按原字幕引用，不能当作当前事实。
- 结尾优先可靠、自然完整、面向观众、含购买动作的真实CTA，缺失则如实说明，不能虚构。
- 保留原SRT原文、口误、编号，不纠错不拼写“优化”。不做MP4/音频核验；疑点如实标注。

## 抖音电商合规风险筛查（轻量 Gate）

- **定位与范围：** 这是剪辑风险提示，不是穷尽式禁词表、法律意见或平台审核保证。默认只筛最终入选字幕及助手生成的标题/话题；用户明确要求全篇排查时再扩大范围。短文本在唯一通读中顺手识别候选风险；长文本在既有的一次语义筛选中一并判断，定稿 Gate 只复核最终入选内容，不增加全文重读、额外解析或多轮竞选。
- **重点类别：** 广告极限词或绝对化商品宣称（如“国家级”“最高级”“最佳”“全国第一”“唯一”“全网最低价”）；功效、效果和结果保证；缺少依据或与商品信息不一致的材质/成分、产地、品质、功能、专利或资质宣称；价格、比较价、折扣、活动时间、库存、稀缺性和购买紧迫信息与事实不一致或无法核实。示例用于提醒，不构成完整清单。
- **按语境判断：** 结合商品对象、前后字幕、主播主观体验与客观商品宣称、价格和优惠条件判断，不按单个字或关键词片段机械命中。区分个人体验与商品客观等级宣称。仅凭字幕无法核实的材质、价格、库存、资质等，标为“需事实核实”，不得直接断定为假。
- **处理方式：** 若明确高风险片段有已读字幕中的合适替代项，且替换不损害完整性和成片质量，使用替代原句；不得改写、润色、拼接或补写原话。无合适替代时保留原文并提示发布前核实；不得编造证明或作平台审核结论。助手生成的标题/话题若含无字幕依据的极限承诺，改为中性且有字幕支持的表述。
- **输出位置：** 保持五部分结构和第三部分冻结格式。在第一部分末尾增加一行合规提示：无明显风险时写“本轮入选字幕及标题/话题未见明显高风险项（不代表平台审核结论）”；发现风险时列原SRT序号、必要的原句短引、风险类别及“已替换”或“需核实”。不要在第三部分原话行内加标签，也不要更改字幕。
- **规则参考基线（2026-11-03）：** 抖音电商《创作者〖虚假宣传〗处置细则》（https://school.jinritemai.com/doudian/web/articlev0/102131）和《抖音电商创作者管理总则》（https://school.jinritemai.com/doudian/web/articlev0/102117）。官方规则示例并非穷尽列举。默认快路径不联网；用户要求最新规则或规则归类会改变选段决定时，查询官方规则中心。无法查询时说明使用内置规则基线，不宣称完成最新规则核对。

## 固定输出格式（已获用户确认）
一、文件解析结果：文件名、原始条数、跨度、入选数、组数、原始选段时长、预计1.2倍速成片时长与核验方式/结果。快路径注明“模型逐条对照，未执行程序”；运行脚本时只报告其实际核验范围。末尾另加一行合规提示，范围限于最终入选字幕及标题/话题。
二、商品识别：商品、别称、离散讲解窗口、必要历史条件说明。
三、最佳成片方案：主题、1.2倍速预计总时长、原始选段时长、逐组。首组标签：三项全有原文依据时写“开头钩子”；否则写“卖点开场（部分符合钩子标准：缺少[具体项]）”：

```text
片段1｜开头钩子
原SRT约 00:36–00:42｜序号 37–40
【37】你有怕这个脚热的
【38】都有怕这个脚出汗的
【39】你就可以去买这双鞋
【40】因为它就是一层网一层纱
```

- 此处**不**显示逐句时间戳、成片逐组时间轴、组内空隙计算或冗长功能描述；只在大于1秒字幕空白时简明标记断点。
- SRT片段时间是原素材1.0倍下的大致秒级定位；原始精确时间码用于计算与对照。时长文本的片段时间是未缩放、按单条时长累加所得的估算位置，原文没有绝对时间码。两种输入都以原编号和原话为主要剪辑依据。1.2倍速只用于成片时长估算，不缩放来源定位。
四、作品标题与话题：恰好1标题3话题。
五、原始SRT序号（按成片播放顺序）：**仅一条**无空格、半角逗号分隔序号串；能提供复制控件时提供；必须是输出最后一行，不再重复序号串或添加结语。

## 运行环境与真实性门槛
- 此插件打包的是Skill及随附Python脚本，**没有**自动托管Python执行服务，也没有可直接调用的远端MCP工具。短文本快路径不依赖脚本；长附件优先使用当前环境可访问的随包脚本，不重新联网下载或手工重建脚本。
- 只有实际执行并通过 `render_compact.py` 的对应检查，才可以报告脚本级来源核验通过。直接读取路径必须说明“模型逐条对照，未执行程序”；不把模型复核描述为程序计算。程序不执行广告合规语义判断；合规提示只报告模型实际筛查的入选字幕与标题/话题。
- 不得自造字幕、时间码、序号；发现无法可靠核验的来源映射或时间计算时，升级到脚本路径或如实说明未核验。
