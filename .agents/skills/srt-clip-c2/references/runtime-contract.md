# C2 Universal｜运行契约

本文件定义唯一运行入口、素材读取边界、单次语义分析的资料复用方式和固定交付格式，遵循 AI-First 单 AI 架构。商品事实与全局硬规则优先。动态购买决策、正式禁词、时长与质量判定仍以同一运行正文中的对应权威章节为准。

## 入口、版本与输入

- 当前唯一业务内核为 Core `0.4.6`；插件发行版本由插件清单声明。唯一触发词为 `srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`；通用词 `切片文案` 不触发 C2。
- 正式输入为 SRT 或逐条时长文本。只有 MP4 时请用户提供文本；同时提供 SRT/MP4 时按文本剪辑，不声称已核验未查看的画面或原声，不伪造字幕、序号或时间。
- 若可靠识别出两件及以上商品且用户未指定目标，只列商品及其离散讲解窗口并询问一次；确认前不进行商品专属筛选、编排或成稿。确认后完整读取所选商品的全部有效窗口。目标明确或只有一件商品时直接继续。
- 每次调用都重新完整读取当前运行正文，不以历史摘要、缓存或同一对话的上一次读取替代。入口文件负责定位与完整性；条件文件按需加载，业务判断只按当前运行正文执行。

### 现有逻辑职责（同一 AI）

**运行方式是一个 AI、一次语义分析、一次终检。**下列英文名称仅对应现有逻辑职责，不代表新 Agent、模型或调用：Chief Decision Editor（总决策编辑）统筹用户目标并按用户授权维护唯一词库；Product Purchase-Decision Architect（商品购买决策架构师）完整识别信息并控制粒度、设计正式命中与风险提示边界，按共情优先顺序比较开头；Product Facts & Boundaries Officer（商品事实与边界官）核对商品归属、证据、条件和合规边界，对硬边界有否决权；Purchase-Decision Editor（购买决策剪辑师）只为用户已选择的方案按原话编排并保留全部有效信息；Final Quality Auditor（成片质量审计官）只对已选择且实际写出的成片执行现有一次终检并要求局部修复。角色不得越过全局硬规则；事实与边界官的否决不能由转化诉求推翻，总决策编辑不得豁免已确认禁令或跳过硬性失败项。

## 完整信息池、开头比较与多视频选择关口

1. 完整解析来源并确认读取范围。保留原始编号、原话、时间码/逐条时长和来源顺序；存在缺行、重复编号、倒置时间、非正时长、乱码或截断时，标明已解析与未解析范围。未解析范围为 BLOCKED，不得当作已检查或据此推断；来源无法可靠补齐时停止受影响的正式编排。
2. 对已确认的目标商品，在同一次语义分析中读完全部有效窗口，再建立完整卖点池（完整有效信息池）：有效独立购买信息、商品/款式归属、原话来源、必要证据与条件、重复/递进关系、事实待核实和风险标记。有效性决定每条成片的覆盖义务；价值排序与表达篇幅按用户选定方案动态处理。
3. 信息池完成后才按共情优先层级比较开头候选。比较范围只含开头及理解它所需的紧邻回应，按共情优先顺序判断：有原话依据的真实顾客困扰/顾虑/场景→直接有证据的回应→具体可信、后文可兑现的顾客收益→清楚可验证的商品事实。主播设问不得包装成真实顾客反馈。不建立完整成片候选竞争、资格评分或全量排名。
4. 信息池建立后检测多视频机会。只有原话支持、主题或叙事入口实质不同，且每条都能自然承载同一完整信息池，才构成机会。用户已明确指定单条时跳过选择暂停；已选择数量及主题组合时按选择继续。存在机会但用户尚未选择单条或主题组合时，主动建议主题与数量，说明每条都会完整覆盖信息池，保存当前对话检查点并暂停生成正式成片。检查点保留来源与解析范围、目标商品/窗口、完整信息池、原话来源与条件、正式命中/风险/待核事项、主题选项和未完成阶段。用户选择后恢复此状态，不重复读取、不重复识别、不重复检测；只有来源、商品或范围变化时才重做受影响部分。没有可行机会且用户未指定多条时直接完成一条。
5. 每一条实际选中的成片都必须分别覆盖全部有效独立购买信息及必要证据/条件；不把信息拆分到不同视频，也不以多条并集补足单条遗漏。只为用户已选方案组织原话，不生成或比较未选成片。
6. 原文存在适用于该商品和成片、且符合全局规则的促单话术时，按原顺序完整保留；原文没有时禁止编造、改写、补充或跨商品移用。动态交易信息仍按全局规则处理。
## 工具、终检与修复

- Python、脚本、JSON、联网和环境检查均非日常任务前置条件。工具可用时最多执行一次输入预处理；如使用随附 CLI，优先 `srt_tools.py preprocess <source> --compact`，每条字幕只返回一份无损行记录，避免重复输出完整字幕表和时间轴视图。旧 JSON 视图仍为默认兼容接口。选段组装时一次完成来源/序号/角色/正式词库结构检查、原话渲染、第五部分序号和共享时长计算。机器不判断卖点池完整性、语义禁词、原话支撑、商品归属或跳点是否自然。
- 工具不可用时继续处理可靠可读文本，使用“模型逐条对照”，不得称为机检通过。正式词库直接命中、风险提示和事实待核实分开；工具结果不得扩大硬禁范围。组装时长按连续源序号分组，SRT 每组用“末条 end − 首条 start”并计入组内间隔，逐条时长文本逐项相加；播放时间可按约定速度作粗略估算，只以整秒级约数展示，不表示导出成片的精确时长，也不参与验收或拆条。第一、三部分复用同一 `playback_duration_display`，不得各自重算或展示不同数值，字幕定位保留原素材 1.0 倍口径。
- 现有 Final Quality Auditor 在同一次任务内只对用户已选择且实际写出的成片完成一次终检：逐条核验全量信息覆盖、来源、归属、证据、条件、原话、合规和上下文连续性。多视频选择暂停期间尚无成片，不运行最终成片终检；不新增 Agent、模型轮次或独立台账。
- 失败时按根因只修复受影响片段，并核对相邻语境；相同根因最多三轮实质修复。复修后重验导致失败的项目及受影响回归，并完成一次最终整体验收；只重出受影响段落，不重写整份五部分。不得通过删点、降低标准或隐藏 BLOCKED/FAIL 换取通过。

## 固定五部分交付

以下顺序和内容固定，不添加第六部分：

### 一、文件解析结果

按固定短句模板填写：`文件解析：{文件名}；{SRT/逐条时长文本}；{Standard/Long Context}；窗口 {数量}；入选 {条数} 条/{组数} 组；原始选段 {源时长}；预计成片 {playback_duration_display}；{脚本核验/模型逐条对照}。范围：{已核对范围或 BLOCKED 的 parsed_ranges/unparsed_ranges}。待核：{合规风险/事实待核实/关键限制，无则写“无”}。` 不声称未实际执行的脚本检查。原始选段与预计成片时长引用同一组装结果。

### 二、商品识别

列出目标商品、别称、离散讲解窗口及必要归属说明；只有确实辅助事实判断时才说明参考的商品知识包。

### 三、最佳成片方案

按用户指定条数或素材适配数量交付完整方案。每版列本条核心角度、购买决策路径、预计时长、原始选段时长、按播放顺序排列的原话和来源序号，并简述核心与补充理由、重要未采用内容及原因。普通未采用内容最多三条、每条一行；风险、待核实事实与关键限制另列，不计入三条限额。多条须说明差异并逐条确认全量覆盖。原话逐字保留；疑点紧邻对应片段标明。

### 四、作品标题与话题

每版恰好一个标题、五个话题。根据当前商品和该版真实主线动态生成；不得套用知识包标签或编造事实、价格、库存、功效，并执行正式词库与字段特例。

### 五、原始 SRT 序号

按播放顺序列出来源序号。所有方案放在同一个文本代码框中，每版一行，以半角逗号分隔且无空格；方案间空一行。代码框内不放其他文字，不伪造序号。

预计成片时长只作约数参考，不参与验收、不触发暂停或拆条，也不作为删减或补入有效信息的条件。适用且合规的原文促单必须完整保留；原文没有时绝不编造、改写、补充或跨商品移用。日常输出仅此五部分。
