# C2 Universal 0.4.1｜质量验收标准

本标准用于版本验收和开发期回归，不构成日常剪辑任务的额外流程。

## 硬性失败项

任一项实质失败即不通过：

- 原话被擅自改写、补造或不连续拼接；商品归属/款式串用；字幕编号、来源或时间伪造。
- 用固定类目模板压过当前商品、顾客问题和素材证据；商品知识包决定结构、开头、卖点排序、成交位置、话题或事实取舍。
- 总决策编辑越过事实与边界官对已确认全局禁令、商品归属或证据边界的否决。
- 开头弱候选仅凭先后位置或表面完整度压过明显更强、可信且可兑现的顾客结果；老粉限定表达被误当陌生顾客通用利益。
- 购买理由尚未成立就以弱逼单替代证明/适配信息，或忽略更自然、低阻力且能推进购买决定的原话。
- 素材仍有可自然加入的有效高/中决策价值信息，成片低于45秒却直接按正式成片交付；或为凑45秒灌入重复夸赞、弱逼单、普通过渡及无新增信息。
- 机械地按相似词或重复次数删句；删除未完成起句后的完整重述；把有说服增量的强调一律当冗余；漏掉递进句的条件/证据价值；或保留没有信息/说服增量的过度重复。
- 有效强调挤占更重要的独立购买理由，或把机械/过度重复作为达到45秒下限的材料。
- 合规、归属清楚、独立且可在时长范围内成立的高价值理由无理由遗漏；120秒硬限制下的取舍未说明真实原因。
- 90–120秒没有仍值得保留的独立高决策价值信息，或正式方案超过120秒。
- 明确要求多条时，仅更换开头而购买路径和主体同质，没有新增购买决策价值。
- 动态交易信息或全局禁用表述被错误保留；禁用范围被擅自扩大；缺少证明被误称已知虚假或平台拒审。
- 新增多个模型、串行 Agent、额外语义轮次、职责台账、强制 Python/网络/JSON 或普通文本任务环境门槛。
- 声称运行了未执行的程序、完整读取了未读文件或核验了未读取的视频；固定五部分输出实质缺失。

## 质量评分（100分）

| 指标 | 权重 |
|---|---:|
| 组织职责边界与动态内容结构 | 14 |
| 陌生顾客首屏价值与强候选裁决 | 16 |
| 高价值理由覆盖与单位时间购买决策价值 | 16 |
| 重复语义、信息/说服增量与机会成本 | 8 |
| 购买理由成立后的自然决策机会 | 10 |
| 多条方案的购买决策路径互补 | 6 |
| 商品识别、知识包边界与款式归属 | 8 |
| 原话、必要条件与来源序号准确性 | 10 |
| 正式成片45–120秒及取舍说明 | 5 |
| 合规风险判断 | 5 |
| 五部分输出格式 | 2 |
| **总分** | **100** |

建议通过线：90分，且全部硬性失败项通过。平均分不能抵消硬性失败。

## 职责与动态结构验收

- 同一个 AI 在一次语义分析中承担总决策、动态架构、事实边界和原话编排职责；现有一次终检由审计职责完成。
- 总决策编辑只能在硬规则内裁决；事实与边界官对已禁内容、事实混用和证据边界有效否决；审计官可退回局部修复。
- 内容路径能说明为什么适合当前商品、顾客和证据，不依赖“先识别类目再套模板”。
- 知识包只提示事实、条件、风险与归属，不规定剪辑结构或内容选择。
- 未登记商品类别仍能依 Universal Core 完成；不借用相近类别的商品事实。

## 重复判断与语义验收

- 机械性重复、强调性重复、递进性重复、过度性重复按实际语境区分；不以相似词或固定次数代替判断。
- 每个保留的重复表达需能说明信息增量、说服增量或必要承接作用；信息相同但说服收益明确的强调可以通过。
- 评估强调表达占用的时长是否挤掉独立购买理由。45秒下限不能豁免无价值重复。
- 回归案例要检查实际取舍结果和原话完整性，不能只检查规则关键词是否出现。

## 购买信息与验证边界

- 高/中/弱增量按具体商品和顾客动态判断；不以类别代替购买价值，不设覆盖率百分比。
- 单条方案中，合规、归属明确、可在时长内成立的独立高价值理由不得无理由遗漏；不靠堆满弱信息提升覆盖。
- 多条方案各自成立、购买路径实质互补；只换开头不算实质差异。
- 工具只可辅助读取、定位、计算和格式检查。未实际执行的程序、视频/音画查看、商品资料或平台审核必须标记未验证。
