# C2 Universal｜版本更新协议

治理级规则。适用于业务规则、商品知识包、平台适配、长文本、性能、合规基线及发布流程的变更。AI-First Constitution 与全局硬规则优先；本协议约束开发和发布，不增加日常素材剪辑步骤。

## 一、更新审查

1. **职责与 AI 主导**：同一 AI 的现有逻辑职责边界是否清楚？没有新增模型、串行 Agent、额外语义轮次或签核流程。
2. **工具最小化**：每项新增工具是否有清楚的机械用途和可验证收益？不可把工具设为普通素材任务的开始条件。
3. **环境零强制与降级**：可靠文本在工具不可用时仍可由 AI 处理；未核验事项如实标记；只对缺失或无法恢复的输入暂停受影响部分。
4. **覆盖与动态结构**：完整读取和粒度判断先于开头比较与方案编排；低决策价值与弱增量区分；方案数量、逐条覆盖例外和超长筛选只按 `references/clip-selection-policy.md`。
5. **商品与开头选择**：多商品时先呈现商品及原始讲解窗口并等待用户选择，之后才生成所选商品的开头候选；目标明确或只有一件商品时跳过商品选择。完整信息池后列出最多三个开头候选，每个仅含四个允许字段，不预选/代选/凑数；用户选择后每个开头独立生成完整成片。开头仍只比较开头及必要紧邻回应，执行 `references/editorial-policy.md` 动态顾客心理驱动优先级；存在合格候选时从中择优，仅在其不存在时才从其他有效候选择优；类型按观看动力识别，第一优先级内部无固定顺序、权重或分数。既有逐条覆盖、超长与五部分规则保持。
6. **促单和原话**：适用且合规的原文促单完整保留；没有来源时禁止编造、改写、补充或跨商品移用；动态交易信息仍按全局规则处理。
7. **终检、时长和交付**：终检覆盖每条实际输出方案；先完整编排再计算时长，120 秒不是目标或硬上限，超长动态处理遵循唯一规则；固定五部分输出不变。
8. **更新验收**：对受影响路径做回归，覆盖相关常规、长文本、多商品、多视频与商品事实情形。未实际测试的项标记“未验证”。
9. **发布与同步**：记录实际变更、版本和渠道；仅对实际写入且可读回核实的渠道声明“已同步”。效率只报告实测。

## 二、一票否决

- **边界或身份破坏**：改动商品识别、归属、重复识别、动态结构、原话真实性、正式词库精准边界、AI-First 单 AI 架构，或插件 ID、身份、入口、连接配置。
- **质量下降**：原话改写、商品串用、有效信息遗漏、单条覆盖不全、来源编号错误、仅比较开头却演变为完整成片排名、错误合规判断或以时长作门槛。
- **新环境硬依赖**：普通素材任务必须安装工具、联网、生成 JSON、启动 Agent 或通过环境测试才能开始。

必要的可选机械校验不受禁止；结果不能替代语义判断。日常 SRT 执行完全不调用 Python 或脚本，Python 只用于开发、构建和测试。

## 三、每次更新记录

- 基准和目标版本、改动性质。
- 变更文件、理由、影响场景及明确冻结项。
- 同一 AI 的逻辑职责和事实/规则否决边界。
- 动态内容路径、AI 独立主路径及工具降级。
- 读取范围、先选商品再选开头、候选格式与上限、独立成片、动态顾客心理驱动开头、每条逐条覆盖、超长动态筛选、零日常 Python、不可变序号映射硬门、原文促单、实际成片终检和固定五部分等兼容检查。
- 回归结果：PASS / FAIL / BLOCKED，真实素材范围和未验证事项。
- GitHub、私人插件、便携包、云盘等渠道各自标记已核实、未同步或待核实。
- 最终判定及一票否决项结论。

## 四、执行边界

本协议不增加日常触发任务的固定表单、脚本调用、环境检查、角色签核或对用户展示字段。只有用户明确提出更新违禁词时才联网核对平台政策并修改正式词库；政策简报不自动扩展禁词范围。
