# 字幕亮点对照表与结构检查

仅字幕/SRT工具路径使用。人工通读、区分不同购买理由并完成逐窗记录后，建立 UTF-8 JSON，保存为 `highlights.json`。一项购买理由一条，`point` 为原话要点，`source_ids` 为快照中支持该点的原始字幕编号；按原素材记录，不凭品类补造。多个相关但不同的利益分别记录，不以同类归并。来源或商品指代不明时仍可记录可靠编号并标待核实，不采用无编号的虚构来源。

单方案沿用根级 `status` 记录。多方案时，根级保留亮点清单，每一项新增 `by_plan`，按 `plans.json` 中方案顺序用字符串序号（`"1"`、`"2"`、`"3"`）记录该亮点在每版的处理；所有亮点都必须为每个方案提供一条状态。

```json
{
  "highlights": [
    {
      "id": "h1",
      "point": "穿着轻",
      "source_ids": ["12"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["12"]},
        "2": {"status": "侧重点省略", "reason": "方案二聚焦版型，不展开穿着轻盈感"}
      }
    },
    {
      "id": "h2",
      "point": "柔软",
      "source_ids": ["34"],
      "by_plan": {
        "1": {"status": "侧重点省略", "reason": "方案一聚焦轻盈和搭配，不展开触感"},
        "2": {"status": "入选", "retained_ids": ["34"]}
      }
    },
    {
      "id": "h3",
      "point": "轻薄手感",
      "source_ids": ["56"],
      "by_plan": {
        "1": {"status": "合并", "merged_into": "h1", "retained_ids": ["12"], "reason": "与h1同义，均表达穿着轻"},
        "2": {"status": "侧重点省略", "reason": "方案二聚焦版型和柔软触感"}
      }
    },
    {
      "id": "h4",
      "point": "功能待核实",
      "source_ids": ["78"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["78"], "note": "商品归属可靠；功能及适用条件待核实"},
        "2": {"status": "待核实", "exception_kind": "商品归属不明", "reason": "交叉讲解指代不清，无法确认目标商品"}
      }
    }
  ]
}
```

状态及字段：
- `入选`：`retained_ids` 非空，必须属于该条 `source_ids`，且实际存在对应冻结方案中。商品归属可靠但内容存疑的亮点仍为入选，在该状态的 `note` 写明具体待核实事项；渲染器按保留序号自动显示在对应片段。
- `合并`：`merged_into` 指向同一方案中的一条 `入选`记录，`retained_ids` 是该目标实际入选来源，`reason` 说明同义关系。同类但信息不同不可误标同义。
- `侧重点省略`：仅多方案台账使用；该版本不采用此亮点，必须写具体的版本侧重点原因，不提供 `retained_ids`。此状态会在该方案的“本版侧重点未选亮点”中展示，不属于素材例外。若该亮点的来源字幕仍被选入该方案，只有对应组的 `note` 明确包含该序号及“保留”“剪除”“回听”三个要点时，才允许记为侧重点省略。
- `未入选`：单方案只允许 `exception_kind` 为 `商品归属不明`、`已知不实`、`当前素材已拒审` 之一；多方案按版本逐条记录时同样只允许这些例外。`reason` 写真实、具体原因。
- `待核实`：用于上述三类素材例外，必须提供 `exception_kind` 和具体 `reason`。归属可靠但内容存疑应为入选，并在对应组的 `note` 标具体疑点。

完成主观补漏比较和人工冻结后执行：
```text
python -S scripts/check_highlights.py --snapshot session.json --plans plans.json --ledger highlights.json
```

退出码为0表示记录结构、来源ID、状态及保留序号与快照及每条方案的机械对应通过。失败时修正具体错误并复核。程序不识别遗漏的亮点，不判断含义是否相同、理由是否真实成立、窗口是否读完、商品事实、合规或音画；`HIGHLIGHT RECORD CHECK PASS` 不代表亮点齐全或成片质量通过。即使通过仍要人工逐项审阅和按源内容补漏。多方案的“侧重点省略”只记录版本取舍，不可替代完整亮点盘点。

短文本可以直接在工作记录列出等价表并人工核对；没有原始字幕编号的 MP4-only 不虚造编号或运行此工具，应使用实际可核验时间与工作记录手动核对。没有可靠方案时不运行空方案来伪造通过。

- 例外来源序号不得进入成片。若平台明确指出某条材质字幕违规，整条字幕序号不得进入成片；同一字幕行里的其他信息也随行删除，并说明删除原因，邻近字幕逐条保留和判断。若已知不实或已拒审内容与有效亮点同处一行，也不得在字幕行内改写或截词；按该类问题的明确范围处理整条来源记录，并说明其影响。商品归属不明的行不入片。
