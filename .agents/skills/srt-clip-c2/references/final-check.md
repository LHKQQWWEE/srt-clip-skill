# 一次最终检查清单

每条正式交付在输出前完成一次整体检查，核实已选成片及其来源、归属、原意、条件、顺序、时长、合规和格式。本清单不是新的卖点扫描、全文复查、台账或模型轮次。

## 明确失败项

出现以下任一项，方案质量验收不通过：

- **弱开头压过强结果开头**：仅因颜色、搭配、材质类别或句子完整，让没有明确顾客结果的弱候选胜过更强、可信且可兑现的陌生顾客收益。
- **购买理由未成立就弱逼单**：用“赶紧拍/直接买”等弱行动口号替代必要证明或适配确认。
- **素材充分却低于45秒**：存在可自然纳入的有效高/中决策价值理由，完成筛选后仍低于45秒且未先评估这些理由，却把方案作为正式成片交付。
- **为凑时长灌水**：用重复夸赞、弱逼单、普通过渡或无新增信息的颜色/搭配将短片拉到45秒。
- **高决策价值亮点无理由遗漏**：合规、归属明确、独立且可在时长内成立的高决策价值理由，被忽略且没有真实取舍原因。
- **多条仅换开头但购买路径同质**：用户要求多条时，主体与决策路径基本相同，又没有带来新的顾客理由或决策角度。
- 原话被改写、补造或不连续拼接；商品/款式归属混用；编号、来源或时间造假。
- 正式方案预计 1.2 倍速时长超过120秒；动态交易信息或全局禁用表述被错误保留；禁用范围被擅自扩大。
- 把缺少证明说成已知虚假，虚称平台拒审，或声称运行了未执行的程序、完整读取了未读文本、核验了未看的视频。
- 固定五部分输出实质缺失。

## 检查项

1. **输入范围**：确认实际读取的 SRT/逐条时长文本及覆盖跨度；未读或截断范围不能假称已读。Long Context Mode 依窗口地图确认目标范围完整，前后候选按同一标准竞争。
2. **商品归属**：每条入选原话确实属于目标商品；不同商品、不同款式的规格和条件没有混用。
3. **类目规则**：已识别商品类别并加载现存适用模块；没有借用其他类别规则。Universal Core 的通用结构优先于类目说明。
4. **原话来源**：原话、原始序号和来源位置一致；没有润色、补造或伪造编号。
5. **购买理由与价值层级**：按高/中/弱增量动态取舍；独立高决策价值信息没有因为开头主题、首次成交、类别不同或位置靠后而无理由遗漏。仅核对已选方案与已有判断，不重新回扫全文。
6. **开头与首屏价值**：陌生顾客听完首屏可理解具体收益、要解决的问题或继续观看理由。弱颜色/普通搭配没有只凭形式完整压过强结果；颜色有明确顾客结果时允许公平竞争。
7. **购买决策链与首次闭环**：后续片段自然证明/推进前文；购买理由成立后优先安排低阻力、自然的首次购买决策机会；购买理由未成立前不使用弱逼单。首次成交后继续考虑尚未利用的高价值独立理由；不强制固定成交数、位置或结尾逼单。
8. **信息密度**：每个片段提供新购买理由、证明、顾虑回应、适配/选择帮助、决策推进或必要承接；删除无新增且拖慢成片的内容。
9. **时长**：正式方案按 1.2 倍速预计 45–120 秒。低于45秒时先检查未利用的高/中价值信息；仍不足则标记“短候选，非正式成片”，不得灌水。90–120秒只在仍有独立高决策价值信息时使用。超时压缩遵循 `highlight-selection.md`，高价值信息只在硬上限下最后取舍并说明原因。
10. **合规与动态信息**：按现行全局规则和适用类目条件筛查。混合字幕只保留完整、连续、自足的原话子句；动态信息删除后剩残句就舍弃整条相关字幕，不改字、补词或拼接。命中全局禁令排除完整原始序号。
11. **多方案互补**：多条均独立成立，购买决策路径有实质差异；核心理由可共享，次要理由按适配方案补充。不得只换开头复制主体或为凑数量降低质量。
12. **AI-First 与五部分交付**：AI 保留所有语义决策权，工具仍为可选机械辅助；没有新增日常模型轮次、环境门槛或台账。五部分顺序、标题话题、来源序号代码框和必要风险说明符合 `SKILL.md`。

发现问题时只修复受影响内容并核对关联项。无法确认商品归属、读取范围或关键时长时，说明限制，不猜测。没有实际运行程序就写“模型逐条对照，未运行程序”；本清单不构成程序证明，也不保证平台审核结果。
