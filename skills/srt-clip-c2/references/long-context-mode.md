# Long Context Mode｜AI-First 长文本模式

## 目标与边界

在较长、多商品或分散窗口的字幕材料中，管理可核实的读取范围和目标商品边界。商品理解、购买信息识别、开头比较与编排仍由同一 AI 在一次语义处理中完成。

## 启用与读取

- 当全文读取有截断、遗漏、上下文污染或商品反复切换风险时，按需启用长文本处理。
- 覆盖来源首尾、窗口之间的必要上下文以及目标商品全部离散片段。分段只管理读取范围；窗口地图只确认范围和商品归属，不替代信息池。
- 逐个目标窗口记录读取范围并理解归属、条件与合规边界；读完所有目标窗口后，再一次性识别完整有效信息池并控制粒度。不得边读边锁定主线、生成成片或围绕局部方案补点。
- 多商品先呈现商品身份与原始讲解窗口并等待用户选择；确认前不提供商品专属开头候选。目标明确或单商品时跳过商品确认。
- 完整建立所选商品信息池后，按 `references/editorial-policy.md` 的开放式观看动力优先级识别真实原话及必要紧邻承接：存在合格第一优先级候选时，候选池仅纳入这些候选；没有时才从其他有效钩子中形成候选池。类型按实际观看动力动态归类，不按卖点类别或名称机械判断，第一优先级内部无固定顺序、权重或评分。展示候选池内全部合格且彼此实质不同的开头，由用户选择，不预选、不代选。
- 展示所有达到现有质量门槛且彼此实质不同的开头候选，不设识别或展示数量上限；不得漏掉合格候选、包装重复候选或凑数。每个只展示方案名称、开头原话、原始 SRT 序号、预估时长。等待用户最多选择三个；超过三个时暂停并要求重选。每个所选开头独立生成一条完整成片并覆盖完整有效卖点池。开放板块编排和逐条容量复核仍遵循 `references/clip-selection-policy.md`。

## 前后位置公平

所有已读窗口都应对完整信息池和开头比较提供公平来源。后段出现的重要顾客困扰、直接回应、可信收益或独立购买信息不能因位置靠后而遗漏；但开头比较始终限于开头和必要紧邻回应，不扩展为完整成片竞争。

## 装配与降级

1. 确认来源读取范围和目标商品窗口；仅补读确实缺失的范围。
2. 所有目标窗口完整读完后，按 `references/editorial-policy.md` 建立信息池并识别全部合格开头候选；按 `references/clip-selection-policy.md` 将用户选择的每个开头分别编排成片。成片数量不得因发现其他主题而自动增加或减少。
3. 每条成片必须从对应用户所选开头开始，分别完成正文动态重组、逐条覆盖与 `references/final-check.md` 终检；不得替换开头或用另一条成片补足覆盖。

分段读取、时间码定位和时长估算是可选机械辅助；工具不可用时，只要文本仍可靠可读就继续。只有来源无法取得、读取范围存在无法补齐的缺口或关键归属无法确认时，才说明受限。
