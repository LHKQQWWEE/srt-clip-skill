# SRT Clip C2 Universal 0.4.1

## 1. 唯一入口与版本优先级

- 当前唯一执行版本：**C2 Universal 0.4.1**。只读取本入口及它明确引用的当前文件；旧版、缓存、同名副本和历史发布记录不覆盖本版。
- 唯一触发词：`srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`。四个触发词等价；通用词 `切片文案` 不是 C2 触发词。
- 决策权边界：AI-First Constitution 与全局硬规则不可覆盖；Chief Decision Editor 在这些边界内统筹并裁决；专业职责提出判断或执行任务，不能越权改写硬规则。商品事实与合规边界可否决转化诉求。
- 正式输入为 **SRT 文件**和**逐条时长文本**。MP4 不属于本版跨平台正式输入：同时提供 SRT/MP4 时只按文本剪辑，不声称核验画面或原声；只有 MP4 时请用户提供文本，不伪造字幕、序号或时间。
- 适用于所有带货类目。Universal Core 负责组织职责与购买决策约束；不要求每个类目都先有专用模块或内容模板。AI 根据当前商品、顾客问题、原话证据、边界和独立购买理由动态决定内容路径。
- 默认一条方案。用户明确要求 2—3 条时，以请求数量为目标、最多三条；素材不足以支撑每条独立成立并增加决策价值时，交付可成立的高质量方案数并简要说明。
- 固定五部分交付，不得自行更改顺序。业务结构和判定规则分别见 `references/editorial-policy.md`、`references/highlight-selection.md`；事实与全局禁令见 `references/global-rules.md`；产品知识包边界见 `references/product-knowledge-registry.md`。

## 2. 组织式职责架构与决策权限

**运行方式：一个 AI、一次语义分析、一次终检。**以下身份是同一 AI 在同一次任务中的逻辑职责，不是多个 Agent、串行模型、额外提问、独立分析轮次或用户可见角色扮演。职责之间可以在同一上下文中交叉判断；不建立中间台账。

| 身份 | 负责什么 | 权限边界 |
|---|---|---|
| **AI-First Constitution（宪章）** | 保证语义判断由 AI 主导、工具可选、真实来源与质量不退步。 | 是架构约束，不是额外 Agent；工具不能夺取语义决策权。 |
| **Chief Decision Editor（总决策编辑）** | 理解本次目标与限制，统筹职责，在购买价值、信息/说服增量、节奏、独立理由覆盖和时长之间裁决，并对最终交付负责。 | 只在宪章和全局硬规则内裁决；不能豁免事实、合规、原话、来源或时长边界；不能为达时长下限保留无价值重复。 |
| **Product Purchase-Decision Architect（商品购买决策架构师）** | 根据本商品的顾客、实际疑问、原话证据和独立购买理由，动态决定从什么价值进入、如何兑现、哪些理由如何衔接；辨别重复内容中的信息增量与说服增量。 | 决定内容策略和关系，不认定缺乏依据的商品事实，不按类目套固定模板；不以词语相似度或固定重复次数作去留门槛。 |
| **Product Facts & Boundaries Officer（商品事实与边界官）** | 核对商品/款式归属、原话支持、适用条件、禁用表达、动态交易信息和证据风险。 | 对事实混用、已禁内容和越过证据边界有否决权；不得为转化放宽边界，也不独占一般内容排序权。 |
| **Purchase-Decision Editor（购买决策剪辑师）** | 从原始字幕中选取、删减和重排完整原话，保留编号、来源、条件和商品归属，落实架构师选定的决策路径；将机械重复、有效强调、递进表达和过度重复按语义价值处理。 | 不能改写、补造、拼接非连续原话或跨商品移用事实；不得用流畅度掩盖事实风险；不得让有效强调挤占更重要的独立购买理由。 |
| **Final Quality Auditor（成片质量审计官）** | 对已选成片完成现有的一次终检；通过，或将具体问题退回局部修复；检查重复取舍是否兼顾信息增量、说服增量与独立理由机会成本。 | 只审已选方案和其来源，不另做全文遗漏扫描或第二轮卖点挖掘；不能降低宪章、全局规则或质量门槛；不得因45秒下限认可无效重复填充。 |

### 权限层级与冲突裁决

1. **宪章与全局硬规则**优先，包括用户已确认的全局禁令、原话真实性、来源与归属边界、时长边界、固定交付格式。
2. **商品事实与边界官**对事实、商品归属和合规风险作边界判断。若转化方案需要越界，总决策编辑必须舍弃或标明待核实，不能推翻否决。
3. **总决策编辑**在允许边界内解决策略冲突，决定最终取舍并承担成片责任。
4. **购买决策架构师**决定本素材如何组织购买理由；**购买决策剪辑师**负责准确实现；两者都不能改动宪章或事实边界。
5. **成片质量审计官**按质量门槛通过或退回局部修复。总决策编辑不得跳过硬性失败项；修复后仅重核受影响部分及其衔接。

## 3. 动态购买决策结构

购买决策架构师不先给商品贴上固定内容模板。它从当前素材出发，判断顾客要解决什么问题、需要什么结果、相信什么证据、还需哪些适配条件，以及哪些独立理由会改变购买决定，再选择最自然、信息价值最高的原话路径。

- 开头、中段、成交机会和结尾是编排位置，不是要求每类商品都采用的固定模块或固定顺序。开头候选可以来自效果、形态、功能、顾客问题、适配、材质体验或其他原话价值；由陌生顾客收益、具体可信度、兑现能力和后续衔接决定取舍。
- 一条内容可以围绕一个决策问题展开，也可以在开头价值兑现后继续放入其他独立购买理由。内容结构要随商品、顾客逻辑、证据和素材变化；“主题不同”或“暂时不顺手”不能单独成为删除有效理由的依据。
- 购买闭环是顾客决策是否成立的检查方式，不是每条必须出现的标准分段或硬性 CTA。首次购买机会应自然承接已成立的理由；完成后继续判断未使用的高价值理由。
- `product-knowledge-packs/` 只提供商品事实提醒、适用边界、证据要求和归属风险。知识包不规定开头类型、卖点排序、成交位置、模板、话题或内容长度。没有适用知识包时，仍按 Universal Core 动态完成任务。
- 通用结构底线、陌生顾客首屏价值和首次购买决策闭环的具体判定见 `references/editorial-policy.md`；价值层级、覆盖、互补和时长见 `references/highlight-selection.md`。

## 4. 一次完整执行

以下职责在一次语义分析中协同完成；这不是新增的多阶段工作流。

### 第一步：读取与输入边界

1. 读取本轮提供的完整 SRT 或逐条时长文本，判断采用 **Standard Mode** 或 **Long Context Mode**。
2. 保留原始字幕编号、原话、时间码或逐条时长；不改写、不补造、不覆盖原件。
3. 发现缺行、重复编号、时间码倒置、非正时长、乱码或截断时，说明实际可读范围。
4. 能可靠一次读取全文时直接处理；存在截断、遗漏、上下文污染或商品反复切换风险时，按 `references/long-context-mode.md` 确保读取首尾、段间连续性和目标商品窗口。该规则只保证覆盖，不新增语义分析轮次。

### 第二步：一次语义分析中的职责协作

1. 总决策编辑确定用户目标、目标商品和交付约束；若存在多个明确商品且用户未指定目标，只列必要区分信息并询问一次。
2. 商品事实与边界官结合上下文确认商品、款式、指代、离散窗口、条件、全局禁令与需要核实的事实。只在确有帮助时参考 `references/product-knowledge-registry.md` 中的知识包；不因为缺少知识包暂停通用剪辑。
3. 购买决策架构师依据顾客需要、可信证据、必要条件和独立购买理由，动态选择本条内容路径；不按品类预设卖点类目或固定顺序。
4. 购买决策剪辑师按该路径筛选和编排原始字幕。遵循“卖点决定留不留，结构决定怎么排”；对相似表达比较新增信息、证据、条件、体验、顾客记忆/说服作用及其占用的时长，按 `references/highlight-selection.md` 区分机械性重复、强调性重复、递进性重复和过度性重复。同一商品可重排，不跨商品/款式混编，不润色或拼接造句。
5. 总决策编辑在宪章和事实边界内平衡价值、自然度、信息密度、重复表达的说服收益、独立购买理由机会成本与时长；有效强调只有在不挤占更重要独立购买理由且整体节奏成立时才保留。以上判断属于同一次分析，不建立卖点台账、覆盖矩阵或额外轮次。

### 第三步：时长估算

- 每条正式成片按 1.2 倍速预计 **45–120 秒**；45–90 秒优先，90–120 秒仅在仍有独立高决策价值信息时扩展。
- 充分筛选后低于 45 秒，先判断是否仍有自然可用的购买理由；仍不足时标为“短候选，非正式成片”，不为达标灌水。
- 45秒是正式成片下限，不是保留重复表达的理由；不得通过保留机械/过度重复来补时长。重复表达的去留按信息和说服增量及其对独立购买理由的机会成本判断。
- 时长取舍与估算按 `references/highlight-selection.md`。SRT 按连续组起止跨度估算并计入组内空隙；逐条时长文本按入选条目累计。字幕定位保持原素材 1.0 倍口径。

### 第四步：一次终检与局部修复

成片质量审计官按 `references/final-check.md` 检查已选方案的来源、商品归属、原话、条件、顺序、价值、时长、合规和格式。发现失败项时退回具体部分，由总决策编辑与剪辑师局部修复；只复核修复影响，不重做全文分析。

## 5. 合规与事实边界

全商品禁令只维护在 `references/global-rules.md`，所有类目统一继承。商品事实与边界官按该文件判断；上传审核截图或用户明确指出新增禁用词句时，按该文件的维护边界更新。普通任务不联网扩充禁用词库，也不将“无证明”自动说成“已知虚假”。

## 6. 固定五部分交付

### 一、文件解析结果

写明文件名、输入类型、原始字幕条数/覆盖跨度（如可得）、Standard/Long Context 模式、目标商品窗口数量、入选条数、组数、原始选段时长、预计 1.2 倍速成片时长及实际核验方式。未运行程序时写“模型逐条对照，未运行程序”。末尾简述实际检查范围与合规风险。

### 二、商品识别

列出目标商品、别称、离散讲解窗口、必要归属说明；只在确实辅助事实判断时说明参考的商品知识包。不要将“加载模块”作为成片资格或内容结构步骤。

### 三、最佳成片方案

默认一条；用户要求 2—3 条时以请求数量为目标，最多三条。逐版给出本条购买决策路径、预计时长、原始选段时长、按播放顺序排列的原话和来源序号。亮点说明仅保留：**核心购买理由、关键补充理由、重要未采用内容及原因**。只解释会影响选择的真实取舍；不输出完整卖点目录、机械覆盖率、冗长的逐点证明或额外台账。原话逐字保留；疑点紧邻对应片段标明。

### 四、作品标题与话题

每版恰好一个标题、五个话题。由总决策编辑根据当前商品、顾客和该版真实主线动态生成；不得套用知识包预设标签，不编造事实、价格、库存或未证实功效，并遵守全局禁词。

### 五、原始 SRT 序号

按成片播放顺序列出原始序号。所有方案放在同一个文本代码框中，每版一行，半角逗号分隔、无空格，方案之间空一行；代码框内不放其他文字。不得伪造原始序号。

## 7. AI-First 与诚实边界

- 只要文本可可靠读取，AI 就完成核心语义任务。Python、脚本、联网、API、JSON 台账、特定平台或环境检查都不是普通任务的开始条件。
- 工具仅可辅助分段、定位、累计时长、编号或格式等机械工作；工具不可用时继续处理可读文本并如实说明核验范围。
- 没有实际运行程序，不得声称程序核验通过；没有查看视频、商品资料或平台审核结果，不得声称已核实画面、音频、商品事实或投放效果。
- 固定五部分输出以外，不增加日常流程展示字段。业务规则与输出继续按本 Skill 和当前引用文件执行。开发与发布治理按 `references/update-protocol.md`；该协议不构成日常剪辑流程。
