# srt-slice-copy｜SRT文案 C2 0.1.9 唯一规则版

已按照用户确认格式保留 **片段功能 / 约略定位 / 原序号 / 完整原话**，不展示逐句毫秒时间码。支持SRT和逐条时长文本。

## 开头钩子

成片最前面的钩子应是完整语义单元，一般在前1–3个信息点内完成，约5–10秒只作参考；信息点不等于剪辑组或字幕行。字幕原文要支持目标人群/场景/问题、商品类别或不适用判断、具体利益。不得以“而且/但是/然后/所以”等承接词或缺少先行词的“这个/它”起头。素材不足时标注“卖点开场（部分符合钩子标准：缺少……）”，不补编。

## 快捷使用
上传 `.srt` 字幕文件，或上传/粘贴逐条时长文本，在启用本插件的聊天发送：**`srt文案`** 或 **`srt切片文案`**。
逐条文本每行格式为 `序号 秒数s 原话`，例如 `1 3.4s 有请361度当家小花旦卫衣闪亮登场`；其中1是字幕编号，3.4s是原素材1.0倍下该条原话的持续时长。所有入选片段按1.2倍速播放后的预计成片保持45–90秒，并在内容质量允许时尽量接近70秒；原始选段对应54–108秒，目标约84秒。估算时原始时长除以1.2并四舍五入到毫秒，半毫秒向上。原SRT定位与时长文本累计位置保持未缩放；未加速的片头、转场或停顿要另计。纯SRT无法核实实际导出时长或加速后的语音清晰度。兼容 `str文案` 与 `C2完整精简版`。所有触发词使用同一套 C2 0.1.9 规则；旧 V3.0、FAST-LITE、R8、旧固定格式契约和 RC5 候选规则不再生效。
短文本或对话中已完整可读的字幕，直接逐条处理，不要求运行脚本；结果注明“模型逐条对照，未执行程序”。长附件、可能被截断的内容或需要大量累计时长计算时，用一次扫描和一次定稿核验分担格式、编号、累计时间及最终序号检查。商品语义和选段始终由模型判断。定稿时会对最终入选字幕及标题/话题做一次语境化的抖音电商合规风险筛查；它提示风险，不提供完整禁词表或审核保证。

## 长附件处理与机器核验

短文本可直接处理。长附件或希望程序核验时，逐条时长文本可以在开头带一行 `srt文案`、`str文案` 或 `C2完整精简版`；解析器会跳过这一行和空行。

```
python -S scripts/srt_fast.py scan-text INPUT.txt --snapshot session.json
# 例如已完整读到第300条，从第301条继续；offset填首条未读记录的零基偏移：
python -S scripts/srt_fast.py page --snapshot session.json --offset 300 --limit 300
# AI完成一次语义筛选并创建六键plan.json后，只核验/渲染一次：
python -S scripts/render_compact.py --snapshot session.json --plan plan.json --stdout
```

分页的 `--offset` 从0开始，后续页增加offset。直接粘贴内容可传给 `scan-text --stdin --snapshot session.json`。程序按输入顺序累计每条时长，只生成**累计位置估算**，不伪造原视频绝对时间码。只报告脚本实际核验的范围。
