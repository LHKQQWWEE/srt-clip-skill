# 字幕亮点对照表与结构检查

仅字幕/SRT工具路径使用。人工通读、区分不同购买理由并完成逐窗记录后，建立 UTF-8 JSON，保存为 `highlights.json`。一项购买理由一条，`point` 为原话要点，`source_ids` 为快照中支持该点的原始字幕编号；按原素材记录，不凭品类补造。多个相关但不同的利益分别记录，不以同类归并。来源或商品指代不明时仍可记录可靠编号并标待核实，不采用无编号的虚构来源。

单方案沿用根级 `status` 记录。多方案时，根级保留亮点清单，每一项新增 `by_plan`，按 `plans.json` 中方案顺序用字符串序号（`"1"`、`"2"`、`"3"`）记录该亮点在每版的处理；所有亮点都必须为每个方案提供一条状态。每个请求方案都须覆盖全部归属明确、有原话支持的不同亮点；不同侧重点只能改变开头或顺序，不能作为省略理由。

```json
{
  "highlights": [
    {
      "id": "h1",
      "point": "穿着轻",
      "source_ids": ["12"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["12"]},
        "2": {"status": "入选", "retained_ids": ["12"]}
      }
    },
    {
      "id": "h2",
      "point": "柔软",
      "source_ids": ["34"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["34"]},
        "2": {"status": "入选", "retained_ids": ["34"]}
      }
    },
    {
      "id": "h3",
      "point": "轻薄手感",
      "source_ids": ["56"],
      "by_plan": {
        "1": {"status": "合并", "merged_into": "h1", "retained_ids": ["12"], "reason": "与h1同义，均表达穿着轻"},
        "2": {"status": "合并", "merged_into": "h1", "retained_ids": ["12"], "reason": "与h1同义，均表达穿着轻"}
      }
    },
    {
      "id": "h4",
      "point": "功能待核实",
      "source_ids": ["78"],
      "by_plan": {
        "1": {"status": "入选", "retained_ids": ["78"], "note": "商品归属可靠；功能及适用条件待核实"},
        "2": {"status": "待核实", "exception_kind": "商品归属不明", "reason": "交叉讲解指代不清，无法确认目标商品"}
      }
    }
  ]
}
```

状态及字段：
- `入选`：`retained_ids` 非空，必须属于该条 `source_ids`，且实际存在对应冻结方案中。商品归属可靠但内容存疑的亮点仍为入选，在该状态的 `note` 写明具体待核实事项；渲染器按保留序号自动显示在对应片段。
- `合并`：`merged_into` 指向同一方案中的一条 `入选`记录，`retained_ids` 是该目标实际入选来源，`reason` 说明同义关系。同类但信息不同不可误标同义。
- 每版均须将可用亮点标为 `入选` 或确属同一信息的 `合并`。不可用“版本侧重点”省略不同卖点。只有商品归属不明、已知不实、当前素材曾拒审这三类真实素材例外可以不入片，并在对应版如实标记。
- `未入选`：单方案只允许 `exception_kind` 为 `商品归属不明`、`已知不实`、`当前素材已拒审` 之一；多方案按版本逐条记录时同样只允许这些例外。`reason` 写真实、具体原因。
- `待核实`：用于上述三类素材例外，必须提供 `exception_kind` 和具体 `reason`。归属可靠但内容存疑应为入选，并在对应组的 `note` 标具体疑点。

同一来源字幕内有完整句需要保留、另一个完整句因平台明确反馈而删除时，方案组使用 `sentence_edits` 明确句子边界；每个分段都写原文及 `保留`/`剪除`，按原顺序拼接后必须与来源字幕全文完全一致。例外亮点的 assignment 增加 `excluded_sentences`，逐项提供 `source_id` 和需从成片排除的精确原句。该序号可同时出现在方案和例外记录中，但校验器会确认实际保留/剪除的句子完全对应；删句仍计入来源字幕整行时长。

```json
{
  "plans": [{
    "groups": [{
      "ids": ["1"],
      "function": "面料",
      "note": "序号1保留独立完整句；句间剪点待回听",
      "sentence_edits": [{
        "id": "1",
        "sentences": [
          {"text": "平台指出的整句。", "action": "剪除"},
          {"text": "同一字幕里的其他完整句。", "action": "保留"}
        ]
      }]
    }]
  }]
}
```

对应的 `highlights.json` 例外记录：

```json
{
  "highlights": [{
    "id": "h-risk",
    "point": "平台指出的材质句",
    "source_ids": ["1"],
    "status": "待核实",
    "exception_kind": "当前素材已拒审",
    "reason": "平台明确指出该整句",
    "excluded_sentences": [{"source_id": "1", "text": "平台指出的整句。"}]
  }]
}
```

完成主观补漏比较和人工冻结后执行：
```text
python -S scripts/check_highlights.py --snapshot session.json --plans plans.json --ledger highlights.json
```

退出码为0表示记录结构、来源ID、状态及保留序号与快照及每条方案的机械对应通过。失败时修正具体错误并复核。程序不识别遗漏的亮点，不判断含义是否相同、理由是否真实成立、窗口是否读完、商品事实、合规或音画；`HIGHLIGHT RECORD CHECK PASS` 不代表亮点齐全或成片质量通过。即使通过仍要人工逐项审阅和按源内容补漏；特别要逐窗反查，并确认每个方案的覆盖清单都包含全部可用亮点。

短文本可以直接在工作记录列出等价表并人工核对；没有原始字幕编号的 MP4-only 不虚造编号或运行此工具，应使用实际可核验时间与工作记录手动核对。没有可靠方案时不运行空方案来伪造通过。

- 被平台明确指出的材质违规句不得作为成片原话。若整条字幕就是该违规句，该序号不得进入成片；若同一字幕还有独立且清楚的非违规句，可用 `sentence_edits` 保留该句。成片片段只显示保留句，例外亮点列出被删原句和原始序号；在对应组旁标明句内剪点待回听。其他句/字幕逐条判断；不得因此删除整段或全部材质内容。商品归属不明的行不入片。
