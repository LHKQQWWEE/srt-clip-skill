# C2 Universal Core 0.4.6｜Plugin 0.4.26 质量验收

本标准用于开发和发布验收，不增加日常剪辑步骤。AI 仍是唯一语义判断者；工具只提供可复核的机械证据。

## 一票否决项

任一项实质失败即不通过：

- 商品识别、归属、重复语义、动态内容结构、原话边界、正式违禁词范围或 AI-First 单 AI 架构被破坏。
- 未完整读取目标商品的有效窗口、未建立完整有效信息池，就比较开头、检测多视频机会或生成成片。
- 用完整成片竞争、资格打分或多维排名取代开头候选比较；开头没有按共情优先，或把主播设问误写成真实顾客反馈。
- 全量信息池完成后漏做多视频机会检测；已有实质不同且均可自然承载完整信息池的主题、用户又未作选择时，未主动建议并暂停；等待期间没有保存足以恢复的来源、范围、商品、信息池、可行主题、风险和待核事项。
- 用户选择后重新读取、识别或检测，且来源、商品和范围并未改变。
- 任一实际成片漏掉有效独立购买信息或必要证据/条件；其他成片、选题并集、时长或评分不能补偿。不得把全量点拆散到不同成片。
- 原话被改写、拼接、补造，来源序号伪造，商品串用，条件/归属改变，或正式违禁词的排除范围被扩大。
- 原文存在适用且合规的促单话术，却未在对应成片中按原话完整保留；原文没有时编造、改写、补充或跨商品移用。动态交易信息仍受全局规则约束。
- 以预计时长作验收门槛、暂停条件、删点理由或拆条触发器。
- 对未选择主题或未实际写出的成片运行/声称完成最终终检。
- 固定五部分交付缺项；新增模型、Agent、额外语义轮次或普通文本任务环境硬依赖。
- 声称运行了未执行的测试、读取了未读材料、审阅了未查看的音画或同步了无法读回核实的渠道。

## 开发质量评分（100 分）

此评分只评估 Skill 的开发质量，不用于比较日常成片或卖点价值。

| 指标 | 权重 |
|---|---:|
| AI-First 单 AI 决策边界及冻结规则 | 15 |
| 完整读取、商品范围和有效信息池 | 18 |
| 共情优先的开头候选比较 | 12 |
| 多视频检测、用户暂停点和检查点恢复 | 15 |
| 每条实际成片分别完整覆盖、原话与条件准确 | 20 |
| 适用合规促单原话保留及无源不补造 | 8 |
| 仅终检实际选中成片；时长只作约数 | 5 |
| 固定五部分输出及真实来源状态 | 7 |
| **总分** | **100** |

建议通过线：90 分，且全部一票否决项通过。评分不能抵消硬性失败。

## 关键场景验收

- 开头比较只覆盖开头及理解它所需的紧邻回应，优先级为有原话支持的顾客困扰/场景、直接回应、具体收益、可验证商品事实。不得把比较扩展为完整成片排名。
- 完整信息池建立后，才检查是否有实质不同、原话支持且每条均能自然承载同一信息池的多视频主题。用户未选时，先简要推荐主题和数量并暂停；保存检查点。用户选择后从检查点继续，不重复读取或检测。
- 每条用户选择并实际生成的成片都分别覆盖完整信息池及必要证据/条件；不得按成片拆分点位。
- 对适用且合规的原文促单逐字完整保留；不为结尾、时长或转化要求编造、改写或补充。来源中的动态价格、活动、库存等内容继续按冻结的全局规则判断。
- 预计时长仅可作约数参考，不进入任何通过/失败判断，不要求删点或拆条。
- 最终终检只检查实际选择并写出的成片。若停在用户选择等待点，没有最终成片，也没有最终终检。
- 交付保持固定五部分；所有未核实的音画、商品资料和平台结果如实标注。
