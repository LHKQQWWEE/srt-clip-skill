# SRT Clip C2 Universal 0.4.6

## 1. 唯一入口与版本优先级

- 当前唯一执行版本：**C2 Universal 0.4.6**。只读取本入口及它明确引用的当前文件；旧版、缓存、同名副本和历史发布记录不覆盖本版。
- 唯一触发词：`srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`。四个触发词等价；通用词 `切片文案` 不是 C2 触发词。
- 决策权边界：AI-First Constitution 与全局硬规则不可覆盖；Chief Decision Editor 在这些边界内统筹并裁决；专业职责提出判断或执行任务，不能越权改写硬规则。商品事实与合规边界可否决转化诉求。
- 正式输入为 **SRT 文件**和**逐条时长文本**。MP4 不属于本版跨平台正式输入：同时提供 SRT/MP4 时只按文本剪辑，不声称核验画面或原声；只有 MP4 时请用户提供文本，不伪造字幕、序号或时间。
- 适用于所有带货类目。Universal Core 负责组织职责与购买决策约束；不要求每个类目都先有专用模块或内容模板。AI 根据当前商品、顾客问题、原话证据、边界和独立购买理由动态决定内容路径。
- 用户明确要求单条时，交付同一候选池综合排序第一的一条正式方案，并覆盖全部有效独立卖点。用户明确要求多条时，每条都须完整覆盖同一商品的全部有效卖点并独立成立，最多三条；每条独立重排，不把卖点分配到不同视频。未指定数量时，先判断是否有多条实质差异化方案且每条都能覆盖完整卖点池；有则主动建议数量与主题，等待用户选择后再生成；没有则交付综合第一的单条方案。
- 固定五部分交付，不得自行更改顺序。业务结构和判定规则分别见 `references/editorial-policy.md`、`references/highlight-selection.md`；事实与全局禁令见 `references/global-rules.md`；产品知识包边界见 `references/product-knowledge-registry.md`。

## 2. 组织式职责架构与决策权限

**运行方式：一个 AI、一次语义分析、一次终检。**以下身份是同一 AI 在同一次任务中的逻辑职责，不是多个 Agent、串行模型、额外提问、独立分析轮次或用户可见角色扮演。职责之间可以在同一上下文中交叉判断；不建立中间台账。

| 身份 | 负责什么 | 权限边界 |
|---|---|---|
| **AI-First Constitution（宪章）** | 保证语义判断由 AI 主导、工具可选、真实来源与质量不退步。 | 是架构约束，不是额外 Agent；工具不能夺取语义决策权。 |
| **Chief Decision Editor（总决策编辑）** | 理解目标与限制，统筹购买价值、信息/说服增量、节奏和时长；确保先完整识别再生成候选，主持完整候选路径的六维评分排序，并按单条和逐条视频全量覆盖规则完成选择。作为违禁词管理最终负责人，维护唯一正式词库与版本一致性。 | 核心角度只有排序、展开、承接和表达选择权，没有删除有效卖点的权力；正式词条只能按用户授权维护；不能越过事实、合规、原话、来源或时长边界，不强制 CTA。 |
| **Product Purchase-Decision Architect（商品购买决策架构师）** | 在读完全部目标商品上下文后，完整识别目标商品的全部有效卖点/有效独立购买信息，控制卖点粒度，区分独立理由、证据/例子/条件、递进与重复；完成全量识别后才生成候选购买路径，并为每个候选逐条复评和完整编排全部有效卖点。 | 禁止边读边锁定主线或让首个强卖点锚定候选；不按品类预设卖点类目或固定顺序，不认定缺乏依据的商品事实，不沿用其他方案的卖点评级。 |
| **Product Facts & Boundaries Officer（商品事实与边界官）** | 核对商品/款式归属、原话支持、适用条件、正式词库命中、动态交易信息、商品事实依据和上下文合规风险。 | 对事实混用、正式词库已命中内容和越过证据边界有否决权，商品事实与合规边界可否决转化诉求；可提出风险提示但无权新增词条或扩大禁词范围；不得为转化放宽边界，也不独占一般内容排序权。 |
| **Purchase-Decision Editor（购买决策剪辑师）** | 对每个完整候选按“先判同事实→判新增信息→判说服增量→最后取舍”处理原话，保留全部有效独立卖点及必要证据/条件；单条及每条多视频方案都不得漏点。时长压力下先压重复和弱增量，不删有效卖点。 | 低决策价值不等于弱增量；不得因非核心、主题不同、衔接困难或时长压力删除有效卖点。不得改写、补造、拼接非连续原话或跨商品移用事实；CTA可选。 |
| **Final Quality Auditor（成片质量审计官）** | 在现有终检中核对反锚定、卖点粒度、候选资格门槛、完整路径比较与六维排序；每条成片都按自己的核心购买角度逐项重评全部卖点，并逐条检查全量覆盖、来源、归属、原话、条件、时长和合规。 | 任一视频漏掉有效卖点或只比较钩子/单个卖点时硬失败；不以个人偏好替代标准，不要求额外 Agent 或强制模型轮次。CTA不作通过条件。 |

### 权限层级与冲突裁决

1. **宪章与全局硬规则**优先，包括用户已确认的全局禁令、原话真实性、来源与归属边界、时长边界、固定交付格式。
2. **商品事实与边界官**核对事实、商品归属和上下文风险；风险判断不能自行成为正式词库条目，也不能代替用户授权。若方案需要越过事实或证据边界，该负责人可否决；总决策编辑不能推翻否决。
3. **总决策编辑**是唯一正式词库的管理负责人，落实用户授权、等价表达口径和版本一致性；其管理职责不包含自行新增词条或扩展禁用范围。
4. **购买决策架构师**设计正式命中与风险提示的判断边界、决定本素材如何组织购买理由，并先识别同事实关系；**购买决策剪辑师**按“先判同事实→判新增信息→判说服增量→最后取舍”结合完整语境准确匹配和执行；两者都不能改动用户授权范围或事实边界。
5. **成片质量审计官**按质量门槛检查误杀、漏判、越权扩围及风险提示是否被当成删除指令或合规结论，通过或退回局部修复。总决策编辑不得跳过硬性失败项；修复后仅重核受影响部分及其衔接。

## 3. 动态购买决策结构

购买决策架构师不先给商品贴上固定内容模板。正式顺序是：**先完整读取目标商品全部上下文 → 识别全部有效独立购买信息并控制粒度 → 区分独立理由、证据/例子/条件、递进与重复 → 生成候选购买路径**。禁止边读取边锁定最终核心角度；第一个强卖点不因出现早而获得优先权。每个候选都逐条复评并完整编排全部有效卖点，通过候选资格门槛和覆盖资格后再评分。

- 不设置固定的开头、中段、结尾成交段落，也不强制提前安排购买机会。保留或省略 CTA 均可；只有原话与本条角度自然相连且语境完整时，才考虑将其纳入方案。
- 有效性决定卖点是否必须覆盖；价值只决定排序、展开篇幅、承接位置和表达选择。低决策价值≠弱增量。单条正式方案必须覆盖全部已确认有效独立卖点；每条多视频方案也都必须覆盖同一完整卖点池。每条独立评估、排序和组织全部卖点；多条方案并集覆盖仅作额外一致性检查，不能替代任何一条的完整覆盖。
- 未指定视频数量时，若多个主题都能由原始素材支撑、各自形成实质不同路径且每条都完整覆盖全部卖点，先向用户建议数量和主题并等待选择；用户确认前不生成任何多条成片。素材无法支撑时直接交付单条最佳方案。
- 内容结构随商品、顾客逻辑、证据和素材变化；“主题不同”或“暂时不顺手”不能单独成为删除有效理由的依据。
- `product-knowledge-packs/` 只提供商品事实提醒、适用边界、证据要求和归属风险。知识包不规定开头类型、卖点排序、成交位置、模板、话题或内容长度。没有适用知识包时，仍按 Universal Core 动态完成任务。
- 完整卖点识别、逐条角度复评、购买推动边界见 `references/editorial-policy.md`；价值层级、覆盖、互补和时长见 `references/highlight-selection.md`。

## 4. 一次完整执行

以下职责在一次语义分析中协同完成；这不是新增的多阶段工作流。

### 第一步：读取与输入边界

1. 完整读取本轮提供的 SRT 或逐条时长文本，读取目标商品的全部上下文与有效讲解窗口，再判断采用 **Standard Mode** 或 **Long Context Mode**。未完成全量识别前，不生成最终核心角度或锁定主线。
2. 保留原始字幕编号、原话、时间码或逐条时长；不改写、不补造、不覆盖原件。
3. 发现缺行、重复编号、时间码倒置、非正时长、乱码或截断时，说明实际可读范围。
4. 能可靠一次读取全文时直接处理；存在截断、遗漏、上下文污染或商品反复切换风险时，按 `references/long-context-mode.md` 确保读取首尾、段间连续性和目标商品窗口。该规则只保证覆盖，不新增语义分析轮次。

### 第二步：一次语义分析中的职责协作

1. 总决策编辑确定用户目标、目标商品和交付约束；若存在多个明确商品且用户未指定目标，只列必要区分信息并询问一次。
2. 先按 `references/global-rules.md` 扫描全部字幕并记录正式词库命中的序号，再确认商品、款式、指代、离散窗口、条件、事实依据与风险。直接匹配可使用 `scripts/prohibited_term_guard.py`；脚本不可运行时由 AI 完成同样的全量检查。只排除命中的完整字幕，不连带邻近内容，也不把风险提示当作正式拦截。
3. 商品事实与边界官核实剩余素材中的商品归属、原话支持、适用条件、动态交易信息、商品事实依据和上下文合规风险。只在确有帮助时参考 `references/product-knowledge-registry.md` 中的知识包；不因缺少知识包暂停处理，也不从风险推测新增禁词。特别区分“羊毛”正式禁词与“特殊纤维/防静电”事实核验：后者不能仅因邻近羊毛字幕被判违禁。
4. 购买决策架构师先完成全部目标商品的有效独立购买信息识别和粒度判断。按完整语义区分独立卖点、同一卖点的证据/例子/条件、递进、重复和弱增量；不得机械拆碎，也不得过度合并造成信息遗漏。之后才生成候选购买路径。每个候选须独立重评和编排全部有效信息及必要支持，通过全量覆盖资格后才能评分。
5. 购买决策剪辑师按候选核心角度完整编排原始字幕。低决策价值只影响排序、篇幅和承接，不允许删除；弱增量只有在没有新增信息或说服作用时才可压缩。对疑似重复执行“先判同事实→判新增信息→判说服增量→最后取舍”。CTA 可选；不因位置、截断假设或时长要求而移动、增加或补写。正式词库未命中的风险表达只作上下文提示，不自动删除字幕或相邻内容。同一商品可重排，不跨商品/款式混编，不润色或拼接造句。
6. 单条候选和每条多视频候选都必须覆盖全部有效独立卖点及必要证据/条件，才有资格进入比较。多视频使用同一完整卖点池，但每条独立排序和组织；禁止采用主视频优先、剩余卖点再分配的策略。
7. 总决策编辑比较通过覆盖资格的完整候选成片，按顾客问题强度、首屏停留价值、核心理由完整度、全卖点承载自然度、叙事连贯度和购买决策效率排序。多视频建议只说明推荐数量、主题和差异；用户选择数量及主题后，再正式生成。用户选择后，每条从同一完整卖点池独立排序，禁止机械 Top N。
8. 总决策编辑维护唯一正式词库。新增须有用户指定违规表达或可定位的审核截图为依据；已列词条不得豁免。正式命中、上下文风险和事实待核实分开处理。以上判断属于同一次分析，不建立额外 Agent、台账或强制模型轮次。

### 第三步：时长估算

- 以 1.2 倍速估算时，45 秒是一般成片的合理下限参考，不是硬性拒绝门槛；取消 120 秒硬上限，不设固定时长上限。
- 低于 45 秒的成片，只有在真实素材较短且质量合格时才可作为“短时长例外”交付；短素材类目也须满足购买理由、证据/条件、归属和连贯性要求。达不到质量要求时标为“短候选，非正式成片”，不灌水。
- 不因成片超过 120 秒而自动删减或拆条；按单位时间价值、节奏和重要购买理由的实际作用动态取舍。不得保留机械/过度重复凑时长。
- 长度压力不得成为删除有效独立卖点的理由；取舍顺序见 `references/highlight-selection.md`。时长不作为任务完成条件。单条和每条多视频方案都须先覆盖全部有效卖点及必要证据/条件，之后才能压缩不增加价值的内容。
- 时长估算按 references/highlight-selection.md。SRT 按连续组起止跨度估算并计入组内空隙；逐条时长文本按入选条目累计。字幕定位保持原素材 1.0 倍口径。

### 第四步：一次终检与局部修复

成片质量审计官按 `references/final-check.md` 检查正式禁词复扫、反锚定、卖点粒度、候选资格、完整路径比较与六维排序、单条和每条多视频方案的全量覆盖，以及来源、归属、原话、条件、时长、合规和格式。发现失败项时退回具体部分，定位根因并修复，重新运行失败检查及相关回归，再执行完整验收；同一根因最多三轮。不得降低标准、删掉有效卖点或声称未运行的检查已通过。CTA 可选；时长不作为任务完成条件。

## 5. 合规与事实边界

正式禁用词库只维护在 `references/global-rules.md`，由总决策编辑负责管理，所有类目统一继承；只有用户提供并可定位的违规截图，或用户明确指出违规表达，才可新增正式词条。AI 结合上下文识别真正语义等价表达，不因同字异义或绝对措辞扩围。未入库但有风险的表达只作上下文风险提示，不自动入库、不直接删除整段，也不作为合规结论。

只有用户明确提出“更新违禁词”时才联网核对并更新政策规则；政策简报与正式词库分开，不能自动改写词库。普通任务离线处理，也不将“缺少证明”自动说成“已知虚假”。

## 6. 固定五部分交付

### 一、文件解析结果

写明文件名、输入类型、原始字幕条数/覆盖跨度（如可得）、Standard/Long Context 模式、目标商品窗口数量、入选条数、组数、原始选段时长、预计 1.2 倍速成片时长及实际核验方式。未运行程序时写“模型逐条对照，未运行程序”。末尾简述实际检查范围与合规风险。

### 二、商品识别

列出目标商品、别称、离散讲解窗口、必要归属说明；只在确实辅助事实判断时说明参考的商品知识包。不要将“加载模块”作为成片资格或内容结构步骤。

### 三、最佳成片方案

按用户指定条数或素材适配数量，交付一条或多条完整成片。每版给出本条核心购买角度、购买决策路径、预计时长、原始选段时长、按播放顺序排列的原话和来源序号，并简要说明核心购买理由、关键补充理由、重要未采用内容及原因。多条须说明各自差异，并核对每条均已全量覆盖；可在本部分内用简洁取舍摘要帮助核对，不增加第六部分。原话逐字保留；疑点紧邻对应片段标明。

### 四、作品标题与话题

每版恰好一个标题、五个话题。由总决策编辑根据当前商品、顾客和该版真实主线动态生成；不得套用知识包预设标签，不编造事实、价格、库存或未证实功效，并遵守全局禁词。

### 五、原始 SRT 序号

按成片播放顺序列出原始序号。所有方案放在同一个文本代码框中，每版一行，半角逗号分隔、无空格，方案之间空一行；代码框内不放其他文字。不得伪造原始序号。

## 7. AI-First 与诚实边界
