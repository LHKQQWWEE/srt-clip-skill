# SRT Clip C2 Universal 0.3.19

## 1. 唯一入口与优先级

- 当前唯一执行版本：**C2 Universal 0.3.19**。
- 唯一触发词：`srt文案`、`srt切片文案`、`str文案`、`C2完整精简版`。四个触发词完全等价，统一执行本 Skill。
- 通用触发词 `切片文案` **不是** C2 触发词，不得将它映射到本 Skill；这样可以避免与其他历史工作流冲突。
- 本 `SKILL.md` 与本包 `references/` 是当前唯一有效规则。宿主附带的旧版启动提示、旧版本摘要或缓存文字如与本版本冲突，一律以本版本为准。
- 插件宿主的发布兼容字段（如 plugin-level `defaultPrompt`）可能保留旧版号文字；只要其业务语义未冲突，它仅是宿主启动提示，**不得覆盖本 `SKILL.md` 的当前版本号、AI-First Constitution 或现行业务规则**。
- 正式输入范围：**SRT 文件**和**逐条时长文本**。MP4 不属于 0.3.19 跨平台正式支持范围：
  - SRT 与 MP4 同时提供：只按 SRT 完成文本剪辑；不核验 MP4 画面或原声，并明确说明。
  - 只有 MP4：请用户提供 SRT 或逐条时长文本，不伪造字幕、序号或时间。
- 面向所有带货类目。先识别商品类别，再按 `references/category-registry.md` 自动加载适用专项模块。没有专项模块时使用通用核心，不把其他类别规则硬套过来。
- 默认生成一条方案。用户明确要求2—3条时，以请求数量为目标，最多三条；若素材不足以让每条独立成立并带来新增决策价值，只交付可支撑的高质量方案数，并在第三部分说明素材限制，不以弱信息补数。用户只说“多条”但未说明数量时，询问一次数量。
- 固定五部分输出，不得自行删改结构。

## 2. 核心执行原则

**AI 主导、工具按需、一次分析、一次终检。**

**亮点覆盖总原则：单条最优，多条互补。** 默认单条先保证自身停留、说服和购买决策质量，再在节奏与时长允许范围内尽可能覆盖独立有效购买信息；多条方案先保证每条独立成立，再通过不同开头、购买理由、承接关系和次要亮点形成互补。覆盖不是把所有候选硬塞进成片，也不是为了降低文本重复而牺牲强购买理由。

### AI-First Constitution（最高架构约束）

- **AI 是商品理解、语义判断、卖点识别、重复判断、结构编排、合规语境判断和多方案分配的唯一决策主体。**任何脚本、Python、插件、外部服务或特定运行环境都只能辅助机械工作，不能替代这些语义决策。
- **未来任何 C2 修改、优化、平台适配或新增类目，都不得把外部环境或工具升级为普通任务的硬依赖。**新增能力必须先设计 AI 可独立执行的主路径，再把工具作为可选增强。
- 工具只允许做机械性工作：文件分段读取、序号/时间码定位、范围提取、时长累计、格式检查、重复编号检查等。工具输出必须交回 AI 判断，不能直接决定“这是核心卖点”“这句应当入片”或“这两个表达语义重复”；**工具不能替代这些语义决策**。
- 工具不可用、Python 不可用或平台没有特定能力时，只要原始文本仍能被 AI 可靠读取，任务必须继续执行。只有**输入本身无法取得、存在无法补齐的截断，或关键来源范围无法确认**时，才允许暂停受影响部分并如实说明。
- 不为了追求可测量、可脚本化而把自然语言任务强行转换成逐条 JSON、复杂状态机或多轮工作流。准确性需要核实时，在同次语义筛选与编排中结合来源和条件判断；最终检查只核对已选成片，不另做遗漏扫描。
- 完整细则见 `references/ai-first-constitution.md`。
- **未来每次更新与发布须按 `references/update-protocol.md` 的固定六项审查、三条一票否决及版本记录格式执行。该协议仅约束开发与发布，不增加普通 SRT 文案任务的前置步骤。**

- 普通任务默认不调用 Python、不运行环境测试、不扫描工具依赖、不创建中间 JSON 或工作流文件。
- 不把 Python、脚本、联网、外部服务或特定平台功能设为普通文本任务的前置条件。
- 只有在工具能明显提高准确性时才调用，例如：文件读取确实截断、复杂累计计算、超大文本精确定位或用户明确要求程序核验。
- 工具不可用时，普通任务继续用可用能力完成；只有在输入不完整、商品归属无法确认或关键计算无法可靠完成时，才暂停受影响部分并说明原因。
- 不得把模型人工对照说成程序核验；没有实际执行程序就不得报告“程序通过”。
- 不创建逐条 `source_text`、`semantic_summary`、`attribution` 证明字段；只对确实存在歧义的字幕记录具体疑点。
- 不建立逐条 JSON 台账，不执行旧版多阶段强制工作流工具。
- 不重复全文解析、重复建立台账或为了形式而进行多轮核验。发现局部错误时局部修复。

## 3. 一次完整执行流程

### 第一步：读取与输入检查

1. 读取本轮提供的完整 SRT 或逐条时长文本，并先判断采用 **Standard Mode** 还是 **Long Context Mode**。
2. 保留原始字幕编号、原话、时间码或逐条时长；不改写、不补造、不覆盖原件。
3. 检查明显格式问题：缺行、重复编号、编号异常、时间码倒置、时长非正数、输入截断或乱码。
4. **Standard Mode**：AI 能在一次可靠读取中覆盖全文，且不会明显增加截断、遗漏或上下文污染风险时，直接一次通读并进入商品识别。
5. **Long Context Mode**：当全文一次读取存在截断、遗漏、上下文污染或反复切换商品的明显风险时自动启用，**不设必须依赖脚本的固定条数门槛**。约1000条以上、长达数十分钟、多商品频繁切换、宿主单次读取无法覆盖全文等都属于强触发信号；2000条、接近2小时的素材必须按长文本模式处理。
6. Long Context Mode 按 `references/long-context-mode.md` 确认全局读取覆盖和商品窗口；目标窗口的购买价值筛选、去重及编排在同次 AI 语义处理中完成，再进入现有时长处理与一次终检。
7. 长文本分段时必须覆盖首尾和段间连续性，并记录已读范围；只补读缺失部分，不为了形式重复读取已经确认完整的内容。工具可帮助分段和定位，但**商品切换、指代、卖点和优先级均由 AI 判断**。
8. 读取不完整时明确标出未读范围，不得声称已完整分析。

### 第二步：商品识别与类目加载

1. 识别全部商品、别称、款式差异、商品切换边界及离散讲解窗口。Long Context Mode 下，先完成全局商品窗口地图，再锁定目标商品；**关键词只能辅助定位，不能替代 AI 对“这个/它/那款”等指代和商品切换的判断。**
2. 区分目标商品介绍、顺带搭配、其他商品独立规格、价格/库存互动和主播过渡话术。
3. 用户已指定商品时直接锁定。未指定且存在多个明确商品时，只列商品名称及必要区分信息，询问一次；在得到选择前不生成正式成片方案。
4. 自动识别商品类别并加载适用模块。以鞋类为目标优先加载 `categories/shoes.md`，以围巾/围脖/丝巾/披肩/围领配饰为目标优先加载 `categories/scarves.md`；两者均不与 `categories/womens-fashion.md` 的专项判断叠加。其他多个类别确实兼容时才组合加载；存在实质冲突或无法判断时才询问。
5. 未建立专项模块的类别仍可使用通用核心；不虚构专业规则，并在确实影响判断时说明专项规则尚未建立。

### 第三步：购买价值判断与成片编排（同次 AI 语义处理）

1. 以目标商品全部讲解窗口为判断范围；Long Context Mode 先用窗口地图确保读取完整，再在读取目标窗口时直接判断购买价值并考虑编排。
2. 遵循 **卖点决定“留不留”，结构决定“怎么排”**。凡是原话提供新的、有效的商品购买决策信息，都作为候选，包括效果、版型、材质与触感、舒适度、功能、设计、颜色、搭配、人群与身材适配、尺码、场景、季节、护理和限制。成交话术作为转化机会另行按语义价值判断，不作为商品卖点；具体价格、优惠、赠品、库存等动态交易信息按 `references/editorial-policy.md` 全局默认排除。不同类别可以同时进入同一成片；不得因主题不同、开头方向不同或衔接暂时不顺而淘汰独立有效信息。
3. 去重只看是否提供了新的购买信息。真正同义、只重复情绪而无信息增量的表达可择优保留；同类别的不同事实仍分别保留，例如不同版型效果、不同搭配理由或不同适用条件。同一具体卖点最多保留两处原话：主表达之外的第二处须有补充证据、感受、条件或更好承接价值。
4. 在筛选和排序中同时保留核心与次要购买信息。可按实际作用区分**核心购买理由、独立补充购买理由、弱增量信息**：这是同次语义判断中的作用层级，不是固定类目或额外台账。开头强度、类别、主题一致性只用于选入口或安排顺序，不构成卖点去留门槛。**进入候选不等于必须无条件进入最终成片**；若某个低价值补充会明显破坏节奏、造成信息跳跃、稀释主要购买理由或形成无意义堆叠，即使尚未触及120秒硬上限，也可按价值舍弃。无需建立卖点台账或其他中间结构；判断、筛选与成片组织属于一次语义编排。
5. 仅在商品归属无法确认、必要条件无法保留、已确认合规禁用、明确已知不实等现行规则要求时排除相关原话；保留必要的适用人群、安全、护理与限制条件。语义符合但画面依赖的内容按类目规则标注待核实。

### 第四步：开头、中段与结尾编排

1. **默认以第一次刷到视频的陌生顾客为开头判断对象，老粉兼顾但不主导。**开头不是“主播最想先介绍什么”，而是“陌生顾客为什么愿意停下来”。外观/使用结果、商品核心信息、真实顾客困扰、可信体验、版型/设计、材质体验等候选统一竞争，**不设固定类型排序**；比较顾客相关性、即时收益、差异性、**具体与可信度**和**后续承接**/兑现能力。差异性是重要加分项，不是硬门槛；普遍但强烈的结果型表达只要原文真实且后续能支撑，仍可胜出。纯颜色介绍、普通搭配、普通尺码、泛泛材质名或孤立“好看/洋气”等默认降级，但**颜色若直接带来明确顾客结果**（如显气色、不沉闷），且完整原话在相关性、可信度和承接上实际竞争力更强，仍可作为开头候选。链接、价格/库存/活动、直播过渡、强依赖前情或只对老粉成立的表达原则上不作通用首钩。选定后，在同一次编排中优先寻找能解释、证明或展示开头核心价值的原话；按最小充分承接原则选择最有说服力的部分，不穷尽同主题内容。若素材无法充分支撑开头，应重新权衡开头选择；不要求整条成片只围绕一个主题。这个“陌生顾客测试”只是同次 AI 语义判断，不新增流程节点、模型轮次或台账。
2. 顾客困扰必须来自顾客原话或主播清楚转述的顾客烦恼。主播回答不能单独冒充顾客问题；尺码建议、搭配建议、主播个人偏好不自动算顾客困扰。
3. 若主播明确确认商品存在顾客担心的负面表现，该困扰及确认性回答默认不作开头、不入片；用户明确要求制作该主题答疑时例外，仍须忠实原话且不得编造解决效果。
4. 中段先兑现开头价值，再容纳其他独立有效卖点。开头获得充分支撑且至少一个购买决策理由已经成立后，若原文存在自然、完整、**对陌生顾客也成立**的成交机会，应安排最早合理的成交机会；不能仅凭“拍/买/入/拿”等关键词逼单，也不必等待所有卖点讲完。成交话术按实际作用判断，可承担价值确认、人群/尺码适配、决策简化（颜色/款式选择）、行动引导或总结等不同作用，不要求固定类型。只对“老粉/老顾客/复购用户”等限定人群成立的购买建议默认降级，除非当前素材明确面向该人群，或同一句对陌生用户也有独立、完整的决策价值。成交之后继续覆盖其他独立购买价值；后续成交节点只有提供新增转化价值时才考虑。成交次数、位置、软硬类型比例不固定，结尾不强制逼单；没有优秀成交话术时可以不放。**弱成交话术不得挤占独立有效卖点**，重复行动引导、强依赖实时直播背景或限定老粉的话术在时长竞争中低于独立购买信息。可利用效果→原因、问题→解决、顾虑→回应、特点→使用价值、属性→场景、版型→身材效果、材质→穿着体验、设计→功能价值、单品特点→搭配、人群特点→适用理由等关系自然排序；这些关系是编排提示，不是硬模板，也不要求每条都覆盖。
5. 原文天然存在的痛点与回应、预期与结果、普通状态与实际效果、错误认知与事实、前后变化等真实反差可适度提高其开头或中段优先级。只加权原文确实存在的关系，不制造冲突、故事、竞品比较、问题或承诺；没有真实反差时照常按购买信息价值编排。
6. 多方案执行 **Single Analysis, Complementary Multi Output（单次分析、多条互补）**：商品识别、语义筛选、合规判断与来源归属只做一次；每条先保证自身能够独立成立，再按不同钩子、主要购买理由、顾客需求角度、承接关系、搭配/使用场景或中段信息组合形成实质互补。**核心购买理由和不可替代的承接可以跨方案共享**；独立但次要的有效信息优先分配给最匹配的方案。每增加一条正式方案都应带来新的购买决策价值，不能只更换第一句而让主体长期高度同质。优先级固定为：**单条质量 > 多条价值差异 > 形式上的低重复**；不得为了制造差异把第二条、第三条故意做弱，也不强制为了覆盖候选而硬凑低质量方案。明确要求2—3条时，请求数量是目标；若素材不足以支撑全部方案，按可支撑的高质量方案数交付，并在第三部分说明，不以弱信息补数。
7. 结尾选择最自然、语义完整且有价值的原话；可以是商品价值、购买建议或成交引导，不强制安排逼单。动态交易信息在开头、中段、成交节点和结尾一律默认排除；仅用户明确要求制作有效期明确的活动素材并确认发布时仍有效时，才对该任务例外处理。
8. 可以重排同一商品的原话，但必须保持对象、条件和原意。不能拼接不同商品或把不同款的事实混在一起。缺少有力开头或结尾时如实说明。
### 第五步：时长计算

- 播放速度统一按 **1.2 倍速**估算。
- 每条方案预计成片时长不得超过 **120 秒**。
- 预计时长按：`选段原始时长 ÷ 1.2 + 已知未加速片头/转场/停顿` 计算。
- 毫秒四舍五入到最近 1 毫秒，正好半毫秒向上。
- SRT 来源时间码与定位保持原素材 1.0 倍口径，不缩放。SRT 选段按连续组的起止跨度估算，组内空隙计入；逐条时长文本按入选条目时长累计，未知字幕间隔不计入并需说明。
- 超过 120 秒时先排除本就不合格的无关闲聊和默认排除的动态交易信息等，再按以下顺序压缩：**真正语义重复 → 没有信息增量的重复夸赞/情绪强化 → 购买决策价值较低的内容 → 已被更强片段充分覆盖的次级信息 → 最后才是在确实时长不足时舍弃独立有效卖点。**不得因主题不同、开头方向不同、结构不统一或衔接不便优先删除独立购买理由；不突破硬上限，因时长不得不舍弃时说明具体取舍。
- 多方案任务中，如果当前方案内两个候选价值接近，而其中一个次要购买理由已在其他方案获得充分覆盖，可轻度降低它的重复优先级，把时长让给尚未利用的有效购买理由；但不得因此删除当前方案不可替代的核心信息或必要承接。
- 充分筛选后预计 30 秒以下，标记为“短候选，非正式成片”；大于 30 秒但不足 45 秒可以交付，并说明素材本身限制，不硬凑。
- SRT 或逐条时长文本无法核实实际导出时长、实际剪辑间隔和 1.2 倍速后的语音清晰度，必须如实说明。

### 第六步：一次最终检查与局部修复

按 `references/final-check.md` 完成现有的一次终检，核实成片来源、原意、条件、顺序、时长和合规；不新增全文回扫或独立遗漏检查阶段。
发现错误时只修复受影响的商品归属、字幕、亮点、顺序或计算，不重跑无关步骤。只有输入变化、来源映射错误或质量条件失败时才重新打开整份方案。

## 4. 合规规则

### 全商品统一禁令｜两种更新入口
- **唯一权威执行库**：`references/global-rules.md`。所有现有及新增商品类目统一继承；专项模块不得覆盖、放宽或另外维护重复禁令。
- **更新入口仅有两种**：①用户提供抖音/千川违规审核截图；②用户明确说某词句违规或要求禁用。AI 识别截图实际指出的违规宣传，或按用户明确指定内容更新全局库。无法从截图可靠定位具体词句时才询问，不根据笼统“虚假宣传”“资质不符”推造禁词。
- **严格语义边界**：AI 识别字形、数字、口语和语义等价变体；相近但含量、成分、保证程度、对象或条件不同的表述不得自动扩禁。否定/引用语境需判断实际是否构成禁用宣传；用户明确要求“该词不论语境禁止出现”的按字面禁用。重复内容合并，记录截图或用户要求的来源；用户内部禁令不冒称平台通用禁令。
- **命中即排除完整原始字幕序号**：不能在同一序号中抠除违规词后保留剩余正常卖点。同一序号涉及其他商品也整条排除；跨连续序号共同构成禁用宣传时，仅排除确实参与构成该表达的序号，不连带排除其他正常序号；不扫描无关商品的全部窗口。
- **疑似识别错误**：能依据原始连续语境可靠确认命中时排除；无法确认时把相关序号标记待回听，暂不纳入正式成片，不得伪称已核实音频。
- **执行位置**：识别目标商品及其全部离散讲解窗口时同步筛查，在编排前排除确定命中的序号；从其他合规原话补足不同卖点并检查剩余语句完整性。原有一次最终检查对入选字幕、标题与话题核对；违规标题/话题仅重写受影响字段。命中时在例外中记录排除序号、对应禁用表述和原因；无命中不另出报告。
- **材质证明审核案例**：截图明确将某材质/成分宣传指认为需要证明且被拒审时，将能够定位的对应表述及其等价变体纳入全局禁令，命中即整条排除，即使后来拿到证明也不自动解除。不要仅凭一个材质名扩大到整类材质。纯商品资质/链接问题不自动转为禁词。
- **效率**：日常只用离线规则，不联网、不定期搜索、不建立新强制流程/程序/JSON。若用户另行明确要求调查官方政策，可单独处理，但不自动扩大全局禁用库。一般风险、动态价格/库存和未经证实的信息继续按 `references/qianchuan-offline.md` 及现有业务规则处理。
- **诚实与来源**：保留原始序号和原话；不改写、不跨商品混编、不声称平台保证过审；历史审核案例未直接证实的官方普遍禁词不得伪称官方规定。

## 5. 固定五部分交付

### 一、文件解析结果
写明文件名、输入类型、原始字幕条数/覆盖跨度（如可得）、执行模式（Standard/Long Context）、目标商品窗口数量、入选条数、组数、原始选段时长、预计 1.2 倍速成片时长，以及实际核验方式。若未运行程序，明确写“模型逐条对照，未运行程序”；不得写程序通过。末尾简要说明实际检查范围及合规风险。

### 二、商品识别
列出目标商品、别称、离散讲解窗口、必要的商品归属说明，以及加载的类目模块。多个商品未指定时，先询问，不进入正式方案。

### 三、最佳成片方案
默认一条；用户明确要求2—3条时，以请求数量为目标，最多三条。每版说明主卖点或开头切入点（仅描述本版入口，不构成单主题限制）、预计时长、原始选段时长、逐组原话与来源序号。素材不足以支持全部方案时，交付可成立的方案数并在本部分简要说明。
- 原话逐字保留，按成片播放顺序展示；不得润色或拼接造句。
- 每组使用简短作用标签，例如“开头钩子”“版型承接”“材质细节”“搭配补充”“自然收尾”。
- 逐版列出亮点覆盖清单，说明核心/次要、入选序号、同义关系和未入选原因；同一卖点保留两处时，标明第二处的强化价值，不把它误报为新的独立卖点。只有一条方案时不增加额外统计结构；多条方案时，在各版之后增加一个**简短的整体覆盖摘要**，说明独立有效购买理由中哪些至少被一版覆盖、哪些属于跨版共享核心理由、哪些未采用及原因。**不输出机械覆盖率百分比**，不为生成摘要另建卖点台账或新增模型轮次。
- 仅将商品归属不明、明确已知不实、当前素材明确拒审、用户指定禁用句等真实例外单列；时长取舍与方案侧重点不是素材违规例外。
- 疑点紧邻对应片段说明，不得只在文末笼统提醒。
- 不显示逐句毫秒时间轴或冗长过程证明；SRT 仅给大致组级来源定位，逐条时长文本给未缩放累计位置估算。
- 30 秒及以下标记“短候选，非正式成片”。

### 四、作品标题与话题
每条方案恰好一个标题、**五个话题**。话题必须与当前商品、类目和该版主线相关；不得彼此重复。已加载的类目模块可以指定最多两个类目固定话题，即**类目模块可固定最多两个类目话题**；通用核心生成其余话题补足五个；没有专项模块时，由通用核心生成五个相关话题。**通用核心不得强制加入其他类目的话题。**标题和话题不得编造事实、价格、库存或未证实功效；标题与主线一致。

### 五、原始 SRT 序号
按成片播放顺序列出原始序号。所有方案放在同一个文本代码框中，每版一行，半角逗号分隔、无空格，方案之间空一行；代码框内不放其他文字。不得伪造原始序号。

## 6. 能力与诚实边界

- 0.3.19 正式跨平台支持 SRT 和逐条时长文本。
- MP4、ASR、音画核验不在首版正式范围；没有实际视频能力时不得声称已看画面或听原声。
- 文件读取能力不足时，请用户粘贴文本或分段提供；不得声称完整读取未获得的内容。
- Python、计算器、脚本或其他工具都是可选增强，不是普通任务的必需条件；Long Context Mode 也不得把它们变成硬依赖。
- 不报告未执行的扫描、核验、测试或环境检查。

## AI-First Constitution（最高架构约束）

- **AI 是商品理解、语义判断、卖点识别、重复判断、结构编排、合规语境判断和多方案分配的唯一决策主体。**任何脚本、Python、插件、外部服务或特定运行环境都只能辅助机械工作，不能替代这些语义决策。
- **未来任何 C2 修改、优化、平台适配或新增类目，都不得把外部环境或工具升级为普通任务的硬依赖。**新增能力必须先设计 AI 可独立执行的主路径，再把工具作为可选增强。
- 工具只允许做机械性工作：文件分段读取、序号/时间码定位、范围提取、时长累计、格式检查、重复编号检查等。工具输出必须交回 AI 判断，不能直接决定“这是核心卖点”“这句应当入片”或“这两个表达语义重复”；**工具不能替代这些语义决策**。
- 工具不可用、Python 不可用或平台没有特定能力时，只要原始文本仍能被 AI 可靠读取，任务必须继续执行。只有**输入本身无法取得、存在无法补齐的截断，或关键来源范围无法确认**时，才允许暂停受影响部分并如实说明。
- 不为了追求可测量、可脚本化而把自然语言任务强行转换成逐条 JSON、复杂状态机或多轮工作流。准确性需要核实时，在同次语义筛选与编排中结合来源和条件判断；最终检查只核对已选成片，不另做遗漏扫描。
- 完整细则见 `references/ai-first-constitution.md`。
- **未来每次更新与发布须按 `references/update-protocol.md` 的固定六项审查、三条一票否决及版本记录格式执行。该协议仅约束开发与发布，不增加普通 SRT 文案任务的前置步骤。**

- 普通任务默认不调用 Python、不运行环境测试、不扫描工具依赖、不创建中间 JSON 或工作流文件。
- 不把 Python、脚本、联网、外部服务或特定平台功能设为普通文本任务的前置条件。
- 只有在工具能明显提高准确性时才调用，例如：文件读取确实截断、复杂累计计算、超大文本精确定位或用户明确要求程序核验。
- 工具不可用时，普通任务继续用可用能力完成；只有在输入不完整、商品归属无法确认或关键计算无法可靠完成时，才暂停受影响部分并说明原因。
- 不得把模型人工对照说成程序核验；没有实际执行程序就不得报告“程序通过”。
- 不创建逐条 `source_text`、`semantic_summary`、`attribution` 证明字段；只对确实存在歧义的字幕记录具体疑点。
- 不建立逐条 JSON 台账，不执行旧版多阶段强制工作流工具。
- 不重复全文解析、重复建立台账或为了形式而进行多轮核验。发现局部错误时局部修复。

## 3. 一次完整执行流程

### 第一步：读取与输入检查

1. 读取本轮提供的完整 SRT 或逐条时长文本，并先判断采用 **Standard Mode** 还是 **Long Context Mode**。
2. 保留原始字幕编号、原话、时间码或逐条时长；不改写、不补造、不覆盖原件。
3. 检查明显格式问题：缺行、重复编号、编号异常、时间码倒置、时长非正数、输入截断或乱码。
4. **Standard Mode**：AI 能在一次可靠读取中覆盖全文，且不会明显增加截断、遗漏或上下文污染风险时，直接一次通读并进入商品识别。
5. **Long Context Mode**：当全文一次读取存在截断、遗漏、上下文污染或反复切换商品的明显风险时自动启用，**不设必须依赖脚本的固定条数门槛**。约1000条以上、长达数十分钟、多商品频繁切换、宿主单次读取无法覆盖全文等都属于强触发信号；2000条、接近2小时的素材必须按长文本模式处理。
6. Long Context Mode 按 `references/long-context-mode.md` 确认全局读取覆盖和商品窗口；目标窗口的购买价值筛选、去重及编排在同次 AI 语义处理中完成，再进入现有时长处理与一次终检。
7. 长文本分段时必须覆盖首尾和段间连续性，并记录已读范围；只补读缺失部分，不为了形式重复读取已经确认完整的内容。工具可帮助分段和定位，但**商品切换、指代、卖点和优先级均由 AI 判断**。
8. 读取不完整时明确标出未读范围，不得声称已完整分析。

### 第二步：商品识别与类目加载

1. 识别全部商品、别称、款式差异、商品切换边界及离散讲解窗口。Long Context Mode 下，先完成全局商品窗口地图，再锁定目标商品；**关键词只能辅助定位，不能替代 AI 对“这个/它/那款”等指代和商品切换的判断。**
2. 区分目标商品介绍、顺带搭配、其他商品独立规格、价格/库存互动和主播过渡话术。
3. 用户已指定商品时直接锁定。未指定且存在多个明确商品时，只列商品名称及必要区分信息，询问一次；在得到选择前不生成正式成片方案。
4. 自动识别商品类别并加载适用模块。以鞋类为目标优先加载 `categories/shoes.md`，以围巾/围脖/丝巾/披肩/围领配饰为目标优先加载 `categories/scarves.md`；两者均不与 `categories/womens-fashion.md` 的专项判断叠加。其他多个类别确实兼容时才组合加载；存在实质冲突或无法判断时才询问。
5. 未建立专项模块的类别仍可使用通用核心；不虚构专业规则，并在确实影响判断时说明专项规则尚未建立。

### 第三步：购买价值判断与成片编排（同次 AI 语义处理）

1. 以目标商品全部讲解窗口为判断范围；Long Context Mode 先用窗口地图确保读取完整，再在读取目标窗口时直接判断购买价值并考虑编排。
2. 遵循 **卖点决定“留不留”，结构决定“怎么排”**。凡是原话提供新的、有效的商品购买决策信息，都作为候选，包括效果、版型、材质与触感、舒适度、功能、设计、颜色、搭配、人群与身材适配、尺码、场景、季节、护理和限制。成交话术作为转化机会另行按语义价值判断，不作为商品卖点；具体价格、优惠、赠品、库存等动态交易信息按 `references/editorial-policy.md` 全局默认排除。不同类别可以同时进入同一成片；不得因主题不同、开头方向不同或衔接暂时不顺而淘汰独立有效信息。
3. 去重只看是否提供了新的购买信息。真正同义、只重复情绪而无信息增量的表达可择优保留；同类别的不同事实仍分别保留，例如不同版型效果、不同搭配理由或不同适用条件。同一具体卖点最多保留两处原话：主表达之外的第二处须有补充证据、感受、条件或更好承接价值。
4. 在筛选和排序中同时保留核心与次要购买信息。可按实际作用区分**核心购买理由、独立补充购买理由、弱增量信息**：这是同次语义判断中的作用层级，不是固定类目或额外台账。开头强度、类别、主题一致性只用于选入口或安排顺序，不构成卖点去留门槛。**进入候选不等于必须无条件进入最终成片**；若某个低价值补充会明显破坏节奏、造成信息跳跃、稀释主要购买理由或形成无意义堆叠，即使尚未触及120秒硬上限，也可按价值舍弃。无需建立卖点台账或其他中间结构；判断、筛选与成片组织属于一次语义编排。
5. 仅在商品归属无法确认、必要条件无法保留、已确认合规禁用、明确已知不实等现行规则要求时排除相关原话；保留必要的适用人群、安全、护理与限制条件。语义符合但画面依赖的内容按类目规则标注待核实。

### 第四步：开头、中段与结尾编排

1. **默认以第一次刷到视频的陌生顾客为开头判断对象，老粉兼顾但不主导。**开头不是“主播最想先介绍什么”，而是“陌生顾客为什么愿意停下来”。外观/使用结果、商品核心信息、真实顾客困扰、可信体验、版型/设计、材质体验等候选统一竞争，**不设固定类型排序**；比较顾客相关性、即时收益、差异性、**具体与可信度**和**后续承接**/兑现能力。差异性是重要加分项，不是硬门槛；普遍但强烈的结果型表达只要原文真实且后续能支撑，仍可胜出。纯颜色介绍、普通搭配、普通尺码、泛泛材质名或孤立“好看/洋气”等默认降级，但**颜色若直接带来明确顾客结果**（如显气色、不沉闷），且完整原话在相关性、可信度和承接上实际竞争力更强，仍可作为开头候选。链接、价格/库存/活动、直播过渡、强依赖前情或只对老粉成立的表达原则上不作通用首钩。选定后，在同一次编排中优先寻找能解释、证明或展示开头核心价值的原话；按最小充分承接原则选择最有说服力的部分，不穷尽同主题内容。若素材无法充分支撑开头，应重新权衡开头选择；不要求整条成片只围绕一个主题。这个“陌生顾客测试”只是同次 AI 语义判断，不新增流程节点、模型轮次或台账。
2. 顾客困扰必须来自顾客原话或主播清楚转述的顾客烦恼。主播回答不能单独冒充顾客问题；尺码建议、搭配建议、主播个人偏好不自动算顾客困扰。
3. 若主播明确确认商品存在顾客担心的负面表现，该困扰及确认性回答默认不作开头、不入片；用户明确要求制作该主题答疑时例外，仍须忠实原话且不得编造解决效果。
4. 中段先兑现开头价值，再容纳其他独立有效卖点。开头获得充分支撑且至少一个购买决策理由已经成立后，若原文存在自然、完整、**对陌生顾客也成立**的成交机会，应安排最早合理的成交机会；不能仅凭“拍/买/入/拿”等关键词逼单，也不必等待所有卖点讲完。成交话术按实际作用判断，可承担价值确认、人群/尺码适配、决策简化（颜色/款式选择）、行动引导或总结等不同作用，不要求固定类型。只对“老粉/老顾客/复购用户”等限定人群成立的购买建议默认降级，除非当前素材明确面向该人群，或同一句对陌生用户也有独立、完整的决策价值。成交之后继续覆盖其他独立购买价值；后续成交节点只有提供新增转化价值时才考虑。成交次数、位置、软硬类型比例不固定，结尾不强制逼单；没有优秀成交话术时可以不放。**弱成交话术不得挤占独立有效卖点**，重复行动引导、强依赖实时直播背景或限定老粉的话术在时长竞争中低于独立购买信息。可利用效果→原因、问题→解决、顾虑→回应、特点→使用价值、属性→场景、版型→身材效果、材质→穿着体验、设计→功能价值、单品特点→搭配、人群特点→适用理由等关系自然排序；这些关系是编排提示，不是硬模板，也不要求每条都覆盖。
5. 原文天然存在的痛点与回应、预期与结果、普通状态与实际效果、错误认知与事实、前后变化等真实反差可适度提高其开头或中段优先级。只加权原文确实存在的关系，不制造冲突、故事、竞品比较、问题或承诺；没有真实反差时照常按购买信息价值编排。
6. 多方案执行 **Single Analysis, Complementary Multi Output（单次分析、多条互补）**：商品识别、语义筛选、合规判断与来源归属只做一次；每条先保证自身能够独立成立，再按不同钩子、主要购买理由、顾客需求角度、承接关系、搭配/使用场景或中段信息组合形成实质互补。**核心购买理由和不可替代的承接可以跨方案共享**；独立但次要的有效信息优先分配给最匹配的方案。每增加一条正式方案都应带来新的购买决策价值，不能只更换第一句而让主体长期高度同质。优先级固定为：**单条质量 > 多条价值差异 > 形式上的低重复**；不得为了制造差异把第二条、第三条故意做弱，也不强制为了覆盖候选而硬凑低质量方案。
7. 结尾选择最自然、语义完整且有价值的原话；可以是商品价值、购买建议或成交引导，不强制安排逼单。动态交易信息在开头、中段、成交节点和结尾一律默认排除；仅用户明确要求制作有效期明确的活动素材并确认发布时仍有效时，才对该任务例外处理。
8. 可以重排同一商品的原话，但必须保持对象、条件和原意。不能拼接不同商品或把不同款的事实混在一起。缺少有力开头或结尾时如实说明。
### 第五步：时长计算

- 播放速度统一按 **1.2 倍速**估算。
- 每条方案预计成片时长不得超过 **120 秒**。
- 预计时长按：`选段原始时长 ÷ 1.2 + 已知未加速片头/转场/停顿` 计算。
- 毫秒四舍五入到最近 1 毫秒，正好半毫秒向上。
- SRT 来源时间码与定位保持原素材 1.0 倍口径，不缩放。SRT 选段按连续组的起止跨度估算，组内空隙计入；逐条时长文本按入选条目时长累计，未知字幕间隔不计入并需说明。
- 超过 120 秒时先排除本就不合格的无关闲聊和默认排除的动态交易信息等，再按以下顺序压缩：**真正语义重复 → 没有信息增量的重复夸赞/情绪强化 → 购买决策价值较低的内容 → 已被更强片段充分覆盖的次级信息 → 最后才是在确实时长不足时舍弃独立有效卖点。**不得因主题不同、开头方向不同、结构不统一或衔接不便优先删除独立购买理由；不突破硬上限，因时长不得不舍弃时说明具体取舍。
- 多方案任务中，如果当前方案内两个候选价值接近，而其中一个次要购买理由已在其他方案获得充分覆盖，可轻度降低它的重复优先级，把时长让给尚未利用的有效购买理由；但不得因此删除当前方案不可替代的核心信息或必要承接。
- 充分筛选后预计 30 秒以下，标记为“短候选，非正式成片”；大于 30 秒但不足 45 秒可以交付，并说明素材本身限制，不硬凑。
- SRT 或逐条时长文本无法核实实际导出时长、实际剪辑间隔和 1.2 倍速后的语音清晰度，必须如实说明。

### 第六步：一次最终检查与局部修复

按 `references/final-check.md` 完成现有的一次终检，核实成片来源、原意、条件、顺序、时长和合规；不新增全文回扫或独立遗漏检查阶段。
发现错误时只修复受影响的商品归属、字幕、亮点、顺序或计算，不重跑无关步骤。只有输入变化、来源映射错误或质量条件失败时才重新打开整份方案。

## 4. 合规规则

### 全商品统一禁令｜两种更新入口
- **唯一权威执行库**：`references/global-rules.md`。所有现有及新增商品类目统一继承；专项模块不得覆盖、放宽或另外维护重复禁令。
- **更新入口仅有两种**：①用户提供抖音/千川违规审核截图；②用户明确说某词句违规或要求禁用。AI 识别截图实际指出的违规宣传，或按用户明确指定内容更新全局库。无法从截图可靠定位具体词句时才询问，不根据笼统“虚假宣传”“资质不符”推造禁词。
- **严格语义边界**：AI 识别字形、数字、口语和语义等价变体；相近但含量、成分、保证程度、对象或条件不同的表述不得自动扩禁。否定/引用语境需判断实际是否构成禁用宣传；用户明确要求“该词不论语境禁止出现”的按字面禁用。重复内容合并，记录截图或用户要求的来源；用户内部禁令不冒称平台通用禁令。
- **命中即排除完整原始字幕序号**：不能在同一序号中抠除违规词后保留剩余正常卖点。同一序号涉及其他商品也整条排除；跨连续序号共同构成禁用宣传时，仅排除确实参与构成该表达的序号，不连带排除其他正常序号；不扫描无关商品的全部窗口。
- **疑似识别错误**：能依据原始连续语境可靠确认命中时排除；无法确认时把相关序号标记待回听，暂不纳入正式成片，不得伪称已核实音频。
- **执行位置**：识别目标商品及其全部离散讲解窗口时同步筛查，在编排前排除确定命中的序号；从其他合规原话补足不同卖点并检查剩余语句完整性。原有一次最终检查对入选字幕、标题与话题核对；违规标题/话题仅重写受影响字段。命中时在例外中记录排除序号、对应禁用表述和原因；无命中不另出报告。
- **材质证明审核案例**：截图明确将某材质/成分宣传指认为需要证明且被拒审时，将能够定位的对应表述及其等价变体纳入全局禁令，命中即整条排除，即使后来拿到证明也不自动解除。不要仅凭一个材质名扩大到整类材质。纯商品资质/链接问题不自动转为禁词。
- **效率**：日常只用离线规则，不联网、不定期搜索、不建立新强制流程/程序/JSON。若用户另行明确要求调查官方政策，可单独处理，但不自动扩大全局禁用库。一般风险、动态价格/库存和未经证实的信息继续按 `references/qianchuan-offline.md` 及现有业务规则处理。
- **诚实与来源**：保留原始序号和原话；不改写、不跨商品混编、不声称平台保证过审；历史审核案例未直接证实的官方普遍禁词不得伪称官方规定。

## 5. 固定五部分交付

### 一、文件解析结果
写明文件名、输入类型、原始字幕条数/覆盖跨度（如可得）、执行模式（Standard/Long Context）、目标商品窗口数量、入选条数、组数、原始选段时长、预计 1.2 倍速成片时长，以及实际核验方式。若未运行程序，明确写“模型逐条对照，未运行程序”；不得写程序通过。末尾简要说明实际检查范围及合规风险。

### 二、商品识别
列出目标商品、别称、离散讲解窗口、必要的商品归属说明，以及加载的类目模块。多个商品未指定时，先询问，不进入正式方案。

### 三、最佳成片方案
默认一条；用户明确要求多条时最多三条。每版说明主卖点或开头切入点（仅描述本版入口，不构成单主题限制）、预计时长、原始选段时长、逐组原话与来源序号。
- 原话逐字保留，按成片播放顺序展示；不得润色或拼接造句。
- 每组使用简短作用标签，例如“开头钩子”“版型承接”“材质细节”“搭配补充”“自然收尾”。
- 逐版列出亮点覆盖清单，说明核心/次要、入选序号、同义关系和未入选原因；同一卖点保留两处时，标明第二处的强化价值，不把它误报为新的独立卖点。只有一条方案时不增加额外统计结构；多条方案时，在各版之后增加一个**简短的整体覆盖摘要**，说明独立有效购买理由中哪些至少被一版覆盖、哪些属于跨版共享核心理由、哪些未采用及原因。**不输出机械覆盖率百分比**，不为生成摘要另建卖点台账或新增模型轮次。
- 仅将商品归属不明、明确已知不实、当前素材明确拒审、用户指定禁用句等真实例外单列；时长取舍与方案侧重点不是素材违规例外。
- 疑点紧邻对应片段说明，不得只在文末笼统提醒。
- 不显示逐句毫秒时间轴或冗长过程证明；SRT 仅给大致组级来源定位，逐条时长文本给未缩放累计位置估算。
- 30 秒及以下标记“短候选，非正式成片”。

### 四、作品标题与话题
每条方案恰好一个标题、**五个话题**。话题必须与当前商品、类目和该版主线相关；不得彼此重复。已加载的类目模块可以指定最多两个类目固定话题，即**类目模块可固定最多两个类目话题**；通用核心生成其余话题补足五个；没有专项模块时，由通用核心生成五个相关话题。**通用核心不得强制加入其他类目的话题。**标题和话题不得编造事实、价格、库存或未证实功效；标题与主线一致。

### 五、原始 SRT 序号
按成片播放顺序列出原始序号。所有方案放在同一个文本代码框中，每版一行，半角逗号分隔、无空格，方案之间空一行；代码框内不放其他文字。不得伪造原始序号。

## 6. 能力与诚实边界

- 0.3.19 正式跨平台支持 SRT 和逐条时长文本。
- MP4、ASR、音画核验不在首版正式范围；没有实际视频能力时不得声称已看画面或听原声。
- 文件读取能力不足时，请用户粘贴文本或分段提供；不得声称完整读取未获得的内容。
- Python、计算器、脚本或其他工具都是可选增强，不是普通任务的必需条件；Long Context Mode 也不得把它们变成硬依赖。
- 不报告未执行的扫描、核验、测试或环境检查。

## AI-First Constitution

# AI-First Constitution

本文件是 C2 Universal 的最高架构约束。后续任何版本、平台适配、长文本优化、类目扩展或测试体系不得与本文件冲突。

## 1. 决策权

AI 负责全部语义决策：商品识别与切换、指代、商品归属、卖点/亮点、核心与次要、重复与强化价值、开头、中段、结尾、多方案分配、合规语境和最终取舍。

工具、Python、脚本、检索器、计算器和平台能力只能提供机械证据或降低读取/计算成本，不能拥有业务决策权。

## 2. 主路径必须无工具硬依赖

- 每个新功能必须先定义“仅依赖 AI + 可取得文本”的可执行主路径。
- 不允许把某个 Python 版本、某个脚本、某个平台 API、联网能力、JSON 中间文件或环境自检设成普通任务的进入门槛。
- 工具不可用时，只要文本仍可可靠取得，继续执行；在交付中如实写明实际核验方式。
- 只有原始输入无法取得、存在无法补齐的截断、来源范围无法确认或用户要求的能力本身不存在时，才暂停受影响部分。

## 3. 工具允许做什么

允许：分段读取、范围提取、序号/时间码定位、累计时长、编号/格式检查、查找确切文本、机械去重候选、生成测试数据。

不允许直接决定：
- 哪个商品正在被讲；
- 某句是否属于目标商品；
- 某句是不是核心卖点；
- 两段是不是语义重复；
- 第二处重复是否值得保留；
- 开头优劣；
- 多方案如何分配；
- 某个表达在具体语境中是否合规。

这些都必须由 AI 结合上下文判断。

## 4. 反过度工程

- 不为“可程序验收”牺牲自然语言理解质量。
- 不恢复逐条 JSON 语义台账、强制多阶段 Gate、重复环境测试或“程序没跑就不能交付”的旧架构。
- 需要更高可靠性时，将来源与购买信息判断整合到同次语义筛选/编排中；不以增加独立遗漏扫描、全文复查、台账或模型轮次换取形式上的检查。可选机械读取与来源定位仍可按需使用。

## 5. 未来修改验收

每次升级必须回答并通过以下内部检查：
1. AI 是否仍是所有语义判断的最终决策者？
2. 工具全部不可用时，只要文本可读，核心任务是否仍能完成？
3. 是否新增了隐性环境前置条件？
4. 是否把长文本、多方案或合规判断错误外包给机械规则？
5. 新规则是否与原话、来源、120秒、卖点覆盖和五部分输出发生冲突？

任一答案不符合本宪章，修改不得发布。

## 6. 固定版本更新协议

未来每一次修改均须执行 `references/update-protocol.md` 的六项审查、三条一票否决、版本记录和同步状态核实。该协议仅作用于开发/发布，不得增加日常文本任务的工具或环境负担。

## 自动识别

- 用户未指定时，根据商品名称、字幕中主播的商品自称、材质/功能/用途及上下文识别类别。

## 通用编辑规则

# 通用开头、承接、结尾与原话规则

本文件适用于所有带货类目。若商品存在已建立的类目模块，同时读取该模块；类目模块只能补充本文件，不能覆盖全局原话、来源、合规和时长规则。

## 开头候选

- 开头候选必须与目标商品相关，原话完整、自然，脱离直播上下文后仍能理解，并能承接同一商品的后续内容。
- 默认把**第一次刷到视频的陌生顾客**作为第一判断对象，老粉兼顾但不主导。候选包括：吸引人的外观/使用效果表达、商品核心卖点、真实顾客困扰、可信的购买者体验、具体版型/设计价值和材质体验。它们**不设固定类型排序**；统一比较顾客相关性、即时收益、差异性、具体/可信度、句子完整度和后续承接。**差异性是重要加分项，不是硬门槛**；即便“显瘦/好看/利落”等不是独家卖点，只要原话具体、对陌生顾客有强收益且后续可兑现，仍可成为最佳钩子。
- 不要把“顾客困扰”标签直接当成排序结果，也不要把主播回答、主播个人偏好或一般选购建议伪装成顾客表达。
- 顾客自己提出的完整疑问或困扰可以作为候选；主播清楚转述顾客担忧时也可作为候选。主播回答应放在问题之后，不能单独冒充顾客问题。
- 顾客困扰必须表达顾客实际购买、使用或体验中的烦恼；商品属性本身、普通尺码建议、搭配建议、主播提问或泛泛描述不自动构成顾客痛点。
- 若主播明确确认目标商品确实存在顾客担心的负面表现，该困扰和确认性回答默认不入片、不作开头。用户明确要求围绕该问题制作答疑时例外，仍须忠实原话，不暗示商品能够解决它。
- 纯颜色名/配色、普通搭配、一般尺码建议、泛泛材质名、孤立“好看/洋气”等如果没有马上转成顾客收益，默认属于普通或弱钩子；它们不是绝对禁用。完整原话若把颜色等属性直接转成显气色、不沉闷等明确结果，并且实际竞争力更强，仍可参与开头竞争。链接、价格/库存/活动、直播过渡、强依赖前情以及只对老粉成立的表达原则上不作通用首钩。\n- 不得编造顾客问题、商品效果、用户评价或后续解释。没有合适开头时，选最清楚、最有辨识度的商品事实；仍没有则如实说明，不用促销、颜色词或碎片口播凑开头。

开头确定后，优先寻找能解释、证明或展示其核心吸引点的原话。以下关系只帮助判断语义承接，不是分类模板，也不要求穷尽：

| 开头价值 | 可优先寻找的支撑内容 |
|---|---|
| 好看、颜值 | 上身效果、版型、材质质感、设计细节 |
| 显瘦、显高 | 剪裁、版型、身材修饰、视觉比例 |
| 材质特点 | 材质表现、触感、质感、实际穿用体验 |
| 穿着舒服 | 柔软度、弹性、亲肤感、真实穿着体验 |
| 搭配好看 | 颜色关系、搭配方式、不同穿搭效果 |
| 保暖 | 面料特点、真实保暖表现、穿着场景 |
| 解决困扰 | 困扰原因、原文中的解决方式及可支持的效果 |
| 性价比、价值 | 商品本身的价值构成；不依赖实时价格、优惠或赠品 |

采用**最小充分承接**：优先选最有说服力且足以兑现开头的原话，不要求全部出现相关卖点；不连续堆砌同义表达，不因开头主题而延长前半段。若素材支撑不足，应重新权衡开头，而不是拼凑解释。具有独立购买价值的其他卖点继续进入后续编排。

## 原话与语义

- 原话必须逐字保留；命中全局禁令时按完整原始字幕序号排除（不进行句内拆分）；其他非禁令的选段规则照旧，不得润色、改写、拼接造句或补充商品事实。
- 允许重排同一商品的原话，但必须保持对象、条件、因果和原意。不能跨商品拼接。
- “它/这个/那款”等指代不清时，先查必要前后文；仍不能确认商品归属则不入正式成片或明确标待核实。
- 连续原话整体可理解、只是疑似字幕识别错字时，优先原样保留并标记回听；不能仅凭错字擅自改写或拆句。
- 开头或片段若依赖“所以/但是/因为”等前文，补最短必要上下文或换更自然的候选；无法解决则不作为正式方案。
- 衔接困难不等于可以删除有价值的不同亮点。先寻找替代原话、调整顺序；仍需确认时保留并标“衔接需回听”。

## 中段与多卖点编排

- 开头之后先接足以兑现开头核心价值的最小充分内容，再自然容纳其余独立有效卖点。带货成片可以同时包含多个信息类别，不要求全片只围绕一个主题。**默认单条先追求成片自身质量，再追求覆盖广度**；有效候选不等于必须塞入最终成片，低价值补充若明显破坏节奏或稀释强购买理由可以舍弃。
- “同一主题先讲完”只可用于避免打断一个问题的直接回答，不是卖点筛选或删除规则。主题先后只影响编排，不决定卖点去留；结构暂时不好排、与开头角度不同，也不能作为淘汰独立购买信息的理由。
- 搭配、颜色、使用场景、规格、尺码、护理方式、适用人群及限制都可能有独立购买价值；是否保留看它提供的信息增量和现行时长约束。
- 不同事实不能仅因同属一个类别而合并。去重只按是否新增购买信息；同义表达可择优保留，同一卖点最多再留一处有实质强化价值的原话。该限制按单条方案内部去冗余理解；多方案之间允许按各自结构共享不可替代的核心购买理由。
- 用户要求多条时，执行“**单条最优，多条互补**”：每条都必须独立成立；核心购买理由和必要承接可以共享，独立次要亮点优先分配给更匹配的方案。每增加一条应带来新的购买决策价值，不能只换开头后长期复制主体，也不能为了降低重复故意削弱第二条、第三条。
- 效果→原因、问题→解决、顾虑→回应、特点→使用价值、属性→场景、版型→效果、材质→体验、设计→功能、人群→适用理由可辅助重排，不是硬模板。真实反差只作轻量加权，禁止编造冲突。
- 开头价值获得充分支撑且至少一个实际购买理由成立后，优先选择原文中**对陌生顾客也成立的最早合理的成交机会**；不为等到所有卖点讲完而推迟，也不为追求更早位置而牺牲必要承接。成交话术不限定软硬程度或功能类型；价值确认、人群/尺码适配、款式/颜色选择、决策简化和行动引导都可按实际语义承担转化作用。
- 第一次成交之后继续考虑尚未覆盖的独立购买理由。后续成交节点仅在增加新的转化价值时安排；成交次数、位置及软硬比例动态决定，不设置双逼单或固定中段成交，也不要求结尾逼单。
- 搭配建议中顺带提到另一件商品，不代表当前目标商品切换；只保留搭配关系和解释该搭配所必需的内容。另一件商品的独立规格不能混入当前商品方案。

## 动态成交引导与动态交易信息

- 成交话术是否入选由其语义和新增转化价值决定，不靠“拍/买/入/拿”等关键词识别。它可以承担价值认同、购买建议、人群/尺码适配、款式/颜色选择、决策简化、行动引导或总结收口；不要求固定类型或顺序，不设置固定次数、位置或软硬比例。\n- **限定老粉话术**（以及“老顾客/复购用户”等限定人群话术）默认降级，**不是禁止**，但默认不作为面向陌生流量的优先成交节点；只有当前素材明确面向该人群，或同一句对陌生顾客也提供独立完整的购买决策价值时，才按实际价值参与竞争。弱成交话术、重复劝买和强依赖直播前情的行动引导不得挤占独立有效卖点。
- 具体商品价格、原价/现价对比、限时优惠、优惠券、满减、赠品、直播间福利、倒计时、库存/稀缺数量、最后一天、即将涨价及其他依赖实时交易条件的信息，全局默认排除，不得进入开头、中段、任何成交节点或结尾。普通批量切片始终采用这一默认规则。
- 仅当用户明确要求制作有明确有效期的活动素材，并确认价格、活动条件和实际发布时段仍有效时，才对该任务例外处理。此规则是长期素材的选片边界，不代表平台将这些内容认定为违规。
- 商品本身的设计、材质、版型、体验、搭配、场景及其他不依赖实时交易条件的购买理由仍可保留。笼统的商品价值表达不能因“价格”字样被误判为动态交易信息，但不得借价值表述带入具体实时价格或优惠。
- 同一字幕同时包含动态交易信息和商品卖点时，只有在排除动态部分后，剩余内容仍能逐字对应**完整原话子句**，且该子句是原始连续表达、语法与语义完整、脱离被删除交易条件后仍可独立成立并与成片衔接自然，才可只选该子句并保留原始序号。仅剩词组或残句时不保留残句，应舍弃整条相关字幕。不得改字、补词或拼接不连续片段；若完整子句依赖前文，只在已选内容能自然承接时使用。
- 本条混合话术处理不改变 `global-rules.md` 的禁令边界：命中全局禁用表述时，仍须排除完整原始字幕序号。
- 结尾可以用商品展示、有效价值总结、自然购买建议或有行动指向的原话；没有合适的成交话术时自然收口，不强制逼单，也不为传统结构破坏衔接。

## 社会证明与事实

- 购买者真实反馈在来源清楚、原话完整且表达有吸引力时可以作为候选；裸销售数字、复购量或单纯“买了”不自动构成有力开头。
- 主播泛称“大家都喜欢”不等于真实顾客反馈。无法核实的社会证明要标记，不扩写为所有顾客都喜欢。
- 历史价格、库存、售后、链接、销量或活动不代表当前事实。不得将其写成当前承诺。
- 安全风险或明确不适用人群信息不能被悄悄删除或弱化；保留完整原话并标明需要核实的适用条件。若同条原始序号命中全局禁用表述，则全局禁令优先排除整个序号。

## 购买信息筛选与多卖点编排

# 购买信息筛选与多卖点编排规则

## 基本原则

**卖点决定“留不留”，结构决定“怎么排”。单条最优，多条互补。**本规则在现有 AI 语义筛选与编排中一次完成，不增加独立主题分析、卖点池、遗漏检查、复查或大纲生成阶段。内部可按需要记住来源与条件，但不要求中间台账、JSON 或额外模型轮次。

凡是原话提供新的、有效的商品购买决策信息，都应成为成片候选。常见信息包括上身/使用效果、版型、材质、面料、触感、舒适度、功能性能、设计细节、颜色、搭配、适用人群、身材适配、尺码、场景、季节、护理要求和限制条件。成交话术作为转化机会单独判断；具体价格、优惠、赠品、库存等动态交易信息不属于商品卖点，默认依照 `editorial-policy.md` 全局排除。清单用于提醒，不是每条必须包含的模板。

## 去重与去留

- 判断是否重复，只看这段内容有没有带来新的购买信息，不看它们是不是同一类别。
- “特别显瘦 / 真的很显瘦 / 穿起来非常显瘦”在信息相同且没有新增证据时可择优保留。
- “肩线往里收、不显肩宽”与“腰线做高、更显腿长”各自提供不同效果，应分别保留；同类别的材质、颜色、搭配、场景、护理或适用条件也适用此规则。
- 情绪表达只有在确实增强理解、体验或可信度时才算强化价值；单纯换词夸赞不构成新的卖点。
- 对同一具体卖点，除了择优保留的主表达，最多再留一处确有新角度、证据、感受、条件或承接价值的原话。不同信息不可套用这一上限互相合并。**该“两处”上限主要约束单条方案内部去冗余，不是整个多方案任务的累计上限**；核心购买理由若对不同方案都不可替代，可以在各方案按需共享。

## 编排

- 不要求一条成片只有一个主题，也不以主题一致性决定卖点去留。多个类别的有效信息可以自然共存；不要求把每个类别都输出成独立段落。
- 开头从现行允许的强兴趣入口中选择，默认以第一次刷到视频的陌生顾客为判断对象。上身/使用结果、真实困扰、具体好看/高级/显瘦/利落、版型设计、材质体验等类型统一竞争，**不设固定类型排序**；比较顾客相关性、即时收益、差异性、具体/可信度和后续兑现。差异性是重要加分项，不是硬门槛。纯颜色、普通搭配、一般尺码、泛泛材质或孤立夸赞默认降级，但若完整原话直接产生强顾客收益且实际胜过其他候选，仍可胜出。选定后，优先寻找能解释、证明或展示开头核心价值的原话；只取最有说服力且足以兑现开头的最小充分承接，不穷尽同主题片段，不连续堆叠同义表达，也不为主题统一而延长前半段。素材支撑不足时重新权衡开头；其他具有独立购买价值的信息仍进入后续候选。之后可利用效果→原因、问题→解决、顾虑→回应、特点→价值、属性→场景、版型→身材效果、材质→穿着体验、设计→功能、单品→搭配、人群→适用理由等真实关系自然排序。它们只辅助安排顺序，不是硬结构。
- 原素材中的真实反差可作为轻量加权：痛点→回应、预期→实际结果、普通状态→效果、错误认知→事实、前后效果变化等。不得为故事性编造对立、问题、竞品比较或效果承诺。没有真实反差时按通常购买价值编排。
- 可以为衔接重排同一目标商品的原话；保留对象、条件、因果和原意，不跨商品或款式混编。结构不顺时先调整顺序或选更自然的原话，不能把“难排”当成删掉独立卖点的理由。

## 单条最优与多条互补

- **默认单条方案**：先保证本条自身的停留、说服和购买路径成立，再在节奏与时长允许范围内尽可能覆盖独立有效购买理由。开头只决定入口，不建立“内容围墙”；完成最小充分承接后，可以继续进入材质、功能、设计、搭配、场景、适用条件等其他独立信息。
- **覆盖不是塞满**：一个信息成为有效候选，只代表它有资格参与成片竞争，不代表必须无条件入选。若低价值补充会让视频拖沓、跳跃、稀释强理由或接近“商品说明书”，可以舍弃；120秒是硬上限，不是目标时长。
- **多条先独立成立**：用户明确要求2—3条时，以请求数量为目标，先保证每条都有足够强的入口、承接和购买理由，再做方案间互补。若素材不足以让全部方案独立成立并带来新增决策价值，只交付可支撑的高质量方案数，并在第三部分说明素材限制；不以弱信息补数。
- **核心可以共享，次要尽量互补**：核心购买理由、某个开头成立所必需的解释、对不同决策路径都重要的事实可以跨方案共享；独立但次要的搭配、颜色、场景、围法、设计细节、辅助适配信息等，优先分配到最匹配的方案，减少无意义重复。
- **每增加一条都要有新增决策价值**：新增方案至少应在开头切入、主要购买理由、顾客需求角度、中段信息组合、使用/搭配场景或购买决策路径中的一项形成明显价值差异。只换第一句、主体大段复制，不视为理想多方案。
- **不使用机械重复率或覆盖率**：不设30%、50%等文本差异阈值，也不要求100%候选覆盖。判断对象是顾客购买决策价值，不是句子数量。优先级为：**单条质量 > 多条价值差异 > 形式上的低重复**。
- 多方案仍属于 **Single Analysis, Complementary Multi Output**：商品归属、合规、语义去重和购买价值判断只做一次；互补分配在同一次编排中完成，不增加额外卖点池、覆盖矩阵、第二轮遗漏检查或模型轮次。

## 购买理由递进与动态成交

- 开头价值得到充分支撑、购买理由成立后，优先寻找原文中**对陌生顾客也成立的最早合理的成交机会**，并确认其自然、完整。是否成立由购买价值决定，不由卖点数量或固定时间决定；不能仅凭“喜欢的可以拍”等关键词忽略上下文，也不为提前成交牺牲必要承接。
- 第一次成交机会不限定软硬程度或话术类型。价值认同、购买建议、人群/尺码适配、颜色/款式选择建议、决策简化、行动引导或总结均可按实际语义判断；这些类型只是说明其转化作用，不设固定顺序。**老粉、老顾客、复购限定成交话术默认降级**，除非当前任务明确面向该人群，或同一句对陌生用户也有独立决策价值。
- 成交之后继续筛选并编排其他独立购买理由。允许没有成交话术、只有一次、或存在多个不同价值的成交节点；不设置固定成交次数、位置或软硬比例，不强制结尾逼单。后续节点必须带来新增转化价值；表达相同意思的重复话术择优保留，不拆句凑节点。
- 成交话术不替代商品卖点覆盖；既不能因为前面已成交就停止考虑材质、功能、搭配、颜色、场景、适用条件等独立信息，也不能为了满足某种成交结构删掉这些信息。**弱成交话术不得挤占独立有效卖点**；重复劝买、限定老粉或强依赖直播前情的普通行动引导，在时长竞争中低于独立购买信息。

## 时长不足时的取舍

现行时长上限不因本规则改变。先按现行规则排除不合格片段；若有效内容仍超时，依次淘汰：

1. 真正语义重复的信息；
2. 没有信息增量的重复夸赞或情绪强化；
3. **重复或弱成交话术**，包括限定人群或强依赖直播前情且没有新增决策价值的行动引导；
4. 购买决策价值较低的内容；
5. 已由更强片段充分覆盖的次级信息；
6. 只有在确实时长不足时，才舍弃部分独立有效卖点，并说明具体原因。

多方案任务中，若当前方案两个候选价值接近，可把“该次要理由是否已在其他方案充分覆盖”作为轻量取舍因素，优先把空间留给尚未利用的有效购买理由；这只能用于价值接近的次要内容，不能覆盖当前方案自身的核心需要。

动态交易信息在开头、中段、首次或后续成交节点及结尾一律默认排除；只在用户明确要求制作有效期明确的活动素材，且确认活动条件与发布时段仍有效时，对该任务例外处理。真实商品价值和不依赖直播实时条件的成交话术仍按购买价值及语境判断。无论何种取舍，都不能突破当前正式版本的时长上限。

## 类目边界

同类别的不同事实仍按各自的信息增量判断。本规则是跨类目通用编排层。鞋类、围巾、服装等专项模块继续判断各自的关键属性、限制、证据和归属；专项规则可以补充通用层，但不能把同类当同义或以主题一致性删掉独立有效信息。合规禁令、商品归属、必要条件、原话真实性及现行结尾规则优先执行。

## Long Context Mode

# Long Context Mode｜AI-First 长文本模式

## 目标与边界

在数百到数千条字幕、数十分钟到数小时直播文本中，确保文本和目标商品窗口不被截断或漏读。长文本模式只管理读取覆盖和商品边界；商品理解、购买价值判断、去重、筛选和编排仍由 AI 完成。分段读取是输入管理，不是新增模型轮次或额外语义复查。

## 何时自动启用

不设置“超过N条就必须调用Python”的工具门槛。全文一次读取有明显截断、遗漏、上下文污染或商品反复切换风险时启用；约1000条以上是强信号但非硬阈值，2000条、接近2小时的素材直接启用。工具不可用时，AI 仍按可读范围处理。

## 读取与编排

1. **确认覆盖与商品窗口**：按可用读取能力覆盖全文并识别商品切换、别称、款式与目标商品的离散窗口。分段之间保留必要边界上下文。窗口地图只帮助定位和确认覆盖，不包含强制卖点台账。
2. **逐个目标窗口完成同次语义处理**：阅读目标商品窗口时，直接判断商品归属、必要上下文、合规边界和每段内容的购买信息增量；在同一次语义处理中筛选并考虑自然顺序。不另设主题分析、卖点池建立、遗漏扫描或先大纲后成片阶段。
3. **围绕购买信息组织成片**：独立有效信息不因类别或主题不同而删除。同义内容按新增信息去重；效果与原因、顾虑与回应、特点与价值等关系仅帮助排序。真实反差可以加权，不制造原文不存在的冲突。多方案共享同一次商品归属、语义取舍和合规判断。
4. **时长装配**：汇集一次语义处理选出的片段，按现行时长规则计算。超时裁剪依据 highlight-selection.md，独立有效卖点最后才因时长不足舍弃。

## 一次终检

使用 final-check.md 对成片的来源、商品归属、原意、条件、顺序、时长、合规和输出格式进行一次终检；不再次通读完整目标窗口来另做遗漏检查。若发现输入范围确有缺口，只补读缺失范围；这属于读取完整性修复，不是卖点复查。

## 工具降级

分段文件读取、序号/时间码定位、时长累计可作为可选机械辅助，必须把语义判断留给 AI。缺少工具不构成失败；只有文本无法取得、范围存在无法补齐的缺口或关键来源无法确认时，才如实说明受限。

## AI 识别与排除

- 只将原词、格式变化和**语义实质等价**内容视为命中；不同成分比例、商品对象、程度或条件不能因词语相近就自动扩禁。是否定声明还是正面营销承诺须依据完整语境判断。
- 已确认命中时，**整条原始字幕序号排除**；同序号里其他正常句也不拆出。多个连续序号共同构成禁用表达时，仅排除实际参与的那些序号。其他正常序号不受牵连。
- 目标商品所有离散讲解窗口均执行该规则。一个目标字幕序号同时提到其他商品且其中有禁用表述，也整条排除。
- 疑似同音/错字、但尚不能可靠确定的序号暂不入正式成片，标记待回听；平台只给笼统拒审原因又无法定位原句时询问用户，不随意把整段判为禁词。
- 命中后优先从同一目标商品其他合规原话寻找替代，保证语义完整；不得改写、删字造句或重新加入禁用序号。
- 标题和话题命中禁令只重新生成受影响字段。仅实际命中时在五部分交付中的例外里注明排除序号、禁用表述和原因；无命中不额外报告。

## 一次最终检查

# 一次最终检查清单

每条正式交付在输出前完成现有的一次整体检查。此检查核实成片，不新增独立卖点遗漏扫描或全文复查阶段。

1. **输入范围**：确认实际读取的 SRT/逐条时长文本范围；未读或截断范围不能假称已读。Long Context Mode 使用窗口地图确认目标范围完整。
2. **商品归属**：每条入选原话确实属于目标商品；不同商品、不同款式的规格没有混用。
3. **类目规则**：已识别商品类别并加载已存在的适用模块；没有专项模块时没有借用其他类别规则。
4. **原话来源**：每条入选字幕原话、原始序号和来源位置一致；没有改写、补造或伪造编号。
5. **购买信息、覆盖与去重**：入选片段各自提供有效信息，或属于同一卖点的有价值补充；同类别不同事实未被当成重复。单条没有为了“覆盖更多”而塞入明显破坏节奏的低价值内容，也没有因为开头主题而漏掉仍有高决策价值的独立理由。检查实际取舍是否符合语义去重和价值优先级；这不是回扫原文的另一个筛选阶段。
6. **递进编排与陌生顾客视角**：开头默认面向第一次刷到视频的陌生顾客，能说明“为什么值得停留”，并在相关性、即时收益、差异性（加分而非硬门槛）、具体/可信度和后续兑现上胜过其他候选；纯颜色/普通搭配等没有顾客收益时没有误胜强结果型候选。开头吸引点获得最小充分支撑；购买理由成立后，首次成交机会安排在对陌生顾客也成立的最早合理且自然的位置；限定老粉的话术没有被误当通用逼单；成交之后仍考虑其他独立有效卖点；后续成交节点有新增价值；不强制固定成交次数、软硬比例或逼单结尾。
7. **时长**：按现行 1.2 倍速规则计算，每版不超过 120 秒。接近上限时，裁剪遵循 highlight-selection.md 的优先级，独立有效卖点只在确实时长不足时才考虑舍弃。
8. **合规与动态信息**：目标商品素材按现行规则筛查全局禁令和材质/功效证据；具体价格、优惠、赠品、库存等动态交易信息在开头、中段、成交节点和结尾默认排除。混合字幕仅可保留完整原话子句；删除动态部分后仍须语法、语义与衔接完整自然，仅剩词组或残句时舍弃整条相关字幕，不改字、补词或拼接不连续片段。全局禁令仍排除完整原始序号，未虚称平台审核结论。
9. **标题与话题**：一个标题、五个与当前类目相关的话题；不得混入未加载类目的固定话题，遵守全局标题/话题禁令。
10. **多方案质量与互补**：需要多方案时，方案来自同一次商品归属、购买信息判断和合规结论；每条先独立成立，再检查是否存在实质不同的购买决策角度。核心理由重复应有必要性，次要亮点在适合时尽量互补；不得只换开头后主体高度复制，也不得为了差异故意删掉某条不可替代的强卖点或用弱内容硬凑第二、第三方案。多方案整体覆盖摘要只展示既有判断结果，不新增覆盖矩阵、全文回扫或第二轮筛选。
11. **AI-First 与效率**：AI仍拥有所有语义决策权；普通任务没有新增脚本、结构化台账、模型轮次或额外确认门槛。
12. **五部分输出**：顺序、来源序号代码框、方案行数和必要风险说明均正确。

## 附录｜固定版本更新协议


# C2 Universal｜固定版本更新协议 (Update Protocol)

> 治理级规则。适用于今后每次业务规则、类目模块、平台适配、长文本、性能、合规基线及发布流程的变更。执行优先级：AI-First Constitution > 本更新协议 > 具体业务模块。不得以本协议替代或降低 SKILL.md 的现有剪辑要求。

## 一、更新的六项固定审查

1. **AI 主导**：先写出不依赖 Python、脚本、API、联网或中间 JSON，且原始文本可靠可读时 AI 能独立执行的主路径。商品归属、亮点、语义去重、结构、合规语境与最终取舍仍归 AI。
2. **工具最小化**：新增工具须明确机械用途、触发条件、准确性或端到端效率的可验证收益。禁止将工具可用性、环境自检或多层 Gate 设为普通文本任务前置条件；不得为实现形式上的自动化而增加重复调用。
3. **环境零强制与自动降级**：说明工具不可用时的 AI 主路径、需要告知用户的核验边界，以及仅在输入本身缺失、不可恢复的截断、关键来源无法确认等情况下暂停受影响部分；不能伪称运行过程序。
4. **质量不退步**：逐项核对原话真实性、字幕编号与来源、商品归属、独立购买信息覆盖、按新增信息去重、合规语境、1.2 倍速 120 秒硬上限和固定五部分输出。主题或类别不得成为删除理由；不得为了覆盖率新增普通任务的台账、遗漏扫描、全文复查或模型轮次。
5. **更新验收**：对受影响路径做最小充分回归；覆盖常规文本、相关长文本/多商品/多方案和对应类目场景。开发期可按需使用测试脚本；不得让发行测试成为日常执行的硬依赖。未实际测试的项目标记“未验证”。
6. **发布与同步**：记录实际变更的文件、版本号、GitHub/插件/便携包/云盘各渠道状态；仅对实际上传且可核实的渠道声明“已同步”。对比端到端耗时与工具调用次数时，只能报告实测，不得凭推测断言“更快”。

## 二、三条一票否决

- **无明确收益的工具否决**：新增日常工具调用，却无法说明其明确、可核实的准确性或端到端效率收益，不得发布。
- **质量下降否决**：简化步骤导致原话被改、商品串用、不同关键卖点漏选、来源编号错误、时长计算不可靠或合规误判，不得发布。
- **新环境硬依赖否决**：本来 AI 可以仅凭可靠文本完成的普通任务，新版本要求先装 Python、安装依赖、联网、生成 JSON 中间件或通过环境测试才能开始，不得发布。

上述条款不得用于禁止必要的可选机械校验：复杂长文本或时长计算可按需调用工具；其结果不能替 AI 作语义决策。

## 三、每次更新的固定记录格式

- **基准与目标版本**：旧版本 → 新版本；改动性质（业务/类目/平台/效率/治理/修复）。
- **变更范围**：具体文件、变更理由、影响场景和明确不变的规则。
- **AI 独立主路径**：在可靠文本可读且无工具时如何完成核心任务。
- **工具决策与降级**：每项工具的用途、触发条件、增益证据、不可用处理。
- **质量与兼容检查**：原话、商品归属、卖点覆盖、时长、固定五部分及相关类目/长文本检查结果。
- **端到端效率**：实测数据和条件；没测则写“未测”，不得以减少步骤数冒充耗时提升。
- **发布状态**：GitHub / 私人插件 / 便携包 / 云盘 / 其他平台逐项写“已核实 / 未同步 / 待核实”，不得笼统宣称全部完成。
- **最终判定**：“通过 / 不通过 / 待验证”，三项一票否决逐项写明。

## 四、执行边界

本协议只约束未来版本的**开发与发布**，不增加每次使用“srt文案”时的分析步骤、固定表单、Python 调用、环境检查或额外对用户展示的字段；日常五部分交付保持不变。

版本升级完成后，只有通过核验的已发布渠道才可称为“当前已更新版本”；其他渠道必须明确保留旧版状态。

# 开头钩子、商品顺序与句级处理

处理开头、材质平台反馈、穿搭搭配、逼单话术或商品归属前，先读本文件。这里是时尚品类的细则；通用判断仍遵循 `references/editorial-policy.md`。

## 开头：先识别候选，再比较吸引力

开头候选必须是目标顾客愿意听、原话完整自然、离开直播上下文也能理解的句子；它还要能接上同一商品的后续原话。**默认把第一次刷到视频的陌生顾客作为第一判断对象，老粉兼顾但不主导。**候选包括有吸引力的上身/外观结果、商品核心卖点、真实顾客困扰、版型/设计、材质体验与可信体验；这些类型**不设固定类型排序**。先判断句子是谁在说、表达的是顾客的问题、主播评价、商品事实、穿搭建议，还是成交话术，再统一比较：顾客相关性、即时收益、差异性、具体/可信度、后续原话能否兑现。**差异性是重要加分项，不是硬门槛**；普遍需求如显瘦、利落、好看只要表达具体且后续有原话支撑，仍可成为最佳钩子。不要把“困扰”“材质”“好看”等标签直接当成排序结果。

按下面的规则筛选：

1. **外观表达可以是强候选。** 对服装、箱包等外观消费品，完整清楚的“穿起来很好看”“显瘦又好看”等表达可以开头；女性服装中“好看”是有吸引力的外观理由。多个外观句都自然、强度相近时，明确说“好看”的句子优先于普通外观夸赞。无需凭画面替原话背书；若没有看过视频，只把语气和实际穿着效果列为未核实项。孤立的“好看！”、“你们看这个”等碎句仍不够完整。
2. **商品核心卖点可以胜过弱开头。** 用原话里辨识度高、归属明确的核心卖点；例如羽绒填充标准或面料工艺可比身高/短款选购建议更适合作为开头。卖点是否适合开头，要与其他合格候选比较，不因它是材质/工艺就自动第一，也不因有顾客困扰就自动排在后面。若商品资料可用，核对标准、成分和工艺；没有资料时，仍可把原话作为剪辑候选，但必须在对应片段注明资料待核实。不要补写原话没有的标准、含量或效果；已知不实或明确被拒审的说法按例外处理。
3. **顾客困扰也是有条件的候选。** 只有素材明确呈现顾客使用、穿着或购买时自己的烦恼，或主播清楚地复述/转述了顾客的烦恼，才进入候选；结合共鸣强度、句子质量及后面有没有相关原话判断。困扰确实最能打动目标顾客且有相关后续时可以开头；用户明确要多条方案时，也可把合适的困扰放在另一条方案开头。若后续明确确认目标商品存在顾客担心的负面表现，该困扰和确认性回答默认都不进入成片，也不得作开头；用户明确要求制作这项答疑时，再按原话如实呈现，不暗示商品能够解决问题。没有明确确认负面表现时，清楚且有信息价值的顾客困扰仍可在后文保留，说明素材没有对应解释，不能暗示商品解决它。
4. **颜色与普通介绍默认降级，不是绝对禁用，也不是关键词黑名单。** 纯颜色介绍、单纯颜色名、普通配色、一般搭配、普通尺码、泛泛材质名、孤立“好看/洋气/高级”等，如果没有立刻给陌生顾客明确收益，通常不如上身结果、身材修饰、真实困扰回应、具体版型/设计价值等强。若完整颜色原话直接带来显气色、不沉闷等明确顾客结果，并且在相关性、收益、可信度和承接上实际胜过其他候选，仍可做开头。链接、价格/库存/活动、直播过渡以及“老粉都知道/老顾客直接买”等强依赖既有关系的表达不作通用首钩。\n5. **没有合适候选时，** 选素材中最清楚、最有辨识度的商品事实；没有就如实说明，不用颜色搭配、尺码建议、促销或碎片口播凑开头。

### 认定顾客困扰

- 顾客自己说出的疑问、担心或穿用问题可以算，包括弹幕中的完整问题；例如“顾客弹幕：小个子穿这件会不会显矮？”可保留完整问题本身作开头，后面接原素材中的衣长、腰线等相关版型介绍。主播回答放在开头钩子之后，作为后续内容；不能把回答句单独当成顾客困扰，也不能把“问题＋回答”整体冒充一条顾客困扰。
- 主播清楚概括“顾客担心……”“很多小个子担心……”时可作为候选；普通主播提问、主播自己的偏好或商品描述不能在没有语境依据时冒充顾客表达。“我喜欢这件”不能推成顾客喜欢；清楚表达“因为穿起来好看所以喜欢”的完整原话可按其实际意思评估。
- **顾客困扰说的是顾客会遇到什么，不是商品有什么问题。** “这种颜色比较怕流水印子”是在描述商品/颜色，不等于顾客担心；“浅色衣服容易脏，怕不好打理”若明确表达为顾客的使用烦恼，才可候选。尺寸、衣长、选长短款、选颜色、问如何搭配，通常是选购或搭配问题，不是开头痛点。
- 不按商品品类或困扰种类设置固定黑名单。只要原话或清楚的主播转述说明顾客购买、使用或穿着时会遇到的具体烦恼，就可作为困扰候选；再按共鸣、句子自然度和相关后续判断是否适合开头。显矮、怕冷、易脏不好打理、怕闷热、穿着沉、鞋磨脚、包不好用、围巾肤感不适等都按具体语境判断，不因为类别本身自动通过或淘汰。
- 商品本身的颜色、质量或商品属性描述，不会自动等于顾客困扰；必须说清它让顾客产生了什么实际购买或使用烦恼。尺码建议、选长短款和搭配/配色建议仍不作为顾客困扰开头。“好看”是女装有吸引力的外观表达；颜色搭配建议、“显白”或“显年轻”单独出现都不作开头。若完整句同时有明确的外观吸引力和搭配信息，按整句实际表达比较，不把颜色搭配误标成顾客痛点。

### 负面特点、劝退表达与安全限制

- **明确确认商品负面表现的困扰默认排除。** 当顾客提出某个穿着/使用负面表现，而主播明确确认商品确实有该表现（如问“肚子大了会显吗”，回答“有肚子一定会显”），整组内容默认不入片，不作为开头。只有用户明确要求围绕该问题制作答疑时才可使用，必须忠实原话且不补造解决办法。
- **中性特点与劝退表达分开处理。** 若中性特点和劝退话术属于不同字幕序号，保留有价值的中性特点，删除劝退话术。若两者在同一序号，不做句内拆分；结合商品、该特点对购买判断的重要性和是否有其他原话替代，决定整条保留或排除。
- 同一序号中的中性特点很重要，且找不到其他来源明确的原话表达时，优先保留完整序号，放在正文后段。不得为了凑亮点把劝退话术另行改写成文案。
- **安全风险或明确不适用人群优先完整保留原话。** 即使与其他商品描述同处一个序号，也不拆句；在相应位置标出需核实的安全/适用依据。若同条原始序号命中全局禁令，则整条序号排除，并在例外中说明。

### 句子完整、相关承接与方案差异

- 直接保留最完整、最能听懂的困扰句。只有“这个/它”等指代确实不清楚时，才把最短的必要前句一起放进开头；如果前文很长，找更短的困扰候选，或改用外观/核心卖点。
- 选定顾客痛点后，先接与该问题对应的商品讲解。例如显矮/显臃肿接衣长、腰线、版型；保暖担心接实际保暖讲解。直接回应后可继续安排其他独立有效卖点；不要用无关内容打断问题回答，也不因主题不同而删除后续卖点。
- 不同开头候选都不强时，先换一段更短、更自然的原话，再考虑商品核心卖点。不要选读起来不通顺、需要猜错字、悬空的颜色词或“所以/但是”起头的半句。疑似转写错误保留原字并标回听，不代改。
- 多条方案按 Universal Core 的“单条最优、多条互补”执行：分别寻找有吸引力且有后续承接的入口，并让主要购买理由或中段信息组合产生实质差异；核心理由可按需要共享，不能只换开头后长期复制主体。用户要求的2—3条是目标数；素材只支撑更少的独立高质量方案时，按核心规则交付可成立的数量并说明，不硬凑。每版预计1.2倍速时长都必须不超过120秒。

## 商品描述、搭配、选购与结尾

- 开头后可先接直接回应，再按原话中的效果、原因、版型、材质、搭配或场景关系自然排序。主题先后只影响编排，不决定卖点去留；不得因类别不同、开头方向不同或“衔接不顺”删除独立有效信息。需要时重排原话或标注局部需回听。
- 将搭配、颜色和使用场景视为可能具有独立购买价值的信息；同类别中的不同事实不得自动合并。纳入与否按信息增量、商品适配、必要条件和现行时长优先级判断。对单条方案，尽量覆盖独立有效信息。相同卖点不再机械只留一处：若第二处原话有不同表达、补充信息、情绪强化或更好的承接价值，且总时长允许，同一卖点最多保留两处。多方案分配统一继承 Universal Core：重要且不可替代的理由可以共享；裤装/外套搭配、颜色效果、场景等女装次要信息优先进入最匹配的方案，尽量让有实际购买价值的不同理由至少在一版获得利用，但不为追求覆盖率破坏单条节奏或硬凑弱方案。搭配建议里顺带出现另一件商品，不代表切换为介绍该商品；只保留搭配建议及直接解释该搭配的必要细节。另一件单品的独立规格不混入目标商品成片。
- 尺码与选购建议放在商品介绍之后。它们能帮助选择，但不因指向“小个子/高个子”就变成顾客烦恼或开头。
- 成交话术按通用核心在购买理由成立后尽早、自然地编排；判断重点不是“有没有买/拍/入/拿”等关键词，而是它是否让**陌生顾客**更接近购买决定。价值确认、人群/尺码适配、颜色/款式选择、决策简化和行动引导都可以承担成交作用；不限定话术类型，不设固定次数或位置，也不强制结尾逼单。只对“老粉/老顾客/复购用户”等限定人群成立的购买建议默认降级，除非当前素材明确面向该人群或同一句对陌生顾客也有独立决策价值。首次成交后仍继续考虑材质、版型、体验、搭配、场景等独立购买理由；后续成交仅在增加转化价值时保留。普通重复劝买、限定老粉或强依赖直播前情的弱成交话术，不得为了结构占用本可保留独立卖点的时长。
- 具体价格、优惠、活动、赠品、直播间福利、库存、倒计时和其他依赖实时交易条件的信息，在整条成片所有位置默认排除。只有用户明确要求制作有效期明确的活动素材并确认发布时仍有效时，才对该任务例外。混合字幕仅在排除动态部分后仍能保留语法完整、意思自足的完整原话子句时才可取用；仅剩词组或残句时舍弃整条相关字幕，不得改字、补词或拼接。全局禁用表述仍按完整原始字幕序号排除。
- 购买者的真实反馈如“买过的姐妹都说好看”在来源清楚且表达有吸引力时可作开头候选；裸销售数字、复购量或单纯“买了”留在后段。明确无法核实的社会证明要标记，不扩写为所有顾客都喜欢。主播单说“大家都喜欢”不等于观众已表达喜欢。

## 用户指定禁用词句与审核截图

## 商品归属、事实冲突与话题

- 先认清主播正在介绍哪个商品。顺带出现的穿搭单品不是额外目标；明确切换后的其他款不混进当前成片。口播数字只有在语义明确指向款号或链接时才作商品标识；倒数、金额、尺码、销量或加库存后的报数不单独作为同款或链接证据，须结合明确的商品/链接话语和前后文。商品切换、别称和指代依据不够时查前后文，仍不清楚就标归属不明，不把它当成正式选段。
- 同品牌、同类的多个商品可以作为同一类目候选，但必须在工作判断和成片中区分款式/商品事实，不能把一件的版型、长短或面料说成另一件的。不同品牌、不同材质或明显不同款式应分别识别；不同长短款若同一设计/同款系列可放同一候选，但具体版型与衣长仍按各款归属标清。
- 商品资料与主播陈述冲突时，先用可靠商品资料确认；没有资料能判定时，优先保留说得更清楚且适合成片的一段，并在计划外说明原始矛盾。分别属于短/长款的衣长数字不是互相冲突。相反的主观穿搭意见可并存，保留各自条件，不伪装成同一事实。
- 标题和生成话题聚焦商品、外观吸引力或商品卖点，不以颜色搭配作为开头式话题，不写颜色名/配色组合；“显瘦又好看”这类原话有支持的外观利益可用。不得加入平台明确指出的违规词句、价格、库存、促销、SKU或未证实事实。本类目模块固定话题为 `#穿搭`、`#时尚营销`；通用核心再生成三个与该版商品/主线相关的话题，合计五个。该固定话题规则不得外溢到非时尚类目。
- **标题与话题全商品禁词：** 任何商品的作品标题和生成话题均不得出现“羽绒服”；仅该两个输出字段受此限制。正文原话、商品识别、素材例外和风险说明可以如实使用“羽绒服”，不因此删除正文。生成替代表达必须与原文支持的商品品类相符，不用猜测出来的词代替。

# 鞋类专项模块（Shoes）

## 适用范围、路由与边界

适用于所有作为目标商品销售的鞋类：单鞋、高跟鞋、平底鞋、皮鞋、靴子、雪地靴、运动鞋、跑鞋、休闲鞋、凉鞋、拖鞋及其他鞋型，不限性别与季节。用户指定商品优先；顺带提到的裤子、袜子、包或其他鞋款只是搭配/对比，不自动切换目标。与 `categories/womens-fashion.md` 采用排他式品类路由：以鞋类为目标商品时加载本模块，不同时加载女装模块的开头、排序、适配等专项规则。

必须服从 `SKILL.md`、`references/editorial-policy.md`、`references/highlight-selection.md`、`references/global-rules.md` 与 `references/qianchuan-offline.md`。本模块只增加鞋类语义判断，不新增固定输出、时长、工具或环境条件。以下范例仅用于解释判定，不能当成实际素材原话。

## 1. 开头：按鞋款动态判断

- 在原话中比较整体外观、上脚效果、鞋型、脚感、工艺/功能、真实顾客困扰等候选；以吸引力、商品相关性、语义完整度、后续承接与可信度决定，不设置“好看/舒适/痛点”机械排名。
- 顾客困扰须真实来自顾客原话或主播明确转述；普通尺码咨询、搭配建议、主播自问自答不能冒充顾客困扰。
- 开头依赖后续真实原话支撑，不能把“防滑设计”扩成“任何路面都不打滑”，不能把个体穿着感受扩成普遍保证。动态价格/库存不作默认开头。

## 2. 卖点盘点与中段装配

- AI 对实际字幕逐一识别：外观与上脚效果、鞋头/鞋型、修饰效果、鞋面及内里、鞋底结构、软硬与回弹感、重量、跟高、鞋筒/筒围、脚型与尺码适配、材质工艺、搭配、配色、使用条件及场景。以上是候选清单，不要求每款鞋都有。
- 分清独立购买理由：鞋底柔软、前掌空间、鞋跟高度、裤装搭配各有不同决策意义；不能笼统合并为“舒服/百搭”。单独的不同颜色、服装名称也不自动算新的购买理由，须判断真实信息增量。
- 开头后优先安排直接承接信息，再把其他独立有效理由按语义关系自然排列。鞋型、材质、脚感、适配、搭配、颜色与场景各自提供新购买信息时均可保留；不以主题顺序或类别差异作为删除依据，也不固定“鞋型→材质→脚感”。
- 同一卖点最多保留两处原话，第二处须有新信息、补充条件、独特体验或有效情绪强化；不同购买理由分别计数。该上限按单条方案内部去冗余理解。多方案时，鞋型、脚感、鞋底、跟高、脚型/尺码适配、搭配与场景等按 Universal Core 的“单条最优、多条互补”分配：核心理由可共享，次要有效理由优先进入最匹配方案。累计时长及压缩顺序完全沿用通用核心的 1.2 倍速、120 秒上限。

## 3. 脚型、尺码、穿着适配

- 分别识别脚宽、脚背高低、鞋头空间、脚长/尺码、鞋筒与腿围、鞋跟高度、试穿脚感、走路适应条件。哪些是核心取决于实际鞋款及字幕购买价值，而非固定全部置后或全部优先。
- “建议大一码”“脚背高不适合”“此款偏窄”等如来自可靠原话，应保留所依赖条件；不自行推断所有宽脚、胖脚、长时间步行均适配。买鞋建议不能被改造成承诺。
- 有明示的不适用条件、安全限制或相反证据时，不得通过截去条件留下“人人适合”“完全不会磨脚”等误导性正面承诺；无法同时在成片中可靠表达必要条件时，排除相关可能误导的正面原话并说明。

## 4. 材质、设计、体验、性能、风险

- AI 区分 **材质/参数事实**（如真皮、跟高厘米数）、**结构设计**（如防滑纹路）、**主播主观体验**（如踩着柔软）、**客观功能主张**（如防水、防滑）与**绝对化承诺**（如永不磨脚、走一天都不累）。不同类型不能互相证明。
- 对未有商品资料佐证的材质、功能与使用效果，按通用合规规则标待核实，不因缺少证明就一刀切删除全部材质原话；已知不实、已明确拒审或命中全局禁令时按更高优先级规则处理；明确命中全局禁令的，排除完整原始字幕序号，不在本类目句内拆分。
- 不凭鞋型或材质自行推出防滑、防水、耐磨、矫正姿态、治疗足部不适等效果；涉及医疗/健康效果须核实依据与平台限制，不把设计特征当实测性能。
- 普通负面体验（如新鞋略磨脚）按通用负面表述规则取舍；重要脚型限制、安全提醒不可被剪掉后使保留原话失真。对应正面与限制互相矛盾时先核对商品归属及上下文，仍不明则不作无条件承诺。

## 5. 多颜色、多版本与跨商品归属

- 同一商品不同颜色可以共用确实适用于各色的描述；颜色专属鞋面、材质、搭配及外观只归对应颜色。
- 不同鞋型、鞋底结构、跟高、靴筒、尺码版型、材质及明确不同链接/款号，按实际证据分别判定；同系列不自动等于同款，不同颜色也不自动等于不同商品。
- 不跨款继承脚感、功能、尺寸、鞋跟和适配建议；归属不确定则按通用核心核对上下文，仍不明时不选入正式成片。

## 6. 搭配、场景与画面依赖

- 分开盘点鞋与裙子、牛仔裤、西裤等搭配关系、颜色关系、整体穿搭效果及通勤、运动、休闲、约会等实际场景；按真实信息增量和时长动态取舍。主播提到某场景不等于证明鞋适合长时间负荷使用。
- “你看这个鞋头”“我这样弯给你看”等需画面才能判断的原话，若语义完整、有购买价值可列为候选并就地标注“画面待核实”；完全依靠画面、脱离视频无明确语义的空泛话语默认不入片。仅有 SRT 时不得声称看过上脚画面或演示。
- 成交话术与结尾执行通用核心的动态编排：购买理由成立后尽早安排自然机会，成交后继续覆盖其他独立购买理由；不固定次数、位置或软硬比例，也不强制结尾逼单。具体价格、促销、赠品、库存及其他动态交易信息在全片默认排除；混合话术仅按通用核心的完整原话子句规则处理，仅剩词组或残句时舍弃整条相关字幕。不创作原字幕没有的成交句。标题与话题延续时尚类目原有固定 `#穿搭`、`#时尚营销`，其余由核心补足五个并严格遵守全局标题禁词。

## 类目判断边界（纳入同次语义编排）

脚感、鞋底、跟高、脚型适配分别按购买信息判断；不得误判同义或跨颜色/鞋款混用事实。关键使用限制、未经核实功能与画面依赖按本模块原规则处理。这些条件在同次语义筛选/排序中应用，不另开复查阶段。

## 围巾专项


# 围巾与颈部穿搭配饰专项模块（Scarves）

## 适用范围、路由与边界

适用于以围巾/颈部穿搭配饰为目标商品销售的针织围巾、羊毛/羊绒围巾、皮草/毛绒围脖、丝巾、披肩、围领等，不限季节；按照实际商品属性识别，不把丝巾一律当保暖用品，也不把冬季围脖一律当纯装饰品。披肩属于本模块的前提是它作为围巾/披肩类配饰销售；如果销售对象实际是外套或其他服装，按商品事实路由。以围巾为目标时不并行套用 `categories/womens-fashion.md` 的专项开头和适配规则。

必须服从 `SKILL.md`、`references/editorial-policy.md`、`references/highlight-selection.md`、`references/global-rules.md` 和 `references/qianchuan-offline.md`。本模块不改变原话、序号、时长、五部分输出及日常 AI-First 主路径。例句只解释规则，不得生成虚构原话。

## 1. 开头：按产品及原话动态选

- 比较外观、毛感/光泽/质感、佩戴效果、肤感与保暖、穿搭价值、真实顾客困扰；按吸引力、可信度、语义完整性、商品归属及后续承接动态决定，没有“材质优先”“好看优先”或“痛点优先”的死顺序。
- 一般颜色搭配建议不自动升级为强开头；只有完整原话确有明确穿搭利益、且后续相关讲解可承接时才参与比较。
- 顾客困扰须是真实顾客表达或主播明确转述；不得把主播对商品的评价冒充顾客烦恼。价格/库存不作默认开头。

## 2. 中段：不同购买理由与重复强化

- 完整盘点有原话支持的不同亮点：外观/佩戴整体效果、毛感蓬松度、光泽、材质成分、厚薄/重量、柔软肤感、保暖体验、尺寸长短、垂坠感、图案花色、围法、层次感、用途变化、与服装及颜色的搭配、使用场景、护理及适用条件。
- 多种有效购买理由可以共存；按开头承接及原话中的效果、原因、穿着体验、搭配和场景关系排序，不机械按“材质→保暖→搭配”排序。不同毛感、佩戴层次感、柔软肤感、具体系法不应被笼统合并为“好看”，也不得因主题不同而删除。
- 同一卖点最多保留两处确有补充/强化价值的不同原话；相似描述无新信息的不为凑时长重复。该上限按单条方案内部去冗余理解。多方案时，毛感/质感、肤感、保暖、围法、佩戴效果、搭配、配色与场景等按 Universal Core 的“单条最优、多条互补”分配：核心理由可共享，次要有效理由优先进入最匹配方案。时长上限、取舍顺序严格继承 1.2 倍速不超过 120 秒的核心规则。

## 3. 材质、质感、肤感、保暖与依据

- AI 区分 **材质/成分事实**、**可描述的视觉质感**、**主播主观肤感**、**保暖体验/客观性能**、**绝对化承诺**。材质名称不能推出含量、品质、保暖等级、一定不扎皮肤或适合敏感人群；主观体验不推出所有人有同样体验。
- 兔毛、羊绒、羊毛、皮草、龙猫毛等称谓按原话识别并注意是否只是商品俗称；不能仅凭名称确定真实材质/动物来源/含量。缺材料证明时标明待核实，已知不实/明确命中全局禁令按通用规则处置；禁令命中时排除完整原始字幕序号，不扩大到无关序号。
- “绝不掉毛”“所有人都不扎”“任何气温都保暖”等高风险泛化说法须结合语境及证据处理，不因为原话存在就认定功效真实。

## 4. 围法、佩戴效果与画面

- 不同围法、绕圈/套头/披肩/系发等如确实不同、且主播原话给出具体佩戴利益，可分别作为购买理由或有价值的补充；不要因为都属于“佩戴”就机械去重，也不因动作不同就机械认定信息增量。
- “这样一弄”“你们看这里”等只有画面才能解码的碎句，默认不入片；有完整信息的佩戴讲解即便依赖演示，可作候选并就地标记“佩戴画面待核实”，不能从字幕凭空补出系法细节。
- 使用方式是否实际可行、画面是否对应、成片剪点是否完整，只有视频或可靠商品依据才能进一步确认；纯 SRT 不声称已验证。

## 5. 搭配、配色与使用场景

- 分开识别与大衣、毛衣、羽绒外套等服装的搭配、明确颜色关系、穿搭效果、季节/出行场景；保留有信息增量的不同理由，在核心价值与 120 秒限制下动态取舍。
- 不同服装名称并不必然意味着不同卖点；“所有衣服都百搭”不能凭空证明每一种搭配。顺带提到服装时不把该服装规格和独立卖点串入围巾文案。

## 6. 商品归属、版本与护理限制

- 同款不同颜色可以共享通用事实，但毛质/材质、尺寸长短、双面设计、独有图案、围法及穿戴效果必须分配到正确颜色/规格/款式。不同材质、不同链接或明确不同围脖不可因同类或同系列直接混作一件。
- 区分普通负面体验（如浮毛）、重要肤感/敏感人群限制、护理要求（如干洗）、安全/使用注意事项。普通信息按购买价值取舍；重要限制不得被删除后留下“所有人适合”“完全不扎”等误导性结论。条件无法可靠表达时同步排除可能误导的正面承诺。
- 不由 AI 凭材质推断一定掉毛、需要干洗、敏感皮肤一定能戴；以原话及商品资料为据，事实有疑点就地标待核实。

## 7. 多色/多条购买建议与促单分开判断

- “建议买两条”“多备几个颜色”本身是促单，不自动成为新的商品卖点。若原话确实说明一条搭大衣、一条作日常佩戴等不同使用/搭配价值，识别这些**独立理由**，再按时长和购买价值决定保留。
- 竞品价格比较、到手价、折扣、赠品、库存与稀缺等依赖实时交易条件的信息，按通用规则在成片所有位置默认排除。只有用户明确要求制作有效期明确的活动素材并确认发布时仍有效时，才对该任务例外；此边界不代表平台判定违规。不同商品的价格不能被误认为目标商品价格。
- 成交话术与结尾按通用核心动态编排：购买理由成立后优先安排最早自然、完整的机会，之后继续覆盖其他独立购买理由；不固定成交次数、类型或位置，不强制逼单收尾。混合动态信息的字幕仅在排除动态部分后仍可保留语法完整、意思自足的完整原话子句时才可取用；仅剩词组或残句时舍弃整条相关字幕，不改写、不补词或拼接；命中全局禁用表述仍排除完整原始字幕序号。
- 标题和话题延续时尚类目原有固定 `#穿搭`、`#时尚营销`，由核心补充到五个；服从全局禁词、标题不得编造信息。

## 类目判断边界（纳入同次语义编排）

质感、肤感、围法、佩戴效果、配色、搭配与场景分别按信息增量判断；避免把不同信息合并，也避免把单纯“买两条”误当独立理由。兔毛、龙猫毛等不同商品的材质与价格不得串用。重要适用/护理限制及画面依赖按原专项规则处理，不因此增加额外复查阶段。
