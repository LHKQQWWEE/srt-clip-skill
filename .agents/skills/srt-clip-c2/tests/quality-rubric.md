# C2 Universal Core 0.4.7｜Skill 0.4.29 质量验收

本标准用于开发和发布验收，不增加日常剪辑步骤。AI 仍是唯一语义判断者；工具只提供可复核的机械证据。

## 一票否决项

任一项实质失败即不通过：

- 商品识别、归属、重复语义、动态内容结构、原话边界、正式违禁词范围或 AI-First 单 AI 架构被破坏。
- 未完整读取目标商品的有效窗口、未建立完整有效信息池，就比较开头、检测多视频机会或生成成片。
- 用完整成片竞争、资格打分或多维排名取代开头候选比较；开头固定某类钩子优先，或把主播设问误写成真实顾客反馈。
- 未全量识别有效购买信息，或未先为每个方案完整编排后再计算时长。
- 默认未直接生成两个具有实质差异和独立购买核心的完整方案；把有效信息拆给不同方案、仅靠并集覆盖；或第二条不成立/降质却没有说明只生成一条的具体原因。
- 用户开头指定“单条”或“按推荐版”时，未直接输出一条推荐方案。
- 方案明显超 120 秒时未按该方案购买核心动态筛选并保持决策完整；未逐项说明被省略的有效信息。未明显超时却删点、为填时长补无关内容，或固定按某类信息价值删选。
- 原话被改写、拼接、补造，来源序号伪造，商品串用，条件/归属改变，或正式违禁词的排除范围被扩大。
- 原文存在适用且合规的促单话术，却未在对应成片中按原话完整保留；原文没有时编造、改写、补充或跨商品移用。动态交易信息仍受全局规则约束。
- 120 秒作为目标或硬上限，或未明显超时就用时长作为删点、补点或拆条理由。
- 有有效版本化执行摘要时仍强制每次完整重读所有规则；摘要缺失、版本不匹配或规则不确定时又没有回查原文。
- 对未选择主题或未实际写出的成片运行/声称完成最终终检。
- 固定五部分交付缺项；新增模型、Agent、额外语义轮次或普通文本任务环境硬依赖。
- 声称运行了未执行的测试、读取了未读材料、审阅了未查看的音画或同步了无法读回核实的渠道。

## 开发质量评分（100 分）

此评分只评估 Skill 的开发质量，不用于比较日常成片或卖点价值。

| 指标 | 权重 |
|---|---:|
| AI-First 单 AI 决策边界及冻结规则 | 15 |
| 完整读取、商品范围和有效信息池 | 18 |
| 动态顾客心理驱动的开头候选比较 | 12 |
| 默认双方案、独立购买核心与逐条覆盖 | 15 |
| 每条实际成片的原话、商品归属与条件准确 | 20 |
| 适用合规促单原话保留及无源不补造 | 8 |
| 超长动态筛选与时长判定 | 5 |
| 固定五部分输出及真实来源状态 | 7 |
| **总分** | **100** |

建议通过线：90 分，且全部一票否决项通过。评分不能抵消硬性失败。

## 关键场景验收

- 钩子与必要紧邻承接联合编排，综合判断前 2 秒吸引力及前 5 秒连续吸引力。默认 1.2 倍速的原素材累计 2.4 秒/6 秒只作参考、不硬截原话；承接按素材动态增强情绪、视觉期待、种草兴趣或购买收益，不固定类型、顺序、权重或评分。不得把比较扩展为完整成片排名。
- 默认立即形成两个真实、独立购买核心的方案。每条都必须独立覆盖全部有效卖点及必要证据/条件；主题差异不能由交换顺序或改标题代替。第二条不能成立或降低质量时，只出一条并解释原因；开头指定“单条”或“按推荐版”时直接一条。
- 每条先按购买核心完整编排完整信息池，再计算时长。常规方案完整保留全部有效点；只有明显超过 120 秒才动态筛选，保持该方案购买决策完整，必要时可以适度超过 120 秒，并逐项解释省略的有效信息。
- 对适用且合规的原文促单逐字完整保留；不为结尾、时长或转化要求编造、改写或补充。来源中的动态价格、活动、库存等内容继续按冻结的全局规则判断。
- 缓存可选且可按平台提供；摘要持久化并绑定 Skill 版本和规则校验值。缓存丢失而摘要有效时继续复用摘要。摘要不是高于原文规则的权威。
- 最终终检只检查实际选择并写出的成片。若停在用户选择等待点，没有最终成片，也没有最终终检。
- 交付保持固定五部分；所有未核实的音画、商品资料和平台结果如实标注。
